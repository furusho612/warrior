# ADR-007: レストタイマーは終了予定時刻から残り時間を計算する

- Status: Accepted

## Context

セットを完了にすると同時にレストタイマーが起動する (REQ-TMR-002)。
残り時間を表示し、時間の延長と短縮、スキップができる (REQ-TMR-003)。
別のタブやアプリから戻ったとき、経過時間を反映した正しい残り時間を表示する (REQ-TMR-006)。
画面を消灯した状態やブラウザを閉じた状態でも、レストの終了をプッシュ通知で知らせる (REQ-TMR-008)。
記録中の画面では、下にレストタイマーを固定する (design README 「画面のきまり」)。

## Decision

セットを完了した時点で、レストの **終了予定時刻** を決めて保存する。
残り時間は、表示のたびに終了予定時刻と現在時刻の差から計算する。

一定間隔の処理は画面の再描画にだけ使う。
残り時間を減算する状態として持たない。

タブの表示が戻ったとき、利用者がページを再読み込みしたとき、画面を描き直すたびに、終了予定時刻から残り時間を計算する。
終了予定時刻を過ぎていれば、タイマーは終了したものとして扱う。

延長と短縮は終了予定時刻を変更する。
スキップはタイマーを終了する。

記録中のトレーニングが持つレストタイマーは 1 つとする。
種目を切り替えても、タイマーは続く。

プッシュ通知の予約では、アプリは残り時間をサーバーに送る。
サーバーは受け取った時刻から終了予定時刻を決める。

## Consequences

ブラウザがバックグラウンドでタイマーの処理を止めても、残り時間の計算は影響を受けない。
画面に戻った時点で正しい残り時間を表示できる。

再読み込みの後も、保存した終了予定時刻からタイマーを続けられる。

端末の時計を変更すると、表示する残り時間が変わる。
終了予定時刻そのものは変えないため、時計を戻すとタイマーが長く続く。

画面の再描画の間隔は、残り時間の精度に影響しない。
一方で、終了の瞬間に音を鳴らす処理は、再描画の間隔だけ遅れる。

端末の時計とサーバーの時計がずれている場合、画面の残り時間と通知の時刻がずれる。
画面は端末の時計、通知はサーバーの時計を基準にする。
サーバーが残り時間を受け取るまでの通信の遅れは、通知の時刻に加わる。

1 つのトレーニングに 1 つのタイマーしか持たないため、複数の種目のレストを同時に計ることはできない。
スーパーセットでは、組の最後のセットの完了時にタイマーを起動する (REQ-SET-005)。
