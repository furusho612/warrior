# ADR-005: トレーニングの日付と週の境界は日本時間で決める

- Status: Accepted

## Context

表示言語は日本語とする (REQ-NFR-011)。
カレンダーは月表示で、トレーニングした日を示す (REQ-CLD-001)。
分析は部位区分ごとのセット数と総重量を週単位と月単位で表示する (REQ-ANL-005)。
週は月曜始まりとする (計算ルールと用語定義)。
AI は日、週、月の単位で評価する (REQ-AI-001)。
トレーニングは日付を指定して後から記録を追加できる (REQ-REC-006)。
記録はアカウントに紐づけてサーバーに保存し、複数の端末から同じ記録を見られる (REQ-NFR-006)。

## Decision

トレーニングは、記録した時刻とは別に、日本時間 (Asia/Tokyo) の日付を持つ。
記録中に開始したトレーニングは、開始時刻と終了時刻も持つ。
後から日付を指定して追加するトレーニングは、日付と所要時間を持ち、開始時刻を持たなくてよい。

時刻は UTC で保存する。
トレーニングの日付、週と月の境界、画面の日付は、日本時間で計算する。

週は日本時間の月曜 0 時に始まり、次の月曜 0 時の直前で終わる。
月は日本時間の 1 日 0 時に始まり、翌月の 1 日 0 時の直前で終わる。

カレンダー、部位別の分析、AI の評価期間は、トレーニングの日付を使って範囲を決める。

## Consequences

利用者が日本時間以外の場所にいても、アプリは記録の日付を日本時間で表示する。
端末のタイムゾーンを変えても、過去の記録の日付は変わらない。

サーバーとアプリが同じタイムゾーンで日付を決めるため、端末によって集計が変わらない。

日本時間は夏時間を採用していないため、夏時間の切り替えを考慮しない。

日本以外の地域を対象にする場合は、トレーニングごとのタイムゾーンを持つ移行が必要になる。

後から追加したトレーニングは開始時刻を持たないため、所要時間は記録できるが、1 日のうちのいつ行ったかは示せない。
