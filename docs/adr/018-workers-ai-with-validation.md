# ADR-018: Workers AI を AI バインディングで使い、出力を検証する

- Status: Accepted

## Context

AI は、日、週、月の評価、次回セットの提案、種目ごとの目標重量を踏まえた提案、メニューの最適化を行う。
参照する `../../../brewbook` は Workers AI の AI バインディングを使い、モデル名を環境ごとの vars に持つ。
`../../../brewbook` は外部の AI サービスにデータを送らず、無料枠の範囲で動かしている。
Workers AI は顧客のコンテンツをモデルの学習に使わない。
`../../../brewbook` は、モデルの出力をサーバー側で検証し、形式に合わない項目を落としている。
AI の入力と出力はログに出さず、プロンプトの指示と利用者のデータを別のメッセージに分けている。
AI の評価と提案は医療上の助言ではなく、痛みやけがの記述がある場合は負荷を増やす提案をしない (REQ-AI-016)。

## Decision

AI の呼び出しは Cloudflare Workers AI の AI バインディング (`Ai`) で行う。
アプリは AI の提供者に直接接続しない。
外部の AI サービスと API キーは使わない。

モデル名は環境ごとの vars の `AI_MODEL` に持つ。
初期の候補は `../../../brewbook` と同じ `@cf/meta/llama-4-scout-17b-16e-instruct` とし、PRD のプロンプトで日本語の品質と安全指示の遵守を測ったうえで、合格したモデルを vars に固定する。
テキストだけのモデルのほうが品質と消費の面で良ければ、そちらを使う。

AI のプロンプトの組み立てと出力の検証は、純粋なロジックのクレートに置く。
指示は system メッセージに置き、利用者のデータは user メッセージに分ける。
メモはタグで囲み、制御文字とタグを壊す文字を無害化する。
データの中の指示に従わないことを、指示側に明記する。

出力は Serde の型で検証し、文字列の長さ、配列の件数、列挙値の範囲を検査する。
形式に合わない項目は落とし、表示できる内容がない場合は生成を失敗させる。

痛み、けが、体調不良の記述がある場合は、モデルの出力だけに頼らず、サーバー側で負荷を増やす提案を除く。
負荷を下げるか休むことを勧め、続く場合は医師などの専門家への相談を案内する。

AI の入力と出力はログに出さない。
必要に応じて R2 に入出力のスナップショットを保存する (ADR-017)。

モデルが JSON Mode に対応する場合は JSON Schema を指定する。
対応しない場合は、出力のテキストから JSON を取り出して検証する。

AI の生成に失敗した場合、または無料枠を超えた場合は、提案なしで記録を続けられる。
失敗した生成は Queues で再試行する。

## Consequences

Workers AI の日本語の品質は、PRD のプロンプトで確認するまで確定しない。
合格するモデルがない場合、外部の AI サービスを使うかどうかを別の ADR で決める。
本 ADR は Workers AI を使う決定であり、外部の提供者へのフォールバックを含まない。

モデルの出力は保証されない。
Serde による検証と、痛みやけがに対する決定的な安全ガードを必ず通す。

AI の呼び出しには数秒かかる。
記録の操作を止めず、Queues の消費者で生成する。

ローカルの `wrangler dev` の AI バインディングは、既定でリモートの推論に接続する。
ログインのない CI では `wrangler dev --local` を使い、AI の失敗の経路だけを検証する。

無料枠の 1 日あたりの Neurons を超えると生成が失敗する。
利用者は提案なしで記録を続けられる。

プロンプトインジェクションの余地は残る。
指示とデータの分離と無害化で範囲を狭めるが、データ中の文言がモデルの出力に影響する可能性は残る。
