# ADR-021: Cloudflare Queues と Cron Triggers で AI 生成とレスト通知を実行する

- Status: Accepted

## Context

Cloudflare Workers はリクエストごとに起動し、常駐するプロセスを持たない。
`ctx.wait_until` は応答を返した後に処理を続けられるが、実行時間の上限があり、失敗したときの再試行を持たない。
AI の評価と提案はトレーニングの終了時に生成し、保存する (ADR-009)。
レストの終了は、セットの完了からレスト時間の経過後にプッシュ通知で知らせる (ADR-008)。
レストの延長、短縮、スキップ、トレーニングの終了では、予約を取り消すか時刻を変更する。
週と月の評価は、対象期間の終了後に生成する。
参照する `../../../brewbook` は Queues と Cron Triggers を使っていないが、AI の呼び出しをリクエストの中で待っている。
Cloudflare Queues は Workers Free プランでも 1 日 10,000 操作まで使え、メッセージの保持は 24 時間、遅延は 86,400 秒まで指定できる。
Cron Triggers は 1 分間隔から実行できる。

## Decision

Cloudflare Queues と Cron Triggers を使う。
Queues は、AI の生成と、レスト終了のプッシュ通知の予約に使う。
Cron Triggers は、週と月の評価の生成、期限切れのセッションとチャレンジの削除、R2 の一時ファイルの確認に使う。

Queue のメッセージには ID だけを入れ、AI の入力や記録の本文を入れない。
メッセージの大きさの上限を避け、消費側が D1 と R2 から必要な値を読む。

AI の生成は、`ai_generation` の行で状態を持つ。
状態は `pending`、`enqueued`、`generated`、`failed` とする。
トレーニングの終了時と、週と月の評価の期間の終了時には、`pending` の行を作る。
Cron は `pending` の行だけを Queue へ送り、送信時に `enqueued` と lease の期限を記録する。
消費側は、成功したら `generated`、一時的な失敗なら `pending` に戻し、恒久的な失敗なら `failed` にする。
lease の期限を過ぎた `enqueued` は、Cron が `pending` に戻す。
同じメッセージを複数回処理しても、状態は同じになる。
消費側は、保存済みの記録から入力を作り、Workers AI を呼び、出力を検証し、提案と評価を D1 に保存し、入出力のスナップショットを R2 に保存する。
消費側は、メッセージの利用者 ID または記録の行が D1 に無い場合、処理をせずにメッセージを捨てる。

レストの通知では、セットの完了時に、レストの残り時間を `delaySeconds` に指定して Queue へメッセージを送る。
予約は、予約 ID、版、終了予定時刻、有効かどうかを持つ。
消費側は、D1 の予約の行を読み、予約が有効で、版が一致し、終了予定時刻を過ぎている場合だけ Web Push を送る。
消費側は、利用者の行が D1 に無い場合も通知を送らない。
延長、短縮、スキップ、トレーニングの終了では、版を進め、古い予約を無効にして、新しい残り時間で再投入する。
古い版の Queue のメッセージが届いても、通知を送らない。
Queue のメッセージを削除する操作は使わない。

Cron Triggers は 1 分間隔で実行し、実行のたびに D1 の期限切れの行を削除し、週と月の評価の `pending` の行だけを Queue へ送る。
期限切れの行には、セッション、チャレンジ、OAuth の状態、プッシュの予約、レート制限のカウンタを含める。
Cron Triggers の実行時刻は UTC で指定し、日本時間の週と月の境界はアプリのロジックで扱う (ADR-005)。
プッシュ購読の経路のレート制限は、ADR-016 の規則に従う。

Queue は少なくとも 1 回配信する。
消費側の処理は、同じメッセージを複数回処理しても結果が変わらないようにする。
AI の提案は評価 ID で上書きし、プッシュ通知は予約 ID と版で重複を判定する。
再試行は、タイムアウト、5xx、429 の一時的な失敗に限る。
400、401、403、422、無料枠の超過は恒久的な失敗とし、再試行しない。

Queue と Cron のログには、ジョブの種別、メッセージ ID、試行回数、結果、処理時間、エラーコード、相関 ID を JSON で記録する。
記録の本文、メモ、トークン、購読の情報は記録しない。

## Consequences

Queues と Cron Triggers は、利用者が名指しした Workers、D1、R2、Workers AI に加える Cloudflare の機能である。
レスト終了の秒単位の予約と、AI の再試行を持つために必要である。

Queues の無料枠は 1 日 10,000 操作である。
レストの通知と AI の生成の回数が増えると、無料枠を超える可能性がある。
超えた場合は、ジョブが失敗し、AI の提案は出ず、プッシュ通知は届かない。
音と画面表示の代替を持つ。

レストの通知は Queue の遅延で予約する。
Cron Triggers の 1 分間隔では、レスト終了の秒単位の時刻に合わないため、Cron Triggers を通知の予約に使わない。

Queue のメッセージには記録の本文を入れない。
消費側は D1 と R2 から読むため、D1 と R2 の読み取りが増える。

Queue の消費は少なくとも 1 回であり、同じメッセージが複数回届く。
AI の保存とプッシュ通知の送信を冪等にする必要がある。

ローカルの `wrangler dev` で Queues と Cron Triggers を動かし、結合テストで消費側の処理を検証する。
CI ではリモートの AI バインディングを使わず、失敗の経路を検証する。
