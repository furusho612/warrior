# ADR-008: レスト終了のプッシュ通知はサーバーが予約する

- Status: Accepted

## Context

ブラウザ通知を許可している場合、別のタブを表示中でもレストの終了を通知する (REQ-TMR-007)。
画面を消灯した状態やブラウザを閉じた状態でも、レストの終了をプッシュ通知で知らせる。
通知は利用者が許可した場合のみ送る。
iOS ではホーム画面に追加した場合のみ届く (REQ-TMR-008)。
プッシュ通知は緊急度を最高にして送り、有効期限を短くし、遅れた通知は鳴らさずに破棄する (REQ-TMR-009)。
レストを途中で切り上げた場合や延長した場合は、予約済みの通知を取り消すか、時刻を変更する (REQ-TMR-010)。
セットの完了時に通信できず、プッシュ通知を予約できない場合は、音と画面表示だけで知らせる (REQ-TMR-011)。
プッシュ通知は iPhone と Android の実機で遅れを測る。
合格の基準は、レスト終了から 5 秒以内に届く割合が 10 回中 9 回以上とする。
満たさない場合は、プッシュ通知を補助の位置づけに変え、主な手段を画面の消灯防止と音にする (REQ-TMR-012)。

## Decision

Web Push を使い、Service Worker が通知を受け取る。
サーバーは端末ごとのプッシュ購読を保存する。

セットの完了時に、アプリはサーバーへレストの残り時間を送る。
サーバーは受け取った時刻から終了予定時刻を決め、その時刻に通知を予約する。
アプリは予約の識別子を保存する。
予約は、予約 ID、版、終了予定時刻、有効かどうかを持つ。
延長、短縮、スキップ、トレーニングの終了では、版を進め、古い予約を無効にして、新しい残り時間で予約し直す。
通知を受け取った Service Worker は、予約 ID と版を照合し、最新でない予約を表示しない。

通知の対象は、記録中のトレーニングを開始した端末の購読に限る。
同じアカウントのほかの端末には送らない。

VAPID の公開鍵と subject を環境ごとの vars に持ち、秘密鍵を Secret に置く。
アプリは認証済みの経路から公開鍵を取得する。
購読の endpoint は HTTPS で、対象ブラウザのプッシュサービスのホストだけを受け付ける。
Safari は `web.push.apple.com`、Chrome は `fcm.googleapis.com` を許可する。
それ以外の endpoint は 400 で拒否する。

通知の `Urgency` を `high` にする。
`TTL` を 30 秒にし、遅れた通知を破棄する。

試作では、サーバーが送信時刻を記録し、Service Worker が受信時刻を API に送る。
`mise run verify-staging` は 10 回の遅れを集計し、5 秒以内が 9 回以上かを判定する。

レストの延長、短縮、スキップ、トレーニングの終了では、予約を取り消すか、終了予定時刻を変更する。

予約に失敗した場合、通知の許可がない場合、または購読がない場合は、音と画面表示だけで知らせる。

試作の合格基準を満たさない場合は、プッシュ通知を主手段にしない。
画面の消灯防止と音を主手段とし、プッシュ通知は補助として残す。

通知の本文には、種目名、重量、回数などの記録の内容を含めない。

## Consequences

サーバーが予約の状態を持つため、サーバーが停止している間はプッシュ通知が届かない。
音と画面表示の代替を常に持つ。

iOS ではホーム画面への追加が必要であり、追加していない利用者には届かない。
利用者が通知の許可を取り消した場合も届かない。

プッシュサービスは配信を保証しない。
端末が圏外にあった場合や、OS が通知を抑えた場合は、レストの終了を過ぎてから通知が届くか、届かない。

`TTL` を 30 秒にすると、プッシュサービスは圏外から戻った直後の通知を破棄する。
レスト終了の通知としては、遅れて鳴るより破棄するほうがよい。

予約の取り消しに失敗すると、古い通知が届くことがある。
通知を受け取った側で予約の識別子を照合し、無効になった予約を無視する必要がある。

通知の本文に記録の内容を含めないため、通知だけではどの種目のレストが終わったかを示さない。
画面を開けば確認できる。

通知は開始した端末にだけ送るため、ほかの端末で待っていても届かない。
プッシュサービスのホストを追加するときは、ADR と許可リストを同じ変更で更新し、許可しないホストが 400 になるテストを追加する。
