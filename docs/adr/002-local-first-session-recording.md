# ADR-002: 記録は端末内へ先に保存し、サーバーへ非同期に同期する

- Status: Accepted

## Context

記録中のトレーニングは、入力のたびに端末内へ自動保存し、通信が切れても入力を続けられる (REQ-NFR-003)。
再読み込みの後や、タブを閉じて開き直した後も、記録の続きから再開できる (REQ-NFR-004)。
通信が復帰したら、端末内の記録を自動でサーバーに保存する。
未保存の記録がある間は、その状態を表示する (REQ-NFR-005)。
セットの入力と完了の操作は、通信を待たずに画面へ反映する (REQ-NFR-007)。
未接続の状態でアプリを開くことと、過去の記録を未接続で閲覧することは対象外である。

## Decision

記録の入力は、端末内の永続ストレージへ書いてから画面へ反映する。
サーバーへの送信は入力の完了条件にしない。
端末内の永続ストレージには IndexedDB を使う。
IndexedDB のデータベースに版を持ち、スキーマを変えるときは移行する。
移行に失敗した場合は、未同期の記録を保持したまま再試行できるようにする。
未同期の記録を保護するため、アプリはブラウザに永続ストレージの許可を求める。

記録中のトレーニング、トレーニングに追加した種目、セット、ドロップセットの段、スーパーセットの組は、アプリが生成した UUID v4 の ID を持つ。
マスターの種目とプログラム、ライブラリで作る独自種目の ID は、サーバーが生成した UUID v4 とする。
サーバーは ID の形式と所有権を検証して保存する。
同じ ID の保存を何度送っても、サーバーの状態は同じになるようにする。

サーバーへ送る操作は、端末内の送信待ちの列に置く。
各操作は試行回数と状態を持つ。
通信が復帰したら列の先頭から順に送り、サーバーが受理した時点で未保存の表示を消す。
恒久的なエラーで失敗した操作は `failed` として列から外し、あとの操作を止めない。
画面に失敗を表示し、利用者が再試行か破棄を選べるようにする。
同じトレーニングの操作は順序を保つ。

再読み込みの後は、端末内の記録から状態を復元する。
サーバーに保存済みの内容で、端末内の記録を上書きしない。

過去の記録を未接続で閲覧するためのキャッシュは持たない。
アプリが読み込まれた後は、未接続でも記録中のトレーニングを続けられる。

## Consequences

端末のブラウザストレージを消すと、未同期の記録は失われる。
ブラウザが永続ストレージの許可を出さない場合や、OS がストレージを削除した場合も、未同期の記録が失われうる。
未保存の状態を画面に表示し、利用者が同期の遅れに気付けるようにする必要がある。
失敗した操作を放置すると、そのトレーニングのあとの操作も失敗する。
画面で修正か破棄を促す。

同じ操作を再送しても重複しないように、ID の生成と保存の冪等性を保つ必要がある。
受理の応答が届かない場合も、同じ ID の再送で状態を揃えられる。

アプリとサーバーで記録の形を揃え、形を変えるときは保存済みの記録を移行する必要がある。
IndexedDB のスキーマの移行に失敗した場合も、未同期の記録を保持する。

通信断の間も入力と画面の反応が止まらない。
一方で、サーバーが記録を保存するまでの間は、ほかの端末から最新の記録を見られない。

終了したトレーニングの端末内の控えをいつ消すかを決める必要がある。
サーバーが受理するまで消さないことを原則とする。
