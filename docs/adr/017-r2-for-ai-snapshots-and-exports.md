# ADR-017: R2 を AI の入出力スナップショットと CSV の書き出しに使う

- Status: Accepted

## Context

アプリは R2 を使う。
進捗写真は対象外であり、写真のアップロードは持たない。
AI の評価と提案では、入力スナップショットを保存する (ADR-010)。
入力にはトレーニング記録とメモが含まれ、JSON が大きくなりうる。
CSV の書き出しは全期間の記録を 1 つのファイルにまとめる (REQ-MYP-008)。
D1 の行の大きさには上限があり、大きな JSON や CSV を D1 に置くとクエリが重くなる。
参照する `../../../brewbook` は R2 を写真の保存に使い、バケットを公開せず Worker のバインディングから操作している。

## Decision

R2 を、AI の入出力スナップショットと CSV の書き出しの保存に使う。
バケットは環境ごとに 1 つとし、Worker のバインディングからだけ操作する。
バケットは公開しない。

AI の入力と出力は `users/<利用者 ID>/` の下に、CSV の書き出しは `exports/<利用者 ID>/` の下に置く。

D1 には、スナップショットと書き出しのメタデータだけを置く。
AI の入力と出力のメタデータは ID、利用者 ID、トレーニング ID または評価 ID、モデル、プロンプトの版、R2 のキー、作成日時を持つ。
CSV の書き出しのメタデータは ID、利用者 ID、R2 のキー、作成日時を持つ。

CSV の書き出しは Worker が生成し、R2 に保存する。
利用者は認証済みの経路からダウンロードする。
この経路は認証を必須とし、Worker が R2 のオブジェクトを読んで返す。
署名付き URL と公開 URL は使わない。

AI の入出力スナップショットは、アカウントを削除するまで保持する。
CSV の書き出しは 7 日で削除する。
削除は `exports/` の接頭辞に対する R2 のライフサイクルルールで行う。
この保持期間は REQ-NFR-019 で定める。
アカウントの削除では、`users/<利用者 ID>/` と `exports/<利用者 ID>/` の接頭辞のオブジェクトをすべて削除する。

R2 への保存に失敗した場合、AI の生成を失敗させ、提案を出さない。
D1 には表示に必要なメタデータだけを保存し、大きな JSON を置かない。

R2 はフロントエンドの配信に使わない。
フロントエンドの成果物は Worker の Static Assets から配信する (ADR-016)。
署名付き URL を使わないため、S3 のクレートは追加しない。

## Consequences

アカウントの削除では、D1 の行と R2 のオブジェクトの両方を削除する。
R2 の接頭辞の削除が途中で失敗した場合に再実行できるようにする必要がある。

CSV のダウンロードは Worker を経由する。
R2 のバケットを公開しないため、URL を知るだけでは取得できない。

`exports/` の接頭辞に対する R2 のライフサイクルルールを、環境ごとに設定する。
設定を忘れると、書き出しのファイルが残り続ける。

入力スナップショットにはメモが含まれる。
バケットを公開せず、アクセスは Worker の認証済みの経路に限る。
アカウントの削除では、スナップショットも削除する。

D1 のクエリはメタデータだけを読み、大きな JSON と CSV を走査しない。
R2 に保存できない場合は AI の生成を失敗させるため、R2 の障害中は評価と提案が出ない。
記録と振り返りは続けられる。
