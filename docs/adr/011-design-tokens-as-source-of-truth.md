# ADR-011: デザイントークンを色と寸法の唯一の定義にする

- Status: Accepted

## Context

`docs/design/tokens.json` は、配色、フォント、画面の基準寸法、人体図の色、筋肉の単位を持つ。
ライトとダークの 2 つの配色がある。
部位の色分けとグラフは、どちらのモードでも判別できる配色にする (REQ-NFR-012)。
画面の基準は 390 × 844 で、押せる要素は 44px 以上、文字は 11px 以上とする (design README 「画面のきまり」)。
`mark` と `primary` の色は、`surfaceRaised` の上では文字に使わない (design README 「配色」)。
デザインの HTML は、スタイルを要素に直接書いた参照用の画面であり、アプリのコードではない。

## Decision

`docs/design/tokens.json` を、色、フォント、画面の基準寸法、人体図の色、筋肉の単位の識別子の唯一の定義とする。
アプリのコードに色のリテラル値を書かない。

筋肉の単位の識別子と日本語名の対応は `tokens.json` に持つ。
筋肉の単位の意味と部位区分は PRD の「筋肉の単位」に従う。

ビルド時に `tokens.json` から CSS カスタムプロパティと型付きの定数を生成する。
型付きの定数は Rust のモジュールとし、CSS カスタムプロパティは Tailwind のテーマに取り込む。
アプリは生成物だけを読む。
生成物はビルドのたびに作り、リポジトリに含めない。

ライトとダークの切り替えは、ルート要素のテーマ属性で行う。
初期値は端末の設定に合わせ、利用者が選んだテーマを保存する (REQ-MYP-005, REQ-NFR-012)。

部位の色は 8 つの部位区分のキーで引く。
人体図の色は人体図専用のキーで引く。
部位の色と人体図の色を同じものとして扱わない。

押せる要素の最小 44px と、文字の最小 11px を定数にし、画面の実装で検査する。

`docs/design/` は参照用とする。
アプリが読み込むアイコン、人体図、トークンは、コード側の配置へ移す (design README 「未決事項」)。

## Consequences

トークンを変えるときは生成物を作り直す必要がある。
コードに直接色を書けないため、一時的な色の追加ができない。

ライトとダークの両方でコントラストを検査する必要がある。
`mark` と `primary` を `surfaceRaised` 上の文字に使わないという制約も、検査の対象にする。

デザインの HTML とアプリの実装がずれた場合、`tokens.json` を基準に直す。
HTML の値をそのままアプリへ写さない。

フォントの読み込みに失敗した場合の代替フォントを定義する必要がある。

ビルドにトークンの生成を組み込む必要がある。
生成に失敗した場合、アプリのビルドも失敗させる。
