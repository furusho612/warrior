# TLA+ で認証とレスト通知の不変条件を検査する

- Requirements: REQ-NFR-006, REQ-NFR-013, REQ-NFR-014, REQ-TMR-008, REQ-TMR-009, REQ-TMR-010, REQ-TMR-011
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-formal-auth-notifications

## 目的

認証のチャレンジ、OAuth の状態、セッション、パスキーの管理と、レスト通知の予約、取り消し、再予約、古いメッセージの扱いを TLA+ で書き、TLC で不変条件を検査する。
ADR-024 の形式手法のうち、認証とレスト通知の 2 つのモデルを担う。

## 優先度根拠

認証の状態遷移の誤りは、セッションの再利用やパスキーの喪失として現れる。
レスト通知の誤りは、取り消した通知の配信や同じ予約の重複として現れる。
どちらも入力の組合せのテストでは網羅しにくい。

## 現状

`formal/` に 0009 で編集権と同期のモデルを置くが、認証とレスト通知のモデルがない。
認証と通知の状態遷移は、ADR-013、ADR-019、ADR-008、ADR-021 の文章にだけ存在する。

## 設計方針

`formal/Auth.tla` と `formal/RestNotification.tla` を置く。
定数は利用者 2 人、セッション 2 つ、パスキー 2 つ、予約 2 つ、メッセージ 2 つなど小さくし、TLC が短時間で終わるようにする。

`Auth.tla` は、パスキーのチャレンジ、Google OAuth の状態、セッション、パスキーの追加と削除をモデル化する。
不変条件は次のとおりである。

- チャレンジと OAuth の状態が、それぞれ最大 1 回しか結果を生まない。
- 期限切れのチャレンジと状態を拒否する。
- ログアウトの後のセッションを拒否する。
- パスキーを削除しても、Google アカウントのログインを失わない。

`RestNotification.tla` は、レストの予約、Queue の遅延、取り消し、再予約、古いメッセージ、通知の送信をモデル化する。
不変条件は次のとおりである。

- 1 つの予約につき通知が最大 1 回である。
- 取り消した予約は通知しない。
- 再予約は最新の終了予定時刻を使う。
- 古いメッセージを無視する。
- トレーニングの終了後に通知しない。
- 終了予定時刻から 30 秒を過ぎたメッセージは送らない。

`formal/README.md` に、各不変条件と要求 ID の対応を追記する。
TLC を 0009 と同じ仕組みで CI で実行する。
ガードを 1 つ外した仕様で違反を検出し、結果を issue に記録する。

## 完了条件

- [ ] `formal/Auth.tla` の TLC の検査が、上の 4 つの不変条件を満たして終了する。これは REQ-NFR-006、REQ-NFR-013、REQ-NFR-014 の受入基準「Google アカウントで登録してログインできる」「1 つのアカウントに複数のパスキーを登録でき、追加と削除ができる」「登録したパスキーを使えない状態でも、Google アカウントでログインして新しいパスキーを登録できる」を状態遷移の側から支える。
- [ ] `formal/RestNotification.tla` の TLC の検査が、上の 6 つの不変条件を満たして終了する。これは REQ-TMR-008、REQ-TMR-009、REQ-TMR-010、REQ-TMR-011 の受入基準「通知はそのトレーニングを開始した端末にだけ届き、同じアカウントのほかの端末には届かない」「有効期限は終了予定時刻から 30 秒を上限とし、それを過ぎてから端末に届いた通知は、音も表示も出さずに捨てる」「レストを途中で切り上げたときと、トレーニングを終了したときは、予約済みのプッシュ通知が届かない」「通信できない状態でセットを完了すると、プッシュ通知は予約されず、レストの終了を音と画面表示だけで知らせる」を状態遷移の側から支える。
- [ ] ガードを 1 つ外した仕様で TLC が違反を検出し、その結果を issue に記録する。
- [ ] `formal/README.md` に、認証と通知の不変条件と要求 ID の対応を追記する。
- [ ] `mise run formal` が 4 つのモデルを全て実行し、`mise run check` から呼ばれる。
- [ ] CI が TLC を実行する。
- [ ] 仕様は ADR-008、ADR-013、ADR-019、ADR-021 の判断を抽象化したものである。実装の issue は、この仕様と実装の対応を保つ。

## 解決方法

`formal/Auth.tla`、`formal/RestNotification.tla` を追加し、`formal/README.md` を更新する。
`mise.toml` の `formal` タスクに 4 つのモデルの実行を追加する。
`.github/workflows/ci.yml` の TLC のジョブが 4 つのモデルを実行するようにする。
