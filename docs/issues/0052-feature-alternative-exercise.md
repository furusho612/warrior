# 代わりの種目の候補と入れ替えを実装する

- Requirements: REQ-ALT-001, REQ-ALT-002, REQ-ALT-003, REQ-ALT-004, REQ-ALT-005
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-alternative-exercise

## 目的

記録中の種目について、器具が使われていて行えない場合に、代わりの種目の候補を表示する。
候補は、主働筋が重なる種目を、主働筋の重なりが多い順、使う器具が違う順、過去に記録のある順に並べる。
候補を選ぶと、その回のトレーニングに限って種目を入れ替える。
入れ替えのほかに、その種目を後に回すこともできる。

## 優先度根拠

代わりの種目は段階 3 の機能であり、種目ライブラリと記録の後に作る。
候補の並びを AI に任せると、通信できない状態で候補が出ず、順序も毎回変わる。

## 現状

0019 で種目の主働筋と使用器具、0024 で種目の追加と前回の記録、0039 で種目ライブラリ、0044 でルーティンを実装する。
しかし、候補の選択と並び順、入れ替え、後に回す操作がない。

## 設計方針

候補は、種目ライブラリの中から、主働筋が重なる種目を選ぶ。
主働筋の重なりは、元の種目の主働筋と候補の主働筋の共通する単位の数とする。
並び順は、主働筋の重なりが多い順、使う器具が違う順、過去に記録のある順とする。
同じ順位の候補は、種目ライブラリの表示順 (部位区分、使用器具、種目名の五十音順) で並べる。
元の種目と同じ種目は候補に含めない。

候補は AI を呼ばずにアプリが選ぶ。
候補の API は種目ライブラリと過去に記録した種目の ID だけを読み、AI の Queue にメッセージを送らない。
通信できない状態でも、すぐに候補を表示するため、アプリはログインの後に種目ライブラリと、過去に記録した種目の ID を端末内に保存する。
保存するのは候補の並びに必要な情報だけとし、過去の記録の本文は保存しない。

候補を選ぶと、その回のトレーニングに限って種目を入れ替える。
セット数と回数の目安は元の種目から引き継ぎ、重量は選んだ種目の前回の記録を表示する。
元の種目のセットが既に完了している場合は、入れ替えを行わず、後に回す操作を案内する。
入れ替えた種目のスナップショットを保存する。
元のルーティンは変更しない。
元の種目がルーティンに由来する場合も、ルーティンの内容を変えない。

入れ替えのほかに、その種目を後に回す操作を用意する。
後に回すと、種目は入れ替わらずに記録の一覧の後ろへ移る。
後に回した種目のセットと前回の記録は保つ。

候補の表示と入れ替えと後に回す操作は、端末内の保存と送信待ちの列を通る。

## 完了条件

- [ ] 記録中の種目について、器具が使われていて行えない場合に、代わりの種目の候補を表示できる。これは REQ-ALT-001 の受入基準に対応する。
- [ ] 候補が、種目ライブラリの種目のうち、主働筋が重なる種目だけを含む。並び順が、主働筋の重なりが多い順、使う器具が違う順、過去に記録のある順となる。同じ順位の候補は種目ライブラリの表示順で並ぶ。これは REQ-ALT-002 の受入基準に対応する。
- [ ] 候補が AI を呼ばずにアプリで選ばれ、AI の応答を待たずに表示される。通信できない状態でも、候補が同じように表示される。これは REQ-ALT-003 の受入基準に対応する。
- [ ] 候補を選ぶと、その回のトレーニングの種目だけが入れ替わる。セット数と回数の目安は元の種目の値を引き継ぎ、重量には選んだ種目の前回の記録を表示する。元のルーティンの内容は変わらない。これは REQ-ALT-004 の受入基準に対応する。
- [ ] 種目を後に回す操作を行うと、その種目は入れ替わらずに記録の一覧の後ろへ移る。これは REQ-ALT-005 の受入基準に対応する。
- [ ] 元の種目のセットが既に完了している場合、入れ替えを行わず、後に回す操作を案内する。
- [ ] 候補の表示、入れ替え、後に回す操作が、端末内の保存と送信待ちの列を通る。
- [ ] 候補の表示の後に、AI の Queue にメッセージが増えない。
- [ ] アプリが、ログインの後に種目ライブラリと過去に記録した種目の ID を端末内に保存する。過去の記録の本文は保存しない。
- [ ] PBT で、候補の並びが、主働筋の重なり、器具の違い、過去の記録の有無、種目ライブラリの表示順の比較と一致することを確かめる。
- [ ] PBT で、候補に元の種目と同じ種目が含まれず、主働筋が重ならない種目が含まれないことを確かめる。
- [ ] 例示テストで、主働筋が完全に重なる候補、一部だけ重なる候補、同じ器具の候補、過去に記録のある候補、同じ順位の候補を確かめる。
- [ ] E2E で、候補を表示し、入れ替え、後に回す操作を確かめ、元のルーティンが変わらないことを確かめる。
- [ ] E2E で、通信を切った状態でも候補が表示されることを確かめる。

## 解決方法

`backend/warrior_core/src/alternative.rs` に、候補の選択と並び順を置く。
`backend/warrior/src/alternative.rs` に、候補の取得、入れ替え、後に回す操作を置く。
`backend/warrior/src/router.rs` に `GET /api/sessions/:id/exercises/:exercise_id/alternatives`、`POST /api/sessions/:id/exercises/:exercise_id/replace`、`POST /api/sessions/:id/exercises/:exercise_id/defer` を追加する。
`frontend/src/screens/record.rs` に候補の表示、入れ替え、後に回す操作を置く。
`frontend/src/storage/library.rs` に種目ライブラリと過去に記録した種目の ID の保存を置く。
`backend/warrior/tests/e2e_alternative.rs` に E2E を追加する。
`backend/pbt/tests/alternative.rs` に性質テストを置く。
