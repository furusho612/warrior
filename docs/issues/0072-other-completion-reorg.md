## 設計方針

完了条件を、その issue が実装する範囲のテストで確かめられる条件に限る。
横断する確認は、その振る舞いを実装する後続 issue の完了条件へ移す。
外部環境や実モデルに依存する確認は、リリース判定の issue に分離する。

### 0017 の削除の冪等性と所有関係

削除の冪等性は、サーバーの削除処理を同じ利用者 ID に対して 2 回実行したときの最終状態で定義する。
公開 API の 2 回目の呼び出しは、セッションが削除済みのため 401 を返す。これは冪等性の条件と分ける。
削除の対象には `users` の行を含める。
`migrations/` のすべての表を「利用者に属する」「マスター」「一時」の 3 つに分類し、利用者に属する表が削除の対象に含まれることをテストする。
`set_segments` や `superset_members` のように親から所有される表も、利用者に属する表として扱う。

### 0055 の再試行と状態の取得

一時的な失敗の再試行は最大 3 回とし、間隔を 1 秒、5 秒、30 秒とする。
3 回を超えた場合は `failed` にする。
生成の状態を取得する `GET /api/ai/jobs/:id` を追加する。
画面はこの経路で状態を取得し、`generated` または `failed` になるまで条件を待つ。
