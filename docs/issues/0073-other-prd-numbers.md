# PRD の数値と実装詳細を整理する

- Requirements: なし (文書の整理であり、要求の意味を変えない)
- Priority: Low
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-prd-numbers

## 目的

PRD の数値を、操作上の制約とドメインの定義に分けて置き場を固定する。
実装サービス名や実装手段を PRD から除き、要求の意味だけを残す。

## 優先度根拠

要求の意味は変えないが、数値と実装詳細が各章に散ると、運用値の変更で複数箇所を直すことになる。
リリース前の文書整理として行う。

## 現状

- レート制御の初期値は非機能要件の表にある。
- 通知の有効期限 30 秒は `REQ-TMR-009` の要求と受入基準にある。
- 現在の記録の直近 7 日間は `REQ-GOAL-002` と計算ルールにある。
- AI の 2 〜 10% は `REQ-AI-009`、プログラムの付録、AI のプロンプトにある。
- 回復の 48 〜 72 時間、種目の 100 〜 110 種、24 の筋肉の単位、メモの 2000 文字、時間の 86400 秒は各章にある。
- PRD の非機能要件には、保存先を「サーバー」と書く箇所がある。

## 設計方針

操作上の数値は非機能要件に置く。
計算式、期間の定義、データの範囲は「計算ルールと用語定義」に置く。
ほかの章は、数値を再掲せず見出しの語で参照する。
実装サービス名と実装手段は PRD から除き、ADR と issue に置く。
要求 ID と要求の意味は変えない。

### 置き場の分類

- 非機能要件: 通知の有効期限、レート制御の上限と窓、保持期間、タイムアウト、同時接続などの運用値。
- 計算ルールと用語定義: 推定 1RM、PFC、現在の記録の 7 日間、前回、総重量、セット数の定義。
- 機能章: プログラムの進行の目安 2 〜 10%、回復の 48 〜 72 時間、種目の 100 〜 110 種、24 の筋肉の単位、メモの 2000 文字、時間の 86400 秒のうち、製品の内容として固定する値。必要なら計算ルールへ移す。
- ADR と issue: 保存先のサービス名、テーブル名、API の形、プロンプトの実装。
