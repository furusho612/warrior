# 種目マスターと筋肉の単位のスキーマを実装する

- Requirements: REQ-LIB-002, REQ-LIB-004, REQ-LIB-010, REQ-LIB-011, REQ-LIB-012
- Priority: High
- Created: 2026-11-12
- Completed: 2026-11-13
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-exercise-master-schema

## 目的

種目の名称、部位区分、主働筋と補助筋、使用器具、やり方、注意点、コツ、記録方式、左右別の可否、グリップの選択肢を保存するスキーマと型を作る。
筋肉の単位を 24 個の識別子で持ち、種目と人体図が同じ単位を使えるようにする。

## 優先度根拠

種目を選べないとトレーニングを記録できない。
種目マスターの形を先に固定しないと、記録、分析、AI、人体図がそれぞれ別の種目の表現を持つ。

## 現状

PRD の「種目ライブラリ」と「筋肉の単位」が項目を定めているが、テーブルと型がない。
種目のスナップショットを記録に持たせる仕組みもない。

## 設計方針

マスターの種目と利用者の独自種目を別の表に置く。
マスターの種目は `user_id` を持たず、独自種目は `user_id` を持つ。
独自種目も `name_kana` を持ち、五十音順の並べ替えに使う。
マスターの種目の編集と削除は、利用者ごとの上書きの表に保存する。

マスターの種目の表は、次の列を持つ。

- `id`: サーバーが生成した UUID v4。
- `name`: 種目名。
- `name_kana`: 五十音順の並べ替えに使う読み。
- `body_part`: 胸、背中、肩、二頭・前腕、三頭、脚、腹筋、その他の 8 つ。
- `equipment`: バーベル、ダンベル、マシン、ケーブル、自重、その他。
- `record_mode`: 重量と回数、自重と回数、時間の 3 つ。
- `laterality`: 左右別に行うかどうか。
- `grip_mode`: なし、握り方と手幅、アタッチメントの 3 つ。
- `other_scope`: 部位区分がその他のときに、全身、下半身のいずれか。
- `instructions`: やり方。
- `cautions`: 注意点。
- `tips`: コツ。
- `sort_order`: 一覧の既定の順序。

主働筋と補助筋は、種目と筋肉の単位の組の表に持つ。
役割は `primary` と `secondary` の 2 つとする。
筋肉の単位の表は、`id`、`body_part`、`name_ja`、`display_order` を持つ。
単位は PRD の「筋肉の単位」の 24 個とする。
部位区分がその他の種目は筋肉の単位を持たず、`other_scope` で全身か下半身を示す。

グリップの選択肢は、種目ごとに次の型で持つ。

- `none`: グリップを選ばない。
- `grip`: 握り方 (順手、逆手、パラレル) と手幅 (ワイド、ミディアム、ナロー) を選ぶ。
- `attachment`: ワイドバー、ストレートバー、パラレルグリップ、マググリップ 7 種の合計 10 種から選ぶ。ワイドバーとストレートバーでは、順手か逆手かも選ぶ。

種目の行には、記録時点の種目の内容を保存するための `ExerciseSnapshot` 型を用意する。
スナップショットは、種目 ID、名称、部位区分、主働筋と補助筋、記録方式、左右別の可否、グリップの選択肢を持つ。
セットの記録にスナップショットを保存するのは 0024 以降で行う。

種目の型は、名称が空でないこと、部位区分と筋肉の単位が対応すること、その他の種目が筋肉の単位を持たないことを検証する。
時間で記録する種目は、グリップの選択肢を持たない。左右別は持てる。

## 完了条件

- [ ] その他を除く各種目に、名称、部位区分、主働筋、補助筋、使用器具、やり方、注意点、コツを保存できる。主働筋と補助筋を別の項目として持つ。これは REQ-LIB-002 の受入基準に対応する。
- [ ] 各種目に、重量と回数、自重と回数、時間の 3 つの記録方式のいずれかと、左右別に行うかどうかの値を持つ。これは REQ-LIB-004 の受入基準に対応する。
- [ ] 同じ器具と同じ動作で角度や軌道が違う種目を、別の行として登録できる。それぞれの種目が、角度や軌道に対応する主働筋を持つ。これは REQ-LIB-010 の受入基準に対応する。
- [ ] プル系の種目に、グリップを選べるかどうかの値を持つ。アタッチメントの 10 種と、握り方と手幅の 3 種ずつを表せる。ワイドバーとストレートバーでは順手か逆手かを選べる。これは REQ-LIB-011 の受入基準に対応する。
- [ ] その他を除く種目の主働筋、補助筋、人体図の色分け、グリップごとの部位データが、24 個の筋肉の単位で表せる。これは REQ-LIB-012 の受入基準に対応する。
- [ ] 部位区分がその他の種目が筋肉の単位を持たず、全身か下半身かを表せる。有酸素運動の表示に使う。
- [ ] `ExerciseSnapshot` が種目の表示と比較に必要な項目を持ち、Serde で往復する。
- [ ] 名称が空の種目、部位区分と筋肉の単位が合わない種目、グリップを持つ時間で記録する種目を拒否する。
- [ ] マスターの種目と独自種目が別の表にあり、マスターの種目が `user_id` を持たない。
- [ ] マスターの種目の編集と削除を、利用者ごとの上書きの表に保存できる。
- [ ] PBT で、`ExerciseSnapshot` の Serde の往復、筋肉の単位の部位区分の整合、グリップの選択肢の整合を確かめる。
- [ ] 例示テストで、24 個の筋肉の単位、その他の種目の全身と下半身、時間で記録する種目の制約を確かめる。
- [ ] 種目マスターの初期データは 0042 で投入する。この issue ではデータを入れない。

## 解決方法

`migrations/` に `muscles`、`master_exercises`、`master_exercise_muscles`、`user_exercises`、`user_exercise_muscles`、`master_exercise_overrides` の表を追加する。
`backend/warrior_core/src/exercise.rs` に `BodyPart`、`Equipment`、`RecordMode`、`Laterality`、`GripMode`、`GripSelection`、`Exercise`、`ExerciseSnapshot` を置く。
`backend/warrior/src/exercise.rs` に D1 の読み書きを置く。
`backend/pbt/tests/exercise.rs` に性質テストを置く。
`backend/warrior_core/src/exercise.rs` の `#[cfg(test)]` に例示テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に利用者に属する表を追加する。

## 結果

`muscles`、`master_exercises`、`master_exercise_muscles`、`user_exercises`、`user_exercise_muscles`、`master_exercise_overrides` を追加した。
24 個の筋肉の単位、8 つの部位区分、使用器具、記録方式、左右別、グリップの 10 種のアタッチメントと握り方・手幅、その他の全身・下半身を型にした。
名称、かな、部位と筋肉の対応、その他の筋肉なし、時間種目のグリップなし、アタッチメントの順手・逆手を検証する。
`ExerciseSnapshot` の Serde 往復、検証の例示テスト、筋肉とグリップの PBT を追加した。
D1 のマスター・独自種目の読み書き、マスター種目の利用者ごとの上書き、アカウント削除の対象表の分類を追加した。
種目マスターの初期データは 0042 で投入する。
