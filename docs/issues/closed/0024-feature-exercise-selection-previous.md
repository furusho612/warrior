# 種目の追加と前回の記録の表示、総重量の差を実装する

- Requirements: REQ-REC-002, REQ-REC-003, REQ-REC-004
- Priority: High
- Created: 2026-11-12
- Completed: 2026-11-14
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-exercise-selection-previous

## 目的

記録中のトレーニングに種目を追加し、並べ替えと削除ができるようにする。
種目を追加したときに前回の記録を表示し、1 回の操作で入力欄へコピーできるようにする。
種目ごととトレーニング全体で、前回との総重量の差を表示する。

## 優先度根拠

種目を選び、前回の値を確認して入力する流れが、記録の中心の操作である。
前回の選び方を先に固定しないと、種目ごとと全体の差が画面によって変わる。

## 現状

0021 で記録の表と端末内の保存、0022 でトレーニングの開始と終了、0023 で編集権を実装する。
0019 で種目マスターの型と表を用意する。
しかし、記録への種目の追加、並べ替え、削除、前回の記録の表示、コピー、総重量の差がない。

## 設計方針

種目の追加は、種目ライブラリの選択から行う。
選んだ種目の `ExerciseSnapshot` をトレーニングの種目に保存する。
種目は順序を持ち、並べ替えで順序が変わり、削除で一覧から消える。
削除した種目に属するセットも削除する。
スーパーセットの組に属する種目を削除した場合は、組の参照も更新する。組の実装は 0027 が担う。

前回の記録は、次の規則で選ぶ。

- 種目ごとの前回は、同じ種目を記録した直近の終了済みのトレーニングとする。
- グリップとアタッチメントを選べる種目は、同じグリップと同じアタッチメントを選んだ直近のトレーニングとする。
- トレーニング全体の前回は、同じルーティンから開始した直近の終了済みのトレーニングとする。
- 用意したプログラムから開始したトレーニングの前回は、同じプログラムの同じ日から開始した直近の終了済みのトレーニングとする。
- 独自のプログラムから開始したトレーニングの前回は、同じ独自のプログラムの同じ日から開始した直近の終了済みのトレーニングとする。
- プログラムの規則とルーティンの規則が重なる場合は、プログラムの規則を優先する。
- 空の状態から開始したトレーニングの前回は、同じく空の状態から開始した直近の終了済みのトレーニングとする。

空の状態から開始したトレーニングを同じ群として扱うのは、PRD の「前回」の定義を、ルーティンを持たないトレーニングに適用したものである。

種目ごとの前回の表示は、セットごとの重量、回数、時間、セット種別、ドロップセットの段の値とする。
前回の記録がない種目では、前回の表示を出さない。

前回のコピーの操作を 1 回行うと、前回のセットの値を今回の入力欄に入れる。
コピーする値は、セット種別、重量、回数、時間、左右の値、ドロップセットの段、グリップとアタッチメントとする。
コピーの後に利用者が自由に書き換えられる。

種目ごとの総重量の差は、今回の種目の総重量から前回の同じ種目の総重量を引いた値とする。
時間で記録する種目では、総重量の差の代わりに、合計時間と最長時間の差を表示する。
トレーニング全体の総重量の差は、時間で記録する種目を除いた今回の総重量から、前回の同じルーティンの総重量を引いた値とする。
総重量は 0012 の計算を使う。
前回がない場合は差を表示しない。

差は、増えた場合は正の値、減った場合は負の値として表示する。
0 の場合は 0 と表示する。

## 完了条件

- [ ] 種目ライブラリから選んだ種目が記録の種目の一覧に追加される。追加した種目は並べ替えで順序が変わり、削除すると一覧から消える。これは REQ-REC-002 の受入基準に対応する。
- [ ] 前回の記録がある種目を追加すると、前回のセットごとの重量と回数が表示される。コピーの操作を 1 回行うと、表示された値が今回の入力欄に入る。これは REQ-REC-003 の受入基準に対応する。
- [ ] 前回の記録の選択が、種目、グリップとアタッチメント、ルーティン、プログラムの規則に従う。プログラムの規則とルーティンの規則が重なる場合は、プログラムの規則を優先する。プログラムの候補が無い場合は、独自のプログラム、ルーティン、空の状態の順に候補を探す。
- [ ] 種目ごとに、今回の総重量と前回の総重量の差が表示される。時間で記録する種目では、合計時間と最長時間の差が表示される。トレーニング全体でも、時間で記録する種目を除いた今回と前回の総重量の差が表示される。種目が 0 件でも全体の差を出す。これは REQ-REC-004 の受入基準に対応する。
- [ ] 空の状態から開始したトレーニングでも、同じく空の状態から開始した直近のトレーニングとの差が表示される。PRD の「前回」の定義を、ルーティンを持たないトレーニングに適用するため。
- [ ] 前回の記録がない種目とトレーニングでは、差を表示しない。差の計算は前回の値がある場合だけ行うため。
- [ ] 種目を削除すると、その種目のセットも削除される。セットと段は種目に属し、孤児の行を残さないため。
- [ ] 種目の並べ替えと削除が、端末内の保存と送信待ちの列を通る。サーバーの保存を入力の完了条件にせず、同じ操作の再送で状態を変えないため。
- [ ] 結合テストで、前回の選択が直近の終了済みのトレーニングであり、グリップとアタッチメントの一致を守ることを確かめる。終了済みかどうかは D1 の `finished_at` で決まり、純粋関数の候補には現れないため。
- [ ] 結合テストで、用意したプログラムと独自のプログラムの規則がルーティンの規則より優先され、プログラムの候補が無い場合はルーティンへ落ちることを確かめる。開始元の ID の優先順は D1 の候補の選択で決まるため。
- [ ] PBT で、総重量の差が今回の値から前回の値を引いた値と一致し、前回がない場合は差を返さないことを確かめる。
- [ ] 結合テストで、種目の追加、並べ替え、削除、前回の取得を確かめる。
- [ ] E2E で、種目を追加し、前回の値をコピーし、種目ごとと全体の差が表示されることを確かめる。
- [ ] E2E で、2 種目を並べ替え、1 種目を削除し、一覧の順序、件数、送信待ちの操作種別を確かめる。画面の保存と送信待ちの列が一致するため。

## 解決方法

`backend/warrior_core/src/previous.rs` に、前回の選択と総重量の差の計算を置く。
`backend/warrior/src/training_session_exercise.rs` に、種目の追加、並べ替え、削除と前回の取得を置く。
`backend/warrior/src/library.rs` に、記録の選択が使う `GET /api/exercises` の最小の一覧を置く。一覧はマスターを全件返し、絞り込みとページングは 0039 が拡張する。
`frontend/src/screens/record/exercises.rs` に、選択中の種目の詳細、前回の記録の表示、コピー、差の表示を置く。
`frontend/src/record_rail.rs` と `frontend/src/layout.rs` に、60px の種目レールの状態と一覧を置く。
`frontend/src/screens/record.rs` に種目の追加の操作と、レールの選択を受けた詳細の配置を置く。
`frontend/src/screens/library.rs` に種目の選択の画面を置く。
`backend/warrior/tests/e2e_record_exercise.rs` に E2E を追加する。
`backend/warrior/tests/wrangler_record_exercise.rs` に結合テストを置く。
`backend/pbt/tests/previous.rs` に性質テストを置く。

## 結果

種目の追加、並べ替え、削除を、端末内の保存と送信待ちの列に載せた。サーバーは種目の各データ文にも編集権の条件を付け、削除するセット、段、スーパーセットの参照をトレーニングと利用者で絞る。
前回の取得を `GET /api/trainings/:id/previous` に置いた。応答は `{ "exercise": { "sets": ..., "total_weight_kg": ..., "total_duration_seconds": ..., "max_duration_seconds": ... } | null, "training": { "total_weight_kg": ... } | null }` とし、`exercise_id` を省略するとトレーニング全体の前回だけを返す。種目ごとのセットは `kind`、`rpe`、グリップの選択、段を持つ。
前回の選択は、プログラム、独自のプログラム、ルーティン、空の状態の順に候補を探し、プログラムの候補が無ければ次の規則へ落ちる。種目ごとは同じ種目と同じグリップと同じアタッチメントの完了セットを持つ直近の終了済みを選ぶ。
差は、種目ごとの総重量、時間で記録する種目の合計時間と最長時間、トレーニング全体の総重量について、今回から前回を引いた値とした。種目が 0 件でも全体の差を出す。
コピーは重量、回数、時間までとし、左右、ドロップセットの段、グリップとアタッチメントのコピーは、それぞれ 0027、0026、0031 が担う。セット入力の永続化は 0025 が担う。
種目の一覧は 60px のレールに置き、選択中の種目の詳細と操作を本文に置いた。
`GET /api/exercises` は記録の選択のための最小の一覧であり、0039 が絞り込みとページングを足す。独自種目の反映は 0040 が担う。
