### 端末内削除の所有

端末内の削除は、所有者を 1 つに分ける。
0017 はサーバー側の削除と、削除の応答を成功 (204) として返すところまでを持つ。
0017 の完了条件から 0063 と 0021 の振る舞いを外し、0017 は削除の応答が 204 を返すところで終える。
0063 は UI、セッション Cookie、端末トークンの Cookie、設定、キャッシュを持ち、応答の成功の後に 0021 の `clear_account` を呼ぶ。
0021 は IndexedDB と送信待ちの列を持ち、`clear_account` を提供する。
0017 と 0021 が先にあり、0063 が 0017 の API と 0021 の `clear_account` を呼ぶ。
0063 → 0017 と 0063 → 0021 の一方向とし、0017 と 0021 は 0063 の完了を待たない。

削除の冪等性は、サーバーの削除処理を同じ利用者 ID に対して 2 回実行したときの最終状態で定義する。
公開 API の 2 回目の呼び出しは、セッションが削除済みのため 401 を返す。これは冪等性の条件と分ける。
削除の対象には `users` の行を含める。
`migrations/` のすべての表を「利用者に属する」「マスター」「一時」の 3 つに分類し、利用者に属する表と削除の対象の一覧が双方向に一致することをテストする。
`set_segments` や `superset_members` のように親から所有される表も、利用者に属する表として扱う。
