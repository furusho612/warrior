# ホームに次のメニューと今週の実施状況を表示する

- Requirements: REQ-PRG-005, REQ-PRG-025, REQ-NFR-002, REQ-NFR-005
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-home
- Completed: 2026-11-17

## 目的

ホームに、進行中のプログラムの次に行う日のメニューを表示する。
トレーニングの開始の入口をホームに置く。
今週の実施状況と、部位区分ごとの回復状況の輪を表示する。

## 優先度根拠

ホームはアプリを開いたときの入口であり、次のメニューと開始の操作を置く。
進行中のプログラムの次の日を表示しないと、0045 の進行の位置が利用者に見えない。

## 現状

0007 でホームの空の画面、0044 でルーティン、0045 でプログラムの進行を実装する。0074 が独自のプログラムの作成と進行を実装する。
しかし、次のメニュー、開始の入口、今週の実施状況、回復状況の輪がない。

## 設計方針

ホームは、次のメニュー、開始、今週の実施状況、部位区分ごとの回復状況の輪を表示する。
デザインの「ホーム」の画面に従い、部位区分ごとの回復状況を輪で示し、中央に開始を置く。

次のメニューは、進行中のプログラムがある場合に、次に行う日のルーティンの種目とセット数の目安を表示する。独自のプログラムのメニューは 0074 が足す。
進行中のプログラムがない場合は、ルーティンの一覧と空の状態からの開始の入口を表示する。

開始の操作は、次のメニューのプログラムの日から開始する。
進行中のプログラムがない場合は、空の状態から開始する。
開始の経路は 0022 の開始の API と画面を使う。

今週の実施状況は、日本時間の週の始まりから今日までのトレーニングの日数と、部位区分ごとのセット数を表示する。
週の境界は 0011 の `JstWeek` を使う。
部位区分ごとのセット数は 0012 の計算を使い、ウォームアップを除き、ドロップセットを 1 と数える。

回復状況の輪は、0051 の回復状況の値を使う。
0051 が実装されるまでは、輪の場所だけを用意し、値がない場合は灰色で表示する。

ホームの表示は、画面を開くたびに最新の値を取得する。
未保存の記録がある場合は、その状態を表示する。
通信できない場合は、画面を開いたままなら最後に取得した値を表示し、更新できないことを示す。未接続での再読み込みは対象外であるため、再読み込みの後の表示は定めない。

## 完了条件

- [ ] 進行中のプログラムがあるとき、ホームに次に行う日のメニューが表示される。これは REQ-PRG-005 の受入基準に対応する。
- [ ] 次のメニューの開始の操作で、プログラムの日のトレーニングが開始される。開始の経路は 0022 と 0045 が担うため、この issue ではホームからの統合を確かめる内部条件である。
- [ ] 進行中のプログラムがないとき、ルーティンの一覧と空の状態からの開始の入口が表示される。空の状態からの入口は 0022 が担うため、この issue ではホームからの統合を確かめる内部条件である。
- [ ] 今週の実施状況が、日本時間の週の始まりから今日までのトレーニングの日数と、部位区分ごとのセット数を表示する。これは REQ-PRG-025 の受入基準に対応する。
- [ ] 部位区分ごとのセット数が、ウォームアップを除き、ドロップセットを 1 と数える 0012 の計算と一致する。これは 0012 の計算に基づく内部条件である。
- [ ] 回復状況の輪の場所が表示され、値がない場合は灰色で表示される。値の表示は 0051 が確かめる。これは表示の場所の内部条件であり、受入基準に対応しない。
- [ ] 未保存の記録があるとき、その状態が表示される。これは REQ-NFR-005 の受入基準に対応する。
- [ ] 通信できないとき、画面を開いたままなら最後の値と更新できない旨が表示される。これは設計方針の通信できない間の表示に対応する内部条件である。
- [ ] スマートフォンと PC の両方の幅で、画面が欠けずに操作できる。これは REQ-NFR-002 の受入基準に対応する。
- [ ] 例示テストで、プログラムがある場合とない場合、ルーティンの一覧、週の境界、部位区分ごとのセット数の集計を確かめる。未保存の表示はブラウザテストで確かめる。これは REQ-PRG-005、REQ-PRG-025 の受入基準と、ホームの今週の実施状況の集計の内部条件に対応する。
- [ ] PBT で、今週の実施状況の日数と部位区分ごとのセット数が、0011 と 0012 の計算と一致することを確かめる。これは週の集計の内部条件を PBT で確かめる。
- [ ] Chrome の E2E で、ホームから次のメニューを開始し、終了した後に次の日のメニューが表示されること、空の状態から開始すると記録画面が開くこと、通信できない間の表示、スマートフォンと PC の両幅の操作を確かめる。通信は CDP のネットワークのエミュレーションで切る。これは REQ-PRG-005、REQ-NFR-002 の受入基準と、0022 の開始の経路、ホームの通信できない間の表示の内部条件を確かめる。
- [ ] ブラウザのテストで、今週の実施状況、値がない場合の灰色の輪、ルーティンの一覧、未保存の表示を確かめる。これは REQ-NFR-005、REQ-PRG-025 の受入基準と、今週の実施状況、回復状況の輪の内部条件に対応する。

## 解決方法

`backend/warrior/src/home.rs` に、次のメニュー、ルーティンの一覧、今週の実施状況、回復状況の取得を置く。
`backend/warrior/src/router.rs` に `GET /api/home` を追加する。
`frontend/src/screens/home.rs` に、次のメニュー、ルーティンの一覧、開始、今週の実施状況、回復状況の輪を置く。
`frontend/tests/home.rs` に、今週の実施状況、灰色の輪、ルーティンの一覧、未保存の表示のブラウザのテストを置く。
`frontend/src/text.rs` にホームの文言を追加する。
`backend/warrior/tests/e2e_home.rs` に E2E を追加する。
`backend/warrior/tests/home.rs` に例示テストを追加する。
`backend/pbt/tests/home.rs` に性質テストを置く。

## 結果

ホームに、進行中のプログラムの次の日のメニューと開始、進行中でない場合のルーティンの一覧と空の状態からの開始を表示した。
今週の実施状況は `BodyPartAnalysis` の `training_days` と部位ごとのセット数、回復状況は回復の輪で表示する。
未送信の記録がある場合の表示、取得に失敗したときの表示、回復状況が無い場合の灰色の輪を追加した。
既存の `e2e_home` は追加していない。結合テストは `backend/warrior/tests/programs.rs` と分析の既存のテストで確認する。
