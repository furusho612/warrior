# セットの追加と削除、セット種別を実装する

- Requirements: REQ-SET-001, REQ-SET-002, REQ-LIB-004, REQ-PRF-005, REQ-NFR-003, REQ-NFR-004, REQ-NFR-005, REQ-NFR-007
- Priority: High
- Created: 2026-11-12
- Completed: 2026-11-14
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-set-basic-types

## 目的

種目ごとにセットを追加し、重量と回数を記録できるようにする。
セットの削除と、通常、ウォームアップ、ドロップセットのセット種別の選択を実装する。
セット種別ごとの集計の扱いを、`0012-other-set-calculations.md` の計算に接続する。

## 優先度根拠

セットの記録がないと、総重量、自己ベスト、分析、AI の提案がすべて成立しない。
セットの表と入力の形を先に固定しないと、ドロップセットや左右別の機能が別の構造を持つ。

## 現状

`0021-feature-local-first-sync.md` でセットの表と端末内の保存、`0022-feature-session-lifecycle.md` で記録画面の枠、`0024-feature-exercise-selection-previous.md` で種目の追加を実装する。
しかし、セットの追加、削除、重量と回数の入力、セット種別の選択がない。

## 設計方針

セットは種目に属し、順序を持つ。
セットの追加で行が増え、削除でその行が一覧から消える。
セットの行は、セット番号、重量、回数、セット種別を持つ。
重量の単位は kg とする。
自重と回数の種目は、利用者が加重を任意で入力する。セットの行は、記録時点の体重を `sets.body_weight_kg` に、セットごとの加重を `set_segments.weight_kg` に保存する。セットの重量は、読み取り時に記録時点の体重とセットごとの加重の和で求める。体重は `0043-feature-body-profile.md` の身体情報から取得する。身体情報がない場合は `body_weight_kg` を保存せず、総重量と自己ベストの対象外とする。
セット種別は通常、ウォームアップ、ドロップセットの 3 つとする。

セットの値は、`0012-other-set-calculations.md` の `SetRecord` に変換できる形で保存する。
`0024-feature-exercise-selection-previous.md` の前回のコピーが入力欄へ入れる値は、重量、回数、時間までとする。左右の値、ドロップセットの段、グリップとアタッチメントのコピーは、それぞれ `0027-feature-unilateral-superset.md`、`0026-feature-drop-sets.md`、`0031-feature-grip-attachment.md` が担う。`0024-feature-exercise-selection-previous.md` の入力欄は画面の状態だけを持ち、この issue で端末内の保存へ置き換える。
通常とウォームアップは 1 つの段を持つ。
ドロップセットの段の追加と制約は `0026-feature-drop-sets.md` で実装する。
この issue では、ドロップセットを選べるが、段は 1 つとする。

セットの完了の操作で、レストタイマーを起動する。
タイマーの実装は `0034-feature-rest-timer.md` が担う。
この issue では、セットの完了の状態を保存し、完了のイベントを発行する。

セット種別ごとの集計は、`0012-other-set-calculations.md` の規則に従う。

- 通常は、総重量に含め、推定 1RM と自己ベストの対象とし、部位別のセット数に 1 と数える。
- ウォームアップは、総重量から除き、推定 1RM と自己ベストの対象外とし、部位別のセット数に数えない。
- ドロップセットは、全段を総重量に含め、推定 1RM と自己ベストは最初の段だけを対象とし、部位別のセット数に 1 と数える。

セットの追加と削除は、端末内の保存と送信待ちの列を通る。
削除したセットの段も削除する。
セットの順序は、利用者が並べ替えた順を保つ。
画面のセット番号は表示時に振る。

## 解決方法

`backend/warrior/src/set.rs` に、セットの追加、削除、更新、並べ替えを置く。
`set_segments` の加重は既存の `weight_kg` に保存する。`sets.body_weight_kg` は `0043-feature-body-profile.md` が追加した列に保存し、セットの書き込みで記録時点の体重を入れる。重量の計算は `warrior_core::profile::BodyWeightAtRecord` を使い、読み取り時に行う。
`frontend/src/screens/record.rs` に、セットの表、追加と削除、重量と回数、セット種別の選択を置く。
`frontend/src/text.rs` にセット種別の文言を追加する。
`backend/warrior/tests/e2e_record_set.rs` に E2E を追加する。
Safari の E2E は `backend/warrior/tests/e2e_safari_indexeddb.rs` に追加し、セットの入力と再読み込みの後の復元を確かめる。
`backend/pbt/tests/set.rs` に性質テストを置く。

## 完了時の実装差分

- セットの表、入力、保存の処理は `frontend/src/screens/record/sets.rs` と `frontend/src/screens/record/exercise_view.rs` に分けた。画面の組み立てと行の操作を分けて、変更の影響を小さくするためである。`frontend/src/screens/record.rs` はそれらを組み立てる
- `SetUpdatePayload` に `completed` を足した。値が空になった更新はサーバーで `completed = 0` に戻し、400 にしない。端末の保存が失敗し続けないようにするためである。完了したセットが値を持つ不変条件は、更新と完了の両方で保つ
- セットの完了の前に、いまの値の更新を送信待ちの列へ並べる。更新の後に完了が並ぶようにした。サーバーが値の無い完了を拒否するためである
- 身体情報の体重は端末内の `body_weight` ストアにキャッシュする。同期のメタに型の異なる行を混ぜず、編集権の印の読み取りを壊さないためである。取得に失敗したときはキャッシュを使い、キャッシュが無いときだけ身体情報なしとする
- 前回のセットに `body_weight_kg` を足した。前回のコピーの加重は、前回の段の重量から前回の記録時体重を引いて求める。現在の体重で引くと、体重を変えた後に加重がずれるためである。前回の体重が無いときは加重を 0 とする
- Set 系の破棄は `restore_set` と `restore_set_positions` でサーバーの記録へ戻す。破棄した操作の対象だけを戻し、ほかの送信待ちの入力とメタを残すためである。セットの作成の破棄は端末のセットと段を削除する
- 失敗したセットの作成を破棄したときは、そのセットの後続の更新、完了、削除と、同じ種目の並べ替えも列から消す。種目の作成でも同じように、その種目に属する後続の操作を消す。作成できなかった対象への操作を残さないためである
- 破棄の復元に使うサーバーの記録は、破棄の前に取得する。通信できないときは操作を列に残し、復帰後に破棄をやり直せるようにするためである
- セットの復元は、破棄した操作より後の同じセットの未解決の変更または並べ替えがあるときは行わない。未送信の入力をサーバーの古い値で上書きしないためである
- 復元を見送ったときは、画面にその旨を表示する。未送信の変更を利用者が確認できるようにするためである
- 完了は記録方式に合わせて検証する。時間種目に回数だけの段で完了した操作を受け付けないためである
- セットの保存は、セットが消えているときは何も書かない。削除と保存の競合でセットを作り直さないためである
- セットの表は 5 行分の高さに固定し、行を 44px に揃えた。セットの増減で下の要素の位置が動かないようにするためである
- セット種別と秒の文言は記録用のキーを追加し、カレンダーのキーを流用しない。画面ごとに文言を変えられるようにするためである
- 結合テストの共通処理は `backend/warrior/tests/support/record_common.rs` に、E2E の共通操作は `backend/warrior/tests/support/browser.rs` に寄せた。2 つのテストの準備を同じ実装に保つためである
- Safari の E2E は、同じポートを使うテストを増やさないため、既存の再読み込みのテストにセットの確認を追加した。実行の競合を避けるためである
