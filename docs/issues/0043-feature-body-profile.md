# 身体情報と目的の設定を実装する

- Requirements: REQ-PRF-001, REQ-PRF-002, REQ-PRF-003, REQ-PRF-004, REQ-PRF-005, REQ-MYP-001, REQ-NFR-018
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-body-profile

## 目的

初回の利用時に身体情報を登録できるようにする。
身体情報、目的、週あたりのトレーニング可能日数をいつでも更新できるようにする。
身体情報を入力しなくても記録機能を使えるようにし、未入力の場合は体重を使う計算と AI の評価を行わず、入力を促す。

## 優先度根拠

身体情報は、強度の目安、自重種目の負荷計算、AI の評価とプログラム推奨の入力になる。
最新値だけを持つ規則を先に固定しないと、過去の記録の体重が更新で変わってしまう。

## 現状

0013 で目標カロリーと PFC の計算、0025 から 0033 で記録の機能を実装する。
しかし、身体情報、目的、週あたりの日数の保存と更新の画面がなく、自重種目の記録時の体重も保存していない。

## 設計方針

身体情報は、利用者ごとに 1 行を持つ。
項目は、身長、体重、生年月日、性別、トレーニング経験とする。
性別は男性、女性、その他の 3 つとし、基礎代謝の計算に使う。
その他は、基礎代謝の式で男性と女性の係数の中間値 −78 を使う。
トレーニング経験は初心者、中級者、上級者の 3 つとする。
保持するのは最新値のみで、推移は記録しない。

目的は、筋肥大、ダイエット、ボディメイク、筋力向上、競技力向上の 5 つから 1 つを選ぶ。
あとから変更できる。
週あたりのトレーニング可能日数は 0 から 7 の整数とし、プログラムの推奨と AI のメニューの最適化に使う。
日常の活動量は、低い、普通、高いの 3 つから選ぶ。値は 0054 の計算で使う。

初回のログインの後に、身体情報の登録の画面を出す。
入力を飛ばす操作を用意する。
飛ばした場合も、記録の機能を使える。

身体情報を入力していない状態でも、トレーニングを開始して終了できる。
体重を使う計算の結果と AI の評価は表示せず、身体情報の入力を促す案内を表示する。
体重を使う計算は、自重種目の重量、目標カロリーと PFC、AI の評価とする。
次回セットの提案は、身体情報がなくても、記録から作れる場合は作る。

自重種目のセットは、記録した時点の体重をセットとともに保存する。
あとで身体情報を更新しても、そのセットの重量は変えない。
体重を保存する列は、セットの表に追加する。
身体情報がない状態で自重種目のセットを記録した場合は、体重を保存せず、入力を促す。

入力の検証は次のとおりとする。

- 身長は 100 cm 以上 250 cm 以下。
- 体重は 20 kg 以上 300 kg 以下。
- 生年月日は未来の日付でない。
- 計算した基礎代謝が正の値になる。
- 週あたりの日数は 0 以上 7 以下。

## 完了条件

- [ ] 初回の利用時に身体情報の登録を求められ、身長、体重、生年月日、性別、トレーニング経験の 5 項目を保存できる。保存した値は、再読み込みの後も同じ内容で表示される。トレーニング経験は初心者、中級者、上級者の 3 つから選ぶ。性別は男性、女性、その他の 3 つから選ぶ。年齢は生年月日と日本時間の日付から満年齢で計算する。生年月日は未来の日付でないことと、計算した基礎代謝が正の値になることを検証する。これは REQ-PRF-001 の受入基準に対応する。
- [ ] 低体重または未成年の利用者が身体情報を登録したとき、トレーニングと食事の注意書きと、専門家への相談のガイドが表示される。これは `REQ-NFR-018` の受入基準に対応する。
- [ ] 保存済みの身体情報を更新すると、表示される値が新しい値に変わる。更新の前の値は、推移や履歴として表示されない。これは REQ-PRF-002 の受入基準に対応する。
- [ ] 目的は 5 つから 1 つだけ選べる。保存した目的を別の選択肢に変更でき、変更後の値が保存される。これは REQ-PRF-003 の受入基準に対応する。
- [ ] 週あたりのトレーニング可能日数を設定して保存でき、保存した値が画面に表示される。プログラムの推奨と AI のメニューの最適化が、設定した日数を条件に含める。これは REQ-PRF-004 の受入基準に対応する。プログラムの推奨は 0045、AI の最適化は 0059 が担う。
- [ ] 身体情報を入力していない状態でも、トレーニングを開始して終了できる。体重を使う計算の結果と AI の評価は表示されず、身体情報の入力を促す案内が表示される。これは REQ-PRF-005 の受入基準に対応する。
- [ ] マイページで、身体情報、目的、週あたりのトレーニング可能日数、日常の活動量を確認できる。それぞれを更新すると保存され、ほかの画面の表示も新しい値に変わる。これは REQ-MYP-001 の受入基準に対応する。
- [ ] 自重種目のセットが、記録した時点の体重を保存する。あとで身体情報を更新しても、そのセットの体重が変わらない。
- [ ] 身体情報がない状態で自重種目のセットを記録した場合、体重を保存せず、総重量と自己ベストの対象外とし、入力を促す。
- [ ] 入力の検証が、上の範囲の外の値を拒否する。
- [ ] 例示テストで、5 項目の保存、更新、目的の変更、週あたりの日数の境界、性別の 3 つ、満年齢の計算、身体情報なしの記録、体重のスナップショット、基礎代謝が正の値にならない入力の拒否を確かめる。
- [ ] PBT で、身体情報の更新が過去のセットの体重を変えないことを確かめる。
- [ ] E2E で、初回の登録、更新、目的の変更、身体情報を飛ばして記録する経路、入力を促す案内、低体重または未成年の注意書きと相談のガイドを確かめる。

## 解決方法

`migrations/` に `profiles` の表を追加し、`sets` に記録時の体重の列を追加する。
`backend/warrior_core/src/profile.rs` に、身体情報、目的、経験、活動量の型と検証を置く。検証は 0013 の基礎代謝の計算を使い、正の値になることを確かめる。
`backend/warrior/src/profile.rs` に、身体情報の取得と更新を置く。
`backend/warrior/src/router.rs` に `GET /api/profile`、`PUT /api/profile` を追加する。
`frontend/src/screens/onboarding.rs` に初回の登録と、低体重または未成年の利用者への注意書きと相談のガイドを置く。
`frontend/src/screens/mypage.rs` にプロフィールの表示と更新を置く。
`frontend/src/screens/record.rs` に身体情報の入力を促す案内を置く。
`backend/warrior/tests/e2e_profile.rs` に E2E を追加する。
`backend/pbt/tests/profile.rs` に性質テストを置く。
