# 自分のルーティンを並べて独自のプログラムを作る

- Requirements: REQ-PRG-021, REQ-PRG-022, REQ-PRG-023, REQ-PRG-024
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-custom-program

## 目的

利用者が、自分のルーティンを順番に並べて独自のプログラムを作れるようにする。
独自のプログラムは、あらかじめ用意した 15 本のプログラムとは別に扱い、推奨と参考には含めない。
開始、進行、やめる、切り替えるの扱いは、用意したプログラムと同じにする。

## 優先度根拠

独自のプログラムは、0044 のルーティンと 0045 のプログラムの基本機能、0047 のホームの後に、利用者のメニューの幅を広げる。
15 本の内容の準備が不要で、ルーティンだけで成立するため、Medium とする。

## 現状

0045 が、15 本のプログラムの構成、推奨、取り込み、進行を実装する。
0044 が、利用者のルーティンの作成、編集、複製、削除、並べ替えを実装する。
しかし、自分のルーティンを並べて独自のプログラムを作る機能はない。
PRD の `REQ-PRG-021` から `REQ-PRG-024` が、この機能の要求を定める。

## 設計方針

独自のプログラムは、利用者に属するデータとして保存する。
プログラムは名前と、順番を持つ 2 日以上 7 日以下の日で構成する。
日は利用者のルーティンを参照し、同じルーティンを複数の日に指定できる。
日ごとのルーティンの内容は、参照先のルーティンを編集すると次のメニューから反映する。

独自のプログラムは、用意したプログラムの取り込みを行わない。
開始すると、並べたルーティンがそのまま日ごとのメニューになる。
トレーニングを行った順に次の日へ進み、最後の日を終えると最初の日に戻る。
進行中のプログラムは、用意したプログラムと独自のプログラムを合わせて 1 つとする。0045 の `user_program_progress` に独自のプログラムへの参照を足し、利用者 ID の一意制約で 1 利用者 1 行、CHECK 制約で、用意したプログラムと独自のプログラムの参照のうち非 NULL が 1 つであることを保証する。やめるときと独自のプログラムを削除するときは、`user_program_progress` の行を削除する。
独自のプログラムから開始したトレーニングは、独自プログラムの日の ID を保存し、進行と前回の比較に使う。前回の比較は、同じ独自プログラムの同じ日から開始した直近の終了済みトレーニングを対象にする。
独自のプログラムをやめる、別のプログラムに切り替える、削除する操作は、用意したプログラムと同じ位置に置く。

独自のプログラムで使っているルーティンは削除できない。
削除しようとした場合は、そのルーティンを使っている独自のプログラムの名前を表示する。
すべての独自のプログラムから外した後に、ルーティンを削除できる。

独自のプログラムの編集では、名前の変更、日の追加、削除、並べ替えができる。
編集後の日数が 2 日未満または 7 日を超える場合は保存しない。
進行中の独自のプログラムを編集しても、次に行う日の位置を変えない。
位置が編集後の日数を超える場合は、最初の日を次に行う日にする。

## 完了条件

- [ ] 名前を付け、日ごとのルーティンを 2 日以上 7 日以下になるように順番に並べて、独自のプログラムを保存できる。同じルーティンを複数の日に指定できる。名前が空のとき、日数が 2 日未満のとき、日数が 7 日を超えるときは保存できない。保存した独自のプログラムは、用意した 15 本とは別の一覧に表示され、推奨にも参考にも表示されない。これは `REQ-PRG-021` の受入基準に対応する。
- [ ] 独自のプログラムを開始しても、自分のルーティンは追加されず、並べたルーティンが日ごとのメニューになる。開始すると、ホームに次に行う日のメニューが表示される。トレーニングを行った順に次の日へ進み、最後の日を終えると最初の日に戻る。やめる操作と、別のプログラムに切り替える操作ができる。やめた後は、その利用者の `user_program_progress` の行が残らず、次に行う日のメニューが表示されない。用意したプログラムと独自のプログラムのどちらかが進行中のときに、もう一方を開始すると、後から開始したプログラムだけが進行中になる。これは `REQ-PRG-022` の受入基準に対応する。
- [ ] 独自のプログラムの名前を変更でき、日を追加、削除、並べ替えできる。編集後の日数が 2 日未満または 7 日を超える場合は保存できない。進行中の独自のプログラムを編集しても、次に行う日の位置は変わらない。位置が編集後の日数を超える場合は、最初の日が次に行う日になる。独自のプログラムを削除すると一覧から消え、進行中だった場合は次に行う日のメニューが表示されなくなる。削除しても、並べていたルーティンは残る。これは `REQ-PRG-023` の受入基準に対応する。
- [ ] 独自のプログラムで使っているルーティンを削除しようとすると、削除されず、そのルーティンを使っている独自のプログラムの名前が表示される。そのルーティンをすべての独自のプログラムから外すと、削除できる。ルーティンを編集すると、その後に独自のプログラムの当日メニューから開始したとき、編集後の種目とセットが入った状態で記録が始まる。これは `REQ-PRG-024` の受入基準に対応する。
- [ ] 独自のプログラムから開始したトレーニングが、独自プログラムの日の ID を保存し、前回の比較と進行に使われる。前回は、同じ独自プログラムの同じ日から開始した直近の終了済みトレーニングを対象にする。
- [ ] 結合テストで、作成、編集、削除、開始、進行、やめる、切り替え、ルーティン編集の反映、ルーティンの削除の禁止とすべての独自のプログラムから外した後の削除、推奨と参考からの除外、名前が空の場合の拒否、同じルーティンを複数の日に指定する場合を確かめる。
- [ ] PBT で、2 日以上 7 日以下の検証、同じルーティンを複数の日に指定する場合、日の並びの保存と再読み込み、進行位置の更新を確かめる。
- [ ] ブラウザのテストで、独自のプログラムの一覧と編集の表示、検証のエラー表示、削除、やめる、切り替え、進行中にホームに表示される次に行う日のメニューを確かめる。
- [ ] E2E で、独自のプログラムの作成から開始、進行、やめる、終了、開始と終了の後のホームの次に行う日のメニューの更新を確かめる。
- [ ] 別のアカウントの独自プログラム ID を指定した取得、編集、削除、開始が 404 になる。0015 の所有者検査を使う。
- [ ] `mise run check` が成功する。PRD の `REQ-PRG-021` から `REQ-PRG-024`、ADR-015 の利用者に属さない表の一覧、`docs/architecture/README.md` の「データの境界」が実装と一致している。

## 解決方法

`migrations/` に `custom_programs`、`custom_program_days`、`custom_program_day_routines` を追加する。
独自のプログラムから開始したトレーニングには、`custom_program_days` の ID を保存する。
`migrations/` の `user_program_progress` に独自のプログラムへの参照を追加し、利用者 ID の一意制約で 1 利用者 1 行、CHECK 制約で、用意したプログラムと独自のプログラムの参照のうち非 NULL が 1 つであることを保証する。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に、`custom_programs`、`custom_program_days`、`custom_program_day_routines` を追加する。`user_program_progress` は 0045 で追加済みである。
`backend/warrior_core/src/custom_program.rs` に、名前と日数の検証、日の並びの規則、進行の位置の更新、やめる操作の状態と行削除、ルーティンの削除の禁止を置く。
`backend/warrior/src/custom_program.rs` に、独自のプログラムの作成、取得、更新、削除、開始、進行、やめる、切り替えの API を置く。
`frontend/src/screens/routines.rs` に、独自のプログラムの一覧、作成、編集、削除、開始、やめる、切り替えの画面を置く。
`frontend/src/screens/record.rs` に、独自のプログラムの当日のメニューを表示する。
`frontend/src/screens/home.rs` と `GET /api/home` に、独自のプログラムの次に行う日のメニューを追加する。
`backend/warrior/tests/custom_program.rs` に、作成、編集、削除、開始、進行、やめる、切り替え、ルーティン編集の反映、ルーティンの削除の禁止とすべての独自のプログラムから外した後の削除、推奨と参考からの除外、名前が空の場合の拒否、同じルーティンを複数の日に指定する場合の結合テストを置く。
`backend/pbt/tests/custom_program.rs` に、2 日以上 7 日以下の検証、同じルーティンを複数の日に指定する場合、日の並びの保存と再読み込み、進行の位置の更新の性質テストを置く。
`frontend/tests/custom_program.rs` に、一覧、編集、検証のエラー表示、削除、やめる、切り替え、ホームの次に行う日のメニューのブラウザのテストを置く。
`backend/warrior/tests/e2e_custom_program.rs` に、独自のプログラムの作成から開始、進行、やめる、終了、開始と終了の後のホームの次に行う日のメニューの更新の E2E を置く。
