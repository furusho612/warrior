# 種目マスターの初期データを投入する

- Requirements: REQ-LIB-001
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-exercise-master-seed

## 目的

種目ライブラリに、100 種以上 110 種以下の代表的な種目をマスターとして登録する。
15 本のプログラムで使う種目をすべて含め、部位ごとに主要な器具の定番種目をそろえる。

## 優先度根拠

種目マスターの初期データがないと、ライブラリと記録の種目の選択が空になる。
段階 2 の人体図と段階 3 のプログラムも、このデータに依存する。

## 現状

0019 で種目マスターの表と型、0039 で一覧と詳細、0040 で独自種目と上書きを実装する。
しかし、マスターの種目のデータが 1 件もない。
PRD の付録に 103 種目の案があるが、補助筋の割り当てと、15 本のプログラムで使う種目が決まっていない。

## 設計方針

PRD の付録の 103 種目を初期データとする。
種目名、部位区分、狙う部位、使用器具、記録方式、左右別の可否、グリップの選択肢は、付録の表に従う。
主働筋は、付録の「狙う部位」を主働筋として登録する。
補助筋は、PRD の未決事項であるため、この issue では決めない。

15 本のプログラムで使う種目は、0046 のプログラムの内容が決まった後に、不足する種目を追加する。
この issue の完了時に、プログラムの種目がすべて含まれていることを確かめる。

部位ごとに、バーベル、ダンベル、マシン、ケーブル、自重の定番種目をそろえる。
部位区分は、胸、背中、肩、二頭・前腕、三頭、脚、腹筋、その他の 8 つとする。
筋肉の単位は、0019 の 24 個のうち、付録の「狙う部位」に対応するものを使う。

初期データはマイグレーションで投入する。
データの変更は、新しいマイグレーションで行う。
ID はサーバーが生成した UUID v4 とし、固定の値をマイグレーションに書く。
削除した種目の ID を再利用しない。

## 完了条件

- [ ] 種目ライブラリに 100 種以上 110 種以下の種目が登録されている。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 15 本のプログラムで使う種目がすべて含まれる。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 部位区分ごとに、バーベル、ダンベル、マシン、ケーブル、自重の定番種目がそろっている。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 各種目の名称、部位区分、使用器具、記録方式、左右別の可否、グリップの選択肢が、PRD の付録の表と一致する。
- [ ] 主働筋が、付録の「狙う部位」と一致する。
- [ ] 補助筋は、PRD の未決事項が決まるまで登録しない。
- [ ] 初期データの投入がマイグレーションで行われ、同じマイグレーションを 2 回適用しても重複しない。
- [ ] 投入した種目の並びが、部位区分、使用器具、種目名の五十音順の昇順になる。
- [ ] 結合テストで、種目の件数、部位区分ごとの器具の種類、15 本のプログラムの種目の網羅を確かめる。
- [ ] データの整合は、投入の SQL と種目の型の検証で確かめる。PBT は、データが固定であるため使わない。

## 解決方法

`migrations/` に種目マスターの初期データの SQL を追加する。
`backend/warrior/tests/exercise_seed.rs` に、件数、器具、プログラムの種目の網羅を確かめる結合テストを置く。
`0046` のプログラムの内容が決まった後に、不足する種目を追加するマイグレーションを作る。

## 止める理由

PRD の未決事項「種目マスターの補助筋」と「15 本のプログラムの内容」が決まっていない。
補助筋を登録せずに完了とすると、REQ-LIB-002 の主働筋と補助筋の表示と、REQ-AI-017 の補助筋の参考値が成立しない。
15 本のプログラムの種目が決まらないと、REQ-LIB-001 の「15 本のプログラムで使う種目をすべて含める」を満たせない。

## 再開条件

利用者が 103 種目の主働筋と補助筋の割り当てを決める。
利用者が 15 本のプログラムの内容を決め、そこで使う種目を確定する。
