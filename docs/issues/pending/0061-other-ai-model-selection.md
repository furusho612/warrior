# AI のモデルを選定する

- Requirements: なし (ADR-018 のモデルの選定であり、PRD の要求 ID を持たない)
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-ai-model-selection

## 目的

Workers AI のモデルの候補を、PRD のプロンプトで評価し、環境ごとの `AI_MODEL` に固定するモデルを決める。
日本語の品質と、安全の指示の遵守を測る。

## 優先度根拠

AI の評価と提案の品質は、モデルの日本語の能力と指示の遵守に依存する。
モデルが決まらないと、評価と提案の受入基準のうち、内容の品質を確かめられない。

## 現状

0014 でプロンプトと出力の検証、0055 で Workers AI の呼び出し、0056 から 0060 で評価と提案を実装する。
しかし、`AI_MODEL` に固定するモデルが決まっておらず、日本語の品質と安全の指示の遵守を測っていない。

## 設計方針

候補は、ADR-018 の `@cf/meta/llama-4-scout-17b-16e-instruct` と、テキストだけのモデルの中から、日本語の品質と消費の面で良さそうなものを選ぶ。
評価は、PRD の付録のプロンプトを使い、代表的な記録を入れて行う。
記録は、目的 5 つ、レベル 3 つ、評価の日、週、月、次回セットの提案、メニューの最適化、目標重量の達成が難しい場合、痛みの記述がある場合を含む。
評価の観点は、日本語の自然さ、根拠の数値の正しさ、出力の形式の遵守、安全の指示の遵守、応答の時間とする。

安全の指示の遵守では、痛み、けが、体調不良の記述がある場合に、負荷を増やす提案をしないことを確かめる。
出力の形式の遵守では、0014 の検証を通るかを確かめる。

評価の結果を issue に記録し、合格したモデルを `wrangler.toml` の各環境の `AI_MODEL` に固定する。
モデルを変えるときは、同じ評価を行い、ADR に記録する。

## 完了条件

- [ ] 候補のモデルを、PRD のプロンプトと代表的な記録で評価する。これは ADR-018 の判断のうち、モデルの選定を満たす。
- [ ] 評価の観点が、日本語の自然さ、根拠の数値の正しさ、出力の形式の遵守、安全の指示の遵守、応答の時間を含む。
- [ ] 痛み、けが、体調不良の記述がある場合に、負荷を増やす提案をしないことを確かめる。
- [ ] 出力が 0014 の検証を通ることを確かめる。
- [ ] 合格したモデルを、`wrangler.toml` の各環境の `AI_MODEL` に固定する。
- [ ] 評価の結果と選定の理由を issue に記録する。
- [ ] モデルの変更を ADR に記録する。
- [ ] モデルが合格しない場合、外部の AI サービスを使うかを別の ADR で決める。ADR-018 は外部の提供者へのフォールバックを含まない。

## 解決方法

`mise run verify-staging` に、AI の品質の評価の代表的な記録を入れる手順を追加する。
評価の結果を issue に記録し、`wrangler.toml` の `AI_MODEL` を更新する。
モデルの変更は ADR に記録する。

## 止める理由

staging へのデプロイと、代表的な記録の準備が利用者に依存する。
AI の品質の判断は、実際の出力を読む利用者の評価を含む。
エージェントは実環境へ接続しない。

## 再開条件

利用者が 0003 の環境を用意し、staging へデプロイする。
利用者が代表的な記録と、評価の観点の重みを用意する。
