# AI モデルの品質を無料枠で評価する

- Requirements: なし (ADR-018 のモデルの品質確認であり、製品の要求を実装しない。REQ-AI-009 の「重量増加の上限を設けない」は確認項目に含むが、実装は 0058 が担う)
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-ai-model-evaluation

## 目的

0061 で置いた暫定既定値の Llama 4 Scout を、PRD のプロンプトと代表的な記録で評価する。
合格しなければ代替候補から選び、`AI_MODEL` を確定する。

## 優先度根拠

モデルの品質は、PRD のプロンプトで評価するまで確定しない。
無料枠の範囲で十分な品質が得られない場合、AI の評価と提案の品質が受入基準を満たさない。

## 現状

0061 で `AI_MODEL` の暫定既定値と候補、無料枠の見積もり、評価の fixture と `mise run ai-eval` を用意する。
しかし、実際のモデルの品質評価と、暫定既定値を維持するかの判断がまだない。

## 設計方針

評価は、PRD の付録のプロンプトと、0061 が用意した代表的な記録の fixture で行う。
記録は、目的 5 つ、レベル 3 つ、評価の日、週、月、次回セットの提案、メニューの最適化、目標重量の達成が難しい場合、痛みの記述がある場合を含む。

候補は次のとおりとする。

- `@cf/meta/llama-4-scout-17b-16e-instruct` (暫定既定値)
- `@cf/openai/gpt-oss-20b`
- `@cf/google/gemma-3-12b-it`
- `@cf/meta/llama-3.3-70b-instruct-fp8-fast`
- `@cf/deepseek-ai/deepseek-v4.1-flash-1017`

評価の観点は、日本語の自然さ、根拠の数値の正しさ、出力の形式の遵守、安全の指示の遵守、応答の時間、1 リクエストあたりの Neurons とする。

安全の指示の遵守では、痛み、けが、体調不良の記述がある場合に、負荷を増やす提案をしないことを確かめる。
出力の形式の遵守では、0014 の検証を通るかを確かめる。

入力 8,000 トークン、出力 1,200 トークンのリクエストを 1 日 20 回実行しても、10,000 Neurons 以下になるモデルだけを候補にする。
実際の記録で測った最大の入力と出力がこれを超える場合は、その値で再計算する。

暫定既定値の Llama 4 Scout が合格したら、`AI_MODEL` を変えずに確定する。
合格しない場合は、代替候補のうち、無料枠の条件を満たす中で最も品質の高いモデルを選び、`AI_MODEL` を確定する。
全ての候補が品質の基準を満たさない場合は、無料枠の条件を満たす中で最も品質の高いモデルを選び、制約を ADR-018 に記録する。
外部の AI サービスは使わない。

評価の結果と選定の理由を issue に記録し、モデルを変えた場合は ADR-018 を更新する。
staging を追加したときは、production と同じモデルを staging の `AI_MODEL` に置く。

## 完了条件

- [ ] 評価の観点が、日本語の自然さ、根拠の数値の正しさ、出力の形式の遵守、安全の指示の遵守、応答の時間、1 リクエストあたりの Neurons を含む。
- [ ] 痛み、けが、体調不良の記述がある場合に、負荷を増やす提案をしないことを確かめる。
- [ ] 出力が 0014 の検証を通ることを確かめる。
- [ ] プログラムの進行の目安である 2 〜 10% を、AI の次回セットの提案の上限として扱っていないことを確かめる。
- [ ] 入力 8,000 トークン、出力 1,200 トークンのリクエストを 1 日 20 回実行しても、10,000 Neurons 以下になるモデルだけを候補にする。
- [ ] 暫定既定値の Llama 4 Scout が合格した場合、`AI_MODEL` を変えない。合格しない場合、代替候補から選び、`AI_MODEL` を更新する。
- [ ] 全ての候補が品質の基準を満たさない場合、無料枠の条件を満たす中で最も品質の高いモデルを選び、制約を ADR-018 に記録する。
- [ ] 評価の結果と選定の理由を issue に記録する。
- [ ] モデルを変えた場合、ADR-018 を更新する。
- [ ] 外部の AI サービスを使わない。
- [ ] データが固定の評価であるため、PBT は使わない。

## 解決方法

`mise run ai-eval` で評価のプロンプトを出力し、Workers AI の Playground または staging で利用者がモデルを実行する。
評価の結果を issue に記録する。
モデルを変える場合は、`wrangler.toml` の `[env.production]` の `AI_MODEL` を更新する。
staging を追加したときは、`[env.staging]` の `AI_MODEL` も同じ値にする。
モデルの変更は ADR-018 に記録する。

## 止める理由

評価には Workers AI の Playground または staging が必要であり、実環境への接続は利用者に依存する。
代表的な記録の準備と、品質の判断も利用者に依存する。
エージェントは実環境へ接続しない。

## 再開条件

利用者が Workers AI の Playground または staging で評価できる状態を用意する。
利用者が代表的な記録と、評価の観点の重みを用意する。
