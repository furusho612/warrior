# 種目マスターの初期データを投入する

- Requirements: REQ-LIB-001
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-exercise-master-seed

## 目的

種目ライブラリに、100 種以上 110 種以下の代表的な種目をマスターとして登録する。
15 本のプログラムで使う種目をすべて含め、部位ごとに主要な器具の定番種目をそろえる。

## 優先度根拠

種目マスターの初期データがないと、ライブラリと記録の種目の選択が空になる。
段階 2 の人体図と段階 3 のプログラムも、このデータに依存する。

## 現状

0019 で種目マスターの表と型、0039 で一覧と詳細、0040 で独自種目と上書きを実装する。
PRD の「付録: 種目マスターの初期登録案」で、103 種目の主働筋と補助筋、使用器具、記録方式を決めた。
しかし、マスターの種目のデータが 1 件もない。

## 設計方針

PRD の付録の 103 種目を初期データとする。
種目名、部位区分、狙う部位、補助筋、使用器具、記録方式、左右別の可否、グリップの選択肢は、付録の表に従う。
主働筋は、付録の「狙う部位」を登録する。
補助筋は、付録の「補助筋」を登録する。
補助筋が「なし」の種目は、補助筋を空にする。

15 本のプログラムで使う種目は、PRD の「付録: 15 本のプログラムの構成」の主な種目を含む。
プログラムの日ごとの種目は 0046 が種目マスターから選ぶ。
15 本のプログラムは、この issue の 103 種の範囲で組む。
0046 は 0042 の種目マスターにない種目を使わない。
不足する場合は、同じ部位の別の種目に置き換える。

部位ごとに、バーベル、ダンベル、マシン、ケーブル、自重の定番種目をそろえる。
部位区分は、胸、背中、肩、二頭・前腕、三頭、脚、腹筋、その他の 8 つとする。
筋肉の単位は、0019 の 24 個のうち、付録の「狙う部位」と「補助筋」に対応するものを使う。

初期データはマイグレーションで投入する。
データの変更は、新しいマイグレーションで行う。
ID はサーバーが生成した UUID v4 とし、固定の値をマイグレーションに書く。
削除した種目の ID を再利用しない。

## 完了条件

- [ ] 種目ライブラリに 100 種以上 110 種以下の種目が登録されている。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 15 本のプログラムの主な種目が、103 種の範囲で表現できる。15 本の種目の網羅は 0046 が確かめる。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 部位区分ごとに、バーベル、ダンベル、マシン、ケーブル、自重の定番種目がそろっている。これは REQ-LIB-001 の受入基準に対応する。
- [ ] 各種目の名称、部位区分、使用器具、記録方式、左右別の可否、グリップの選択肢が、PRD の付録の表と一致する。
- [ ] 主働筋が、付録の「狙う部位」と一致する。
- [ ] 補助筋が、付録の「補助筋」と一致する。補助筋が「なし」の種目は、補助筋が空である。
- [ ] 初期データの投入がマイグレーションで行われ、同じマイグレーションを 2 回適用しても重複しない。
- [ ] 投入した種目の並びが、部位区分、使用器具、種目名の五十音順の昇順になる。
- [ ] 結合テストで、種目の件数、部位区分ごとの器具の種類、主な種目の存在を確かめる。
- [ ] データの整合は、投入の SQL と種目の型の検証で確かめる。PBT は、データが固定であるため使わない。

## 解決方法

`migrations/` に種目マスターの初期データの SQL を追加する。
`backend/warrior/tests/exercise_seed.rs` に、件数、器具、主な種目の存在、補助筋の整合を確かめる結合テストを置く。
0046 は 0042 のマスターにある種目だけを使う。0042 に種目を追加しない。
