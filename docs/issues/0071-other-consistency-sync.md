# PRD の修正に合わせて issue と ADR を同期する

- Requirements: REQ-PRF-001, REQ-PRF-005, REQ-REC-004, REQ-SET-007, REQ-SET-010, REQ-PRG-003, REQ-PRG-006, REQ-PRG-016, REQ-GOAL-002, REQ-AI-009, REQ-AI-015, REQ-AI-017, REQ-MYP-006, REQ-MYP-008, REQ-NFR-004, REQ-NFR-010, REQ-NFR-013, REQ-NFR-017
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-consistency-sync

## 目的

0070 で修正した PRD に合わせて、issue と ADR の記述を同期する。
PRD が要求の SSOT である状態を保ち、issue が PRD を上書きしている箇所をなくす。

## 優先度根拠

0070 の PRD 修正だけでは、issue と ADR に古い前提が残る。
特に `sessions` のテーブル名、`p256` の feature、プッシュ通知の計測方法、アカウント削除の対象は、実装の形を変える。

## 現状

0070 で PRD を修正する。
しかし、次の issue と ADR は修正前の前提を持つ。

- 0015、0021、0022、0023、0033 は `sessions` を認証とトレーニングの両方に使う。
- 0019 と 0030 は時間種目の左右別を禁じる。
- 0026 と 0028 はドロップセットの RPE を禁じる。
- 0018 は `REQ-NFR-009` をレート制限の根拠にし、`ip_rate_limits` をアカウント削除の対象にする。
- 0017 と 0063 は端末内データの削除を含まない。
- 0064 は CSV の数式インジェクションを扱わない。
- 0066 と 0038 は送信時刻と受信時刻の差を測る。
- ADR-024 と ADR-025 は `p256` の feature と Fuzzing の対象が不足する。
- 0009 は PRD にない受入基準を引用する。
- 0004、0020、0021 は issue 番号の参照が誤っている。

## 設計方針

PRD の修正に合わせ、issue と ADR を同じ変更で更新する。
設計判断を新たに増やさず、0070 で決めた内容を写す。
issue の Requirements は、0070 で追加した `REQ-NFR-017` を含める。

### 同期する内容

- 認証の `sessions` を `auth_sessions`、トレーニングの `sessions` を `training_sessions` に改名する。0022 の API の経路は `training_sessions` に対応させる。
- 0019 の「時間の種目は左右別を持たない」を削除し、0030 に左右別の時間の記録を追加する。
- 0026 と 0028 の「ドロップセットの RPE を禁じる」を削除し、親セットに 1 つ記録する形に変える。
- 0018 の Requirements を `REQ-NFR-017` に変え、`ip_rate_limits` をアカウント削除の対象から外す。
- 0017 と 0063 に、端末内の記録、設定、キャッシュ、認証情報の削除と、再ログイン後の復元防止を追加する。
- 0064 に、CSV の数式インジェクションを防ぐ出力とテストを追加する。
- 0066 と 0038 の計測を、レスト終了から通知の受信までの時間に変える。未達を分母に含める。
- ADR-025 と 0001 の `p256` の feature を `ecdsa` と `ecdh` にする。
- 0065 に、base64url、ISO 8601、UUID、時間の解析、RPE の解析の Fuzzing を追加する。
- 0009 の引用を PRD の実文に合わせ、NFR-015 に引き継ぎ後の元端末の扱いを追加する。
- 0004、0020、0021 の issue 番号の参照を直す。
- 0013 と 0043 の性別を男性、女性、その他の 3 つにし、その他は基礎代謝の係数 -78 を使う。年齢の下限を外し、生年月日が未来でないことだけを検証する。
- 0053 の現在の記録を、直近 1 週間の平均、記録がない場合は自己ベストに変える。
- 0069 は、0070 の AI の重量増加の整理に合わせて、プログラムの進行と AI の提案を区別する。
