# AI の評価と提案の作り直しを実装する

- Requirements: REQ-AI-015
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-ai-redo

## 目的

AI の評価や提案が行き過ぎていると利用者が感じた場合、ボタンから AI に考え直させられるようにする。
AI は同じ記録をもとに、前回の出力を渡され、より控えめな内容で作り直す。
作り直した出力を保存し、次回の候補を置き換える。

## 優先度根拠

AI の出力は記録の事実ではなく、利用者が採用を決める提案である。
控えめに作り直す経路がないと、利用者が提案を採用できない場合に記録の入力の負担が戻る。

## 現状

0014 で出力の型と検証、0055 で生成の状態、0056 と 0057 で評価、0058 で次回セットの提案を実装する。
しかし、評価と提案の画面の作り直しの操作、前回の出力を渡す生成、控えめになったかの検証がない。

## 設計方針

評価と提案の画面に、作り直しのボタンを置く。
作り直しの依頼では、前回の出力と、同じ記録の入力スナップショットを AI に渡す。
プロンプトでは、前回の出力を踏まえ、より控えめな内容で作り直すことと、前回から何を変えたかを最初に 1 文で書くことを指示する。
新しい出力を保存し、次回の候補を置き換える。

評価の作り直しでは、前回の出力の断定を少なくとも 1 つ弱めるか削除する。
0014 の評価の項目に、`certainty` を追加する。
`certainty` は `assertion` (断定) と `hedge` (推測) の 2 つとする。
作り直した評価は、`assertion` の項目の数が前回より少ないか、同じ数でも `assertion` の項目が削除されていることを条件とする。
`assertion` の項目が前回から 0 の場合、これ以上控えめにできない旨を表示し、その出力を合格とする。
同じ出力を返した場合は不合格とし、利用者にその旨を表示する。

提案の作り直しでは、重量、セット数、時間の少なくとも 1 つを依頼前より小さくする。
重量、セット数、時間の最小値は、重量 0 kg、セット数 1、時間 1 秒とする。
依頼前の提案が全ての最小値に達している場合は、これ以上控えめにできない旨を表示し、その出力を合格とする。
同じ出力を返した場合は不合格とし、利用者にその旨を表示する。

評価と提案の作り直しの結果は、新しい出力として保存する。
評価は対象の日の評価を置き換え、提案は次回の候補を置き換える。
前回の出力と入力のスナップショットは、生成の記録に残す。

作り直しの依頼は、生成の状態の `pending` の行を作り、Queue で実行する。
利用者は作り直しの間も記録を続けられる。

## 完了条件

- [ ] 評価または提案の画面のボタンから、作り直しを依頼できる。これは REQ-AI-015 の受入基準に対応する。
- [ ] 作り直した提案が、重量、セット数、時間の少なくとも 1 つを依頼前より小さくする。評価は、依頼前の出力の断定を少なくとも 1 つ弱めるか削除する。同じ出力を返した場合は不合格とする。これは REQ-AI-015 の受入基準に対応する。
- [ ] 依頼前の提案が重量、セット数、時間の最小値に達している場合は、これ以上控えめにできない旨を表示し、その出力を合格とする。最小値は重量 0 kg、セット数 1、時間 1 秒とする。これは REQ-AI-015 の受入基準に対応する。
- [ ] 依頼前の評価の `assertion` の項目が 0 の場合は、これ以上控えめにできない旨を表示し、その出力を合格とする。
- [ ] 同じ出力を返した場合、不合格として利用者に表示する。
- [ ] 作り直しの依頼に、前回の出力と、同じ記録の入力スナップショットが渡る。
- [ ] 新しい出力が保存され、評価は対象の日の評価を置き換え、提案は次回の候補を置き換える。
- [ ] 前回の出力と入力のスナップショットが、生成の記録に残る。
- [ ] 作り直しの間も、記録の操作が止まらない。
- [ ] PBT で、提案の比較が、重量、セット数、時間の少なくとも 1 つが厳密に小さい場合だけ合格し、全て同じ場合と大きくなる場合を不合格にすることを確かめる。
- [ ] PBT で、評価の比較が、`assertion` の項目の数が減った場合だけ合格し、同じ数で削除もない場合を不合格にすることを確かめる。
- [ ] 例示テストで、提案の 3 つの値のそれぞれの減少、最小値、同じ出力、評価の断定の削除と弱め、断定が 0 の場合を確かめる。
- [ ] E2E で、評価と提案の作り直しを依頼し、結果の表示と、次回の候補の置き換えを確かめる。AI の正常系は staging で確かめる。

## 解決方法

`backend/warrior_core/src/ai_redo.rs` に、提案と評価の控えめになったかの比較、最小値の判定を置く。
`backend/warrior_core/src/ai/output.rs` の評価の項目に `certainty` を追加し、プロンプトに `certainty` の指示を追加する。
`backend/warrior/src/ai_job.rs` に、作り直しの依頼の生成の行と、前回の出力と入力スナップショットの引き渡しを追加する。
`backend/warrior/src/router.rs` に `POST /api/evaluations/:id/redo`、`POST /api/proposals/:id/redo` を追加する。
`frontend/src/screens/summary.rs` と `frontend/src/screens/record.rs` に作り直しのボタンと結果の表示を置く。
`frontend/src/text.rs` に作り直しと、これ以上控えめにできない旨の文言を追加する。
`backend/warrior/tests/e2e_ai_redo.rs` に E2E を追加する。
`backend/pbt/tests/ai_redo.rs` に性質テストを置く。
