# 推定 1RM の表示と自己ベストの判定を実装する

- Requirements: REQ-SET-008, REQ-SET-009, REQ-SET-011
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-one-rm-personal-best

## 目的

重量と回数を入力したときに、そのセットの推定 1RM を表示する。
セットを完了した時点で自己ベストの更新を判定し、更新したものをその場で表示する。
自己ベストの対象は、最大重量、推定 1RM、種目別の総重量、時間で記録する種目の最長時間とする。

## 優先度根拠

推定 1RM と自己ベストは、記録中の達成感と、分析と AI の評価の基礎になる。
判定の規則を先に固定しないと、記録、サマリー、分析で自己ベストが食い違う。

## 現状

0012 で推定 1RM、総重量、自己ベストの対象の計算を実装する。
0025 から 0028 でセットの入力、ドロップセット、左右別、反動と補助、RPE を実装する。
0030 で時間で記録する種目を実装する。
0031 でグリップとアタッチメントの選択と分離、0049 で履歴とグラフの絞り込みを実装する。
0029 は比較のキーにグリップとアタッチメントを含める。実際の選択との比較は 0031 が確かめる。
しかし、入力中の推定 1RM の表示、セットの完了時の自己ベストの判定、保存、その場の表示がない。

## 設計方針

推定 1RM は、重量とストリクト回数から 0012 の式で求める。
回数が 1 のときは重量と同じ値とする。
回数が 0 のときは表示しない。
回数が 10 を超えるセットは、参考値の印を付けて表示する。
時間で記録する種目では、推定 1RM を表示しない。

自己ベストは、利用者、種目、グリップとアタッチメントの組、種類ごとに 1 つの値を持つ。
種類は、最大重量、推定 1RM、種目別の総重量、最長時間とする。
値と達成日、達成したトレーニングの ID を保存する。

セットを完了した時点で、次の候補を作り、保存済みの自己ベストと比べる。

- 最大重量は、ドロップセットの最初の段の重量とする。
- 推定 1RM は、ドロップセットの最初の段の重量とストリクト回数から求める。
- 種目別の総重量は、今回のトレーニングのその種目の全セットの総重量を、ストリクト回数で計算する。
- 最長時間は、時間で記録する種目のセットの時間とする。左右別に行う時間で記録する種目は、左右の最大値を最長時間とする。

ウォームアップセットは、自己ベストの対象にしない。
グリップとアタッチメントが違う記録は、別の自己ベストとして比べる。
グリップとアタッチメントの分離は、0031 が確かめる。
0031 より先に着手する場合は、グリップを持たない種目だけで判定を実装し、0031 で分離を追加する。
同じトレーニングの中で同じ種類の自己ベストを複数回更新した場合は、最後の値を残す。

自己ベストの表のキーは、利用者、種目、グリップ、アタッチメント、種類のままとし、記録方式と左右別を含めない。サマリーの候補は同じキーの最大値へ畳む。0040 で独自種目の上書きを扱う前に、キーに記録方式と左右別を含めるかを決める。

完了済みのセットは、更新、削除、完了の取消、同じ ID の作成の再送、そのセットを含む種目の削除をサーバーが 409 で拒否し、画面が入力を無効にする。過去の記録の編集 (0032) で自己ベストを計算し直すときに、この制限を外す。

更新した自己ベストは、セットの完了の直後に画面に表示する。
サマリーの「更新した自己ベスト」は、新しい `personal_bests` の表でそのトレーニングが更新した分とする。

過去の記録の編集と削除で自己ベストが変わる場合は、0032 が対象の種目の自己ベストを全ての記録から計算し直す。

## 完了条件

- [ ] 重量と回数を入力すると、そのセットの推定 1RM が 0012 の式の値として表示される。回数が 1 のときは重量と同じ値が表示される。これは REQ-SET-008 の受入基準に対応する。
- [ ] 回数が 0 のときは推定 1RM を表示せず、回数が 10 を超えるときは参考値の印を付ける。
- [ ] 時間で記録する種目では推定 1RM を表示しない。
- [ ] セットを完了した時点で、最大重量、推定 1RM、種目別の総重量、時間で記録する種目の最長時間の自己ベストを判定し、更新したものをその場で表示する。左右別に行う時間で記録する種目は、左右の最大値を最長時間とする。これは REQ-SET-009 の受入基準に対応する。
- [ ] 最大重量と推定 1RM がドロップセットの最初の段だけを対象にし、種目別の総重量がドロップセットの全段を対象にする。これは REQ-SET-009 の受入基準に対応する。
- [ ] ウォームアップセットが自己ベストの対象にならない。
- [ ] 自己ベストのキーに、種目とグリップとアタッチメントの組を含める。実際のグリップ選択との比較は 0031 が確かめる。これは REQ-SET-011 の受入基準「前回の記録と自己ベストは、同じグリップと同じアタッチメントの記録だけを対象にし、履歴とグラフはグリップとアタッチメントで絞り込める」に対応する。
- [ ] 同じトレーニングで同じ種類の自己ベストを複数回更新した場合、最後の値が残る。
- [ ] サマリーの「更新した自己ベスト」が、新しい `personal_bests` の表でそのトレーニングが更新した分と一致する。
- [ ] 旧 `training_sessions.personal_bests` の JSON を `personal_bests` の表へ移行する。同じキーは最大値とし、達成日とトレーニング ID はその値のものにする。移行後に列を削除する。
- [ ] サマリーが `personal_bests` の表から、そのトレーニングで更新した分だけを返す。
- [ ] 完了済みセットの更新、削除、完了の取消、作成の再送で既存 ID を指定した場合、そのセットを含む種目の削除を 409 で拒否し、画面が入力を無効にする。0032 で再計算とともに解放する。
- [ ] セットの完了は、そのセットの実行中の保存が終わってから書き、保存のループは完了したセットへ値を書かない。完了を含む E2E を繰り返しても `data-sync-status` が `failed` にならない。
- [ ] ウォームアップのセットに推定 1RM を表示しない。
- [ ] 自己ベストの一覧にグリップとアタッチメントを表示する。
- [ ] 自己ベストの再送の応答が、そのトレーニングが保持する自己ベストを返す。
- [ ] 自己ベストの表が、利用者、種目、グリップとアタッチメント、種類ごとに 1 行を持つ。
- [ ] PBT で、自己ベストの判定が、全ての記録から計算し直した値と一致することを確かめる。
- [ ] 例示テストで、最大重量、推定 1RM、種目別の総重量、最長時間の 4 種類と、ドロップセット、ウォームアップ、グリップの分離、左右別に行う時間で記録する種目を確かめる。左右別に行う時間で記録する種目では、最長時間が左右の最大値、合計時間が左右の和、自己ベストが左右を区別しない最長時間になることを確かめる。
- [ ] 結合テストで、セットの完了の応答に更新した自己ベストが含まれることを確かめる。
- [ ] E2E で、自己ベストを更新し、その場の表示とサマリーの一覧を確かめる。

## 解決方法

`migrations/0013_personal_bests.sql` で `personal_bests` の表を追加し、旧 `training_sessions.personal_bests` の JSON を移行する。同じキーは最大値とし、達成日とトレーニング ID はその値のものにする。移行後に `training_sessions.personal_bests` 列を削除する。
`backend/warrior_core/src/personal_best.rs` に、候補の作成と比較、更新した自己ベストの判定を置く。
`backend/warrior/src/set.rs` のセットの完了の処理に自己ベストの判定を加える。完了済みセットの更新、削除、完了取消を 409 で拒否する。同じ ID の作成の再送も、既存のセットが完了していれば 409 で拒否する。
`backend/warrior/src/personal_best.rs` に D1 の読み書きを置く。`apply_completion` は、新しく更新した項目と、そのトレーニングが保持する項目を分けて返す。サマリーは `personal_bests` の表から、そのトレーニングで更新した分だけを返す。
`backend/warrior/src/sync/exercise.rs` は、完了済みセットを含む種目の削除を 409 で拒否する。
`frontend/src/screens/record.rs` に推定 1RM の表示と自己ベストの更新の表示を置く。
`frontend/src/screens/record/sets.rs` は、完了済みセットの入力、種別、削除、完了取消を無効にし、編集できない旨を表示する。
`frontend/src/screens/record/set_save.rs` に、セットごとの保存のループと、完了との順序を守る印を置く。同じファイルのテストで、止めたセットの保存を始めないことと、実行中の保存の終わりを待つことを確かめる。
`frontend/src/screens/record/exercise_view.rs` のセットの完了は、保存のループを止めて実行中の保存が終わってから書き、保存のループは止めたセットと完了したセットへ値を書かない。
`frontend/src/storage/stopwatch.rs` に、ストップウォッチの開始時刻を読み書きする `Storage` のメソッドを置く。
`frontend/src/screens/summary.rs` に更新した自己ベストの一覧を置く。
`backend/warrior/tests/e2e_personal_best.rs` に E2E を追加する。
`backend/pbt/tests/personal_best.rs` に性質テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に `personal_bests` を追加する。

## 結果

`migrations/0013_personal_bests.sql` で、旧 `training_sessions.personal_bests` の JSON を `personal_bests` の表へ移行し、同じキーは最大値、達成日とトレーニング ID はその値のものにした。移行後に `training_sessions.personal_bests` 列を削除した。サマリーは `personal_bests` の表から、そのトレーニングで更新した分だけを返す。旧セッションのサマリーは、ほかのトレーニングが更新した項目を返さない。
完了済みセットの更新、削除、完了の取消、作成の再送で既存 ID を指定した場合、そのセットを含む種目の削除を 409 で拒否する。画面は完了済みセットの入力、種別、削除、完了取消を無効にし、過去の記録の編集ができるようになるまで変更できない旨を表示する。0032 で自己ベストの再計算とともにこの制限を外す。
自己ベストの表のキーは、利用者、種目、グリップ、アタッチメント、種類のままとし、記録方式と左右別を含めない。サマリーの候補は同じキーの最大値へ畳む。0040 で独自種目の上書きを扱う前に、キーを増やすかを決める。
セットの完了は、そのセットの保存のループを止め、実行中の保存が終わってから値の更新と完了を書く。保存のループは、止めたセットと完了したセットへ値を書かない。完了済みのセットへの更新を送らないため、記録の E2E を繰り返しても同期は失敗しない。
ストップウォッチの `Storage` のメソッドは `frontend/src/storage/stopwatch.rs` に置き、`frontend/src/storage/mod.rs` を 1000 行未満に保つ。
セットの完了の再送は、新しく更新した項目ではなく、そのトレーニングが保持する自己ベストを返す。
ウォームアップのセットには推定 1RM を表示しない。自己ベストの一覧にはグリップとアタッチメントを表示する。
