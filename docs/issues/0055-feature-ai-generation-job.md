# AI の生成ジョブの状態と再試行を実装する

- Requirements: REQ-AI-014, REQ-AI-018
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-ai-generation-job

## 目的

AI の評価と提案の生成を、リクエストの中で待たずに Queue で実行する。
生成の状態を D1 の行で持ち、再試行と失敗の扱いを固定し、入出力のスナップショットを R2 に保存して、生成に使った入力とプロンプトの版をたどれるようにする。
AI の応答を待つ間も記録の操作を止めず、応答が得られない場合は提案なしで記録を続けられるようにする。

## 優先度根拠

AI の評価と提案は段階 3 の機能であり、記録と分析の後に作る。
生成の状態と再試行の規則を先に固定しないと、評価と提案の重複と欠落が起きる。

## 現状

0014 で AI のコンテキストと出力の検証、0018 で Queue と Cron の入口、0022 でトレーニングの終了、0033 でメモを実装する。
しかし、AI の生成の状態の表、Queue への投入、消費側の処理、再試行、R2 のスナップショット、失敗時の扱いがない。

## 設計方針

AI の生成は `ai_generation` の行で状態を持つ。
ADR-009 は、日の評価と次回セットの提案をトレーニングの終了時に生成して保存すると決めている。
ADR-021 は、AI の生成とレスト通知の予約を Cloudflare Queues と Cron Triggers で実行すると決めている。
ADR-017 は、AI の入出力のスナップショットを R2 に保存し、D1 にはメタデータだけを置くと決めている。
この issue はこれらの決定に従う。
状態は `pending`、`enqueued`、`generated`、`failed` とする。
行は、生成の種別、利用者 ID、対象のトレーニング ID または期間、種目 ID、一意キー、試行回数、lease の期限、生成した出力の ID を持つ。

トレーニングの終了時には、サーバーが日の評価と、記録のある種目ごとの次回セットの提案の `pending` の行を作る。
記録のない種目には提案の行を作らない。
週と月の評価の `pending` の行は、0057 の Cron が作る。

Cron は `pending` の行だけを `JOBS_QUEUE` へ送り、送信時に `enqueued` と lease の期限を記録する。
Queue のメッセージには生成の ID だけを入れ、記録の本文を入れない。

消費側は、次の順に処理する。

- 生成の行を読み、`enqueued` で lease の期限内であることを確かめる。
- D1 と R2 から入力を作り、0014 のコンテキストを組み立てる。
- Workers AI の `AI` バインディングを呼ぶ。モデル名は環境ごとの `AI_MODEL` から読む。
- 0014 の検証を通す。
- 出力を D1 に保存し、入力と出力のスナップショットを R2 に保存する。プロンプトの版とモデルの識別子も保存する。
- 状態を `generated` にする。

成功した場合は、同じメッセージを複数回処理しても、出力とスナップショットが重複しないようにする。
出力の ID は生成の ID とし、上書きする。
R2 のオブジェクトのキーは生成の ID から決める。

一時的な失敗は `pending` に戻し、再試行する。
対象は、タイムアウト、5xx、429 とする。
恒久的な失敗は `failed` にし、再試行しない。
対象は、400、401、403、422、無料枠の超過とする。
lease の期限を過ぎた `enqueued` の行は、Cron が `pending` に戻す。

R2 に保存できない場合は、生成を失敗させ、提案を出さない。
D1 に出力を保存しない。

AI の生成に失敗した場合、または時間内に応答がない場合も、トレーニングの終了と保存は成功させる。
利用者は提案なしで記録を続けられる。
画面に生成の失敗を表示し、記録の操作を止めない。

Queue と生成のログには、ジョブの種別、生成の ID、試行回数、結果、処理時間、エラーコード、相関 ID を JSON で記録する。
記録の本文、メモ、AI の入出力、トークン、購読の情報は記録しない。

## 完了条件

- [ ] AI の生成が Queue で実行され、リクエストの中で応答を待たない。これは REQ-AI-014 の受入基準「AI の応答を待っている間も、セットの入力と完了ができる」を、生成の経路の側から満たす。
- [ ] トレーニングの終了で、日の評価と、記録のある種目ごとの次回セットの提案の `pending` の行が作られる。記録のない種目には提案の行が作られない。これは REQ-AI-018 の受入基準のうち、生成の対象の部分に対応する。
- [ ] 生成の状態が `pending`、`enqueued`、`generated`、`failed` の間を遷移し、同じメッセージを複数回処理しても出力が重複しない。
- [ ] 一時的な失敗が `pending` に戻り、恒久的な失敗が `failed` になる。
- [ ] lease の期限を過ぎた `enqueued` の行が `pending` に戻る。
- [ ] R2 に保存できない場合、生成を失敗させ、D1 に出力を保存しない。
- [ ] AI の生成に失敗した場合も、トレーニングの終了と保存が成功する。利用者が提案なしで記録を続けられる。これは REQ-AI-014 の受入基準に対応する。
- [ ] Queue のメッセージに生成の ID だけが入り、記録の本文が入らない。
- [ ] ログに記録の本文、メモ、AI の入出力、トークン、購読の情報が出ない。
- [ ] モデル名が環境ごとの `AI_MODEL` から読まれ、コードにリテラル値がない。
- [ ] 単体テストで、状態の遷移、再試行の分類、lease の回復、重複の判定を確かめる。
- [ ] 結合テストで、`wrangler dev --local` の AI の失敗の経路を確かめる。AI の正常系は staging で確かめる。
- [ ] PBT で、状態の遷移が、同じ生成の ID に対して何度処理しても `generated` または `failed` に収束することを確かめる。
- [ ] 例示テストで、タイムアウト、5xx、429、400、401、403、422、無料枠の超過、R2 の失敗を確かめる。

## 解決方法

`migrations/` に `ai_generation` と `ai_outputs` の表を追加する。
`backend/warrior_core/src/ai_job.rs` に、状態、再試行の分類、lease の期限、一意キーの規則を置く。
`backend/warrior/src/ai_job.rs` に、Queue への投入、消費側の処理、Workers AI の呼び出し、R2 のスナップショットを置く。
`backend/warrior/src/router.rs` と `backend/warrior/src/scheduled.rs` に、生成の行の作成と `pending` の送信を追加する。
`backend/warrior/src/session.rs` の終了の処理に、生成の行の作成を追加する。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に `ai_generation` と `ai_outputs` を追加する。
`backend/warrior/tests/ai_job.rs` に結合テストを追加する。
`backend/pbt/tests/ai_job.rs` に状態の性質テストを置く。
