# 週と月の評価の生成と一覧を実装する

- Requirements: REQ-AI-001, REQ-AI-002, REQ-AI-003, REQ-AI-004, REQ-AI-005
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-period-evaluation

## 目的

週と月の評価を、対象期間の終了後に生成して表示する。
期間ごとに 1 件を保ち、一覧から見返せるようにする。
対象期間の記録が少なく評価できない場合は、その旨を伝える。

## 優先度根拠

週と月の評価は段階 3 の振り返りの機能であり、日の評価と部位別の分析の後に作る。
期間の境界と一意キーを先に固定しないと、同じ期間の評価が重複する。

## 現状

0056 で日の評価の生成と一覧を実装する。
0011 で日本時間の週と月の境界、0018 で Cron Triggers の入口を実装する。
しかし、週と月の評価の生成の対象、期間ごとの一意キー、Cron による生成、一覧の期間の絞り込みがない。

## 設計方針

週と月の評価は、対象期間の終了後に Cron Triggers で生成する。
週は日本時間の月曜 0 時に始まり、次の月曜 0 時の直前で終わる。
月は日本時間の 1 日 0 時に始まり、翌月 1 日 0 時の直前で終わる。

Cron は 1 分間隔で実行し、実行のたびに、直前の週と月の期間の終了を過ぎたかを判定する。
期間の終了を過ぎた場合、利用者と期間の一意キーで `pending` の行を 1 つ作る。
一意キーは、利用者、種別が週または月、期間の開始日とする。
同じ期間の行を 2 回作らない。

評価の対象の期間は、終了した期間の 1 週間または 1 か月とする。
評価は、設定した目的に合わせた観点で行う。
観点は 0014 の目的ごとの観点を使う。
評価は、良かった点、改善点、次に取る行動の 3 つに分け、根拠となる記録の数値を添える。
0014 の出力の検証を通す。

対象期間の記録が評価に足りない場合、評価の代わりに評価できない旨を表示する。
記録にない数値と断定した評価を表示しない。
記録がない期間も、評価できない旨の評価を作る。一覧から期間を確認できるようにするためである。

評価の一覧は、週と月の評価を新しい順に並べる。
期間の種別と期間の開始日で絞り込める。
同じ期間の評価は、一覧と詳細に 1 件だけを表示する。

評価の画面の近くに、医療上の助言ではない旨を表示する。0014 の文言のキーを使う。

## 完了条件

- [ ] 週と月の評価が、対象期間の終了後に表示される。これは REQ-AI-001 の受入基準のうち、週と月の評価の部分に対応する。
- [ ] 設定した目的に応じて、0014 の表の観点で評価が表示される。目的を変えると、評価で使う観点もその目的の観点に変わる。これは REQ-AI-002 の受入基準に対応する。
- [ ] 評価が、良かった点、改善点、次に取る行動の 3 つに分かれて表示される。それぞれに、根拠となる記録の数値が含まれる。これは REQ-AI-003 の受入基準に対応する。
- [ ] 過去の評価を一覧で開ける。期間の種別と期間の開始日で絞り込める。これは REQ-AI-004 の受入基準のうち、一覧の部分に対応する。
- [ ] 対象期間の記録が評価に足りないとき、評価の代わりに評価できない旨を表示する。その場合、記録にない数値と断定した評価を表示しない。これは REQ-AI-005 の受入基準に対応する。
- [ ] 評価の一意キーが、利用者、種別、期間の開始日であり、同じ期間の評価が 1 行に保たれる。
- [ ] Cron が同じ期間の `pending` の行を 2 回作らない。
- [ ] 記録がない期間にも、評価できない旨の評価が作られ、一覧から確認できる。
- [ ] 週の境界が月曜 0 時、月の境界が 1 日 0 時であり、端末のタイムゾーンに依存しない。
- [ ] 固定の AI の出力を使って、週と月の観点、3 つの構成、根拠の数値、評価できない場合を確かめる。
- [ ] PBT で、期間の一意キーが同じ期間に対して 1 つに決まり、期間の外の記録を含まないことを確かめる。
- [ ] 例示テストで、週の境界、月の境界、閏年、記録がない期間、同じ期間の重複、目的の変更を確かめる。
- [ ] 結合テストで、Cron の実行で `pending` の行が作られ、2 回実行しても重複しないことを確かめる。
- [ ] E2E で、評価の一覧を開き、週と月で絞り込み、評価できない場合の表示を確かめる。AI の正常系は 0061 の評価で確かめる。

## 解決方法

`backend/warrior_core/src/period_evaluation.rs` に、期間の一意キー、期間の終了の判定、評価の対象の範囲を置く。
`backend/warrior/src/evaluation.rs` に、週と月の評価の取得と一覧の絞り込みを追加する。
`backend/warrior/src/scheduled.rs` に、期間の終了の検出と `pending` の行の作成を追加する。
`backend/warrior/src/router.rs` の評価の一覧に期間の絞り込みを追加する。
`frontend/src/screens/analysis.rs` に週と月の評価の一覧と絞り込みを置く。
`backend/warrior/tests/e2e_period_evaluation.rs` に E2E を追加する。
`backend/pbt/tests/period_evaluation.rs` に性質テストを置く。
