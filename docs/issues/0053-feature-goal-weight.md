# 種目ごとの目標重量と達成の見通しを実装する

- Requirements: REQ-GOAL-001, REQ-GOAL-002, REQ-GOAL-003, REQ-GOAL-004, REQ-GOAL-005, REQ-NFR-019
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-goal-weight

## 目的

種目とグリップとアタッチメントの組ごとに目標重量を設定し、達成したい時期を任意で設定できるようにする。
種目別の履歴とグラフに目標重量と現在の記録との差を表示し、AI が目標重量を踏まえて次回セットの提案とルーティンの変更案を作る。
現在の記録と時期から達成が難しい目標では、一気に届かせる提案をせず、段階的な途中の目標を提案する。

## 優先度根拠

目標重量は段階 3 の機能であり、種目別の履歴と AI の提案の後に作る。
達成の難しさの判断に固定の基準値を設けないことを先に決めないと、種目ごとの現実的な目標を扱えない。

## 現状

0029 で自己ベスト、0049 で種目別の履歴とグラフ、0014 で AI の出力の型と検証を実装する。
しかし、目標重量の保存、変更、取り消し、履歴とグラフへの表示、AI の入力と出力の扱いがない。

## 設計方針

目標は、利用者、種目、グリップとアタッチメントの組ごとに持つ。
目標重量は必須とし、達成したい時期は任意とする。
目標は変更でき、取り消すと目標のない状態に戻る。
目標重量は 0 kg より大きく、1000 kg 以下とする。
達成したい時期は、設定の時点より後の日付とする。

種目別の履歴とグラフに、目標重量の線と、現在の記録との差を表示する。
現在の記録は、表示の時点の日本時間の日付を含む直近 7 日間の終了済みトレーニングの、その種目とグリップとアタッチメントの組の最大重量の平均とする。直近 7 日間に記録がない場合は、同じ組の自己ベストの最大重量とする。どちらもない場合は、差を表示しない。
差は、目標重量から現在の記録を引いた値とする。
履歴とグラフの画面は 0049 を更新する。

AI に渡すコンテキストに、種目ごとの目標重量と達成したい時期を含める。
次回セットの提案とメニューの最適化は、目標重量を踏まえた内容にする。
目標重量がある種目では、次回セットの提案とルーティンの変更案が、その目標重量へ向けた内容になる。
GOAL-003 の次回セットの提案とメニューの変更案は、0058 と 0059 が確かめる。
グリップとアタッチメントを選べる種目では、その組の目標を使う。

目標の達成が難しいかどうかは、その種目の現在の記録、直近の伸び、トレーニング経験、目標の時期までの期間から AI が判断する。
固定の基準値を設けない。
達成が難しい場合は、その目標に一気に届く提案を表示しない。
難しい旨を伝え、段階的に届く途中の目標を提案する。
途中の目標は、現在の記録より大きく、最終の目標より小さい値とする。
時期がない目標は、達成の難しさの判断に時期を使わない。

AI の出力の型に、目標への対応の結果を含める。
結果は、達成できるか、段階的な途中の目標の列、理由を持つ。
0014 の出力の検証を使い、途中の目標が上の範囲を満たさない場合は、その項目を落とす。

目標の設定と変更と取り消しは、端末内の保存と送信待ちの列を通る。

## 完了条件

- [ ] 種目とグリップとアタッチメントの組ごとに目標重量を設定でき、達成したい時期を任意で添えられる。設定した目標は変更でき、取り消すと目標のない状態に戻る。これは REQ-GOAL-001 の受入基準に対応する。
- [ ] 種目別の履歴とグラフに、その種目の目標重量と、現在の記録との差が表示される。現在の記録は、直近 7 日間の終了済みトレーニングの、その種目とグリップとアタッチメントの組の最大重量の平均であり、記録がない場合は同じ組の自己ベストの最大重量である。どちらもない場合は差を表示しない。これは REQ-GOAL-002 の受入基準に対応する。
- [ ] 目標重量を設定した種目とグリップとアタッチメントの組では、目標重量が AI のコンテキストに渡る。次回セットの提案とルーティンの変更案が目標重量を踏まえることは、0058 と 0059 が確かめる。これは REQ-GOAL-003 の受入基準に対応する。
- [ ] 現在の記録と時期から達成が難しい目標では、その目標に一気に届く提案を表示しない。難しい旨と、段階的に届く途中の目標を提案する。これは REQ-GOAL-004 の受入基準に対応する。
- [ ] 目標の達成が難しいかどうかを、その種目の現在の記録、直近の伸び、トレーニング経験、目標の時期までの期間から判断する。同じ目標重量でも、記録と時期が違えば判断が変わる。これは REQ-GOAL-005 の受入基準に対応する。
- [ ] 目標の達成の判断に固定の基準値を設けない。
- [ ] 途中の目標が、現在の記録より大きく、最終の目標より小さい値になる。
- [ ] 時期がない目標では、達成の難しさの判断に時期を使わない。
- [ ] グリップとアタッチメントを選べる種目では、その組の目標を使う。
- [ ] 目標の設定、変更、取り消しが、端末内の保存と送信待ちの列を通る。
- [ ] 0 kg 以下、1000 kg を超える目標重量、設定の時点より前の時期を拒否する。
- [ ] 例示テストで、目標の設定、変更、取り消し、履歴とグラフの差、直近 7 日間の平均、記録がない場合の自己ベスト、グリップの分離、時期なしの目標を確かめる。
- [ ] 固定の AI の出力を使って、達成できる場合、達成が難しい場合、時期を設定しない場合の 3 つのシナリオで、途中の目標の検証と表示を確かめる。
- [ ] PBT で、目標の差が目標重量から現在の記録を引いた値と一致し、現在の記録が直近 7 日間の終了済みトレーニングの最大重量の平均、記録がない場合は同じ組の自己ベストになること、途中の目標の検証が範囲の外の値を拒否することを確かめる。
- [ ] 別のアカウントの目標を取得、変更、取り消しできない。0015 の所有者検査を使う。
- [ ] E2E で、目標を設定し、履歴とグラフの差を確かめ、AI の出力が得られない場合でも目標の表示が残ることを確かめる。

## 解決方法

`migrations/` に `exercise_goals` の表を追加する。
`backend/warrior_core/src/goal.rs` に、目標の型、検証、現在の記録との差、途中の目標の検証を置く。
`backend/warrior/src/goal.rs` に、目標の設定、変更、取り消し、取得を置く。
`backend/warrior/src/router.rs` に目標の経路を追加する。
`backend/warrior_core/src/ai/context.rs` に目標を含める処理を追加する。
`backend/warrior_core/src/ai/output.rs` に目標への対応の型と検証を追加する。
`frontend/src/screens/exercise.rs` に目標の設定と差の表示を置く。
`frontend/src/screens/summary.rs` と `frontend/src/screens/record.rs` に目標を踏まえた提案の表示を置く。
`backend/warrior/tests/e2e_goal.rs` に E2E を追加する。
`backend/pbt/tests/goal.rs` に性質テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に `exercise_goals` を追加する。
