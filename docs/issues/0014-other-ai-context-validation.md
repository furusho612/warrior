# AI に渡すコンテキストの組み立てと出力の検証を実装する

- Requirements: REQ-AI-002, REQ-AI-003, REQ-AI-013, REQ-AI-016, REQ-AI-017
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-ai-context-validation

## 目的

AI に渡す情報をサーバーで組み立て、目的に応じた観点、根拠の数値を含む出力の形、医療上の助言ではない旨、痛みとけがの記述に対する安全ガード、補助筋の参考値の境界を純粋なロジックとして実装する。

## 優先度根拠

評価、次回セットの提案、メニューの最適化、目標重量の提案がすべてこの組み立てと検証に依存する。
安全ガードをモデルの出力だけに任せると、痛みやけがの記述がある場合に負荷を増やす提案が出る。

## 現状

PRD の「AI による評価と最適化」と「付録: AI に渡すコンテキスト」が入力、観点、出力の形、安全ガードを定めているが、実装がない。
AI の呼び出しは 0055 で行うが、入力と出力の型、検証、安全ガードがない。

## 設計方針

`backend/warrior_core/src/ai/` に、コンテキストの組み立て、プロンプト、出力の型と検証、安全ガードを置く。
ADR-010 は、AI に渡す情報をサーバーで組み立て、評価と提案に必要な項目に限ると決めている。
この issue はその決定に従う。
AI の提供者の API キーはアプリが持たず、呼び出しはサーバーで行う。
この issue は呼び出しを含めない。

コンテキストは、目的、身体情報、トレーニング経験、週あたりの日数、対象期間のトレーニング記録 (メモを含む)、種目ごとの目標重量、部位別の分析、補助筋を含むセット数の参考値、回復状況、現在のルーティン、種目の一覧から組み立てる。
アカウントの識別子、メールアドレス、端末の識別子、プッシュ購読の情報は含めない。
メモは対象期間のトレーニングと種目のメモに限る。

補助筋のセットを 0.5 として加えた参考値は、サーバーで計算し、AI に渡すコンテキストにだけ含める。
アプリへ返す出力の型に、この参考値の項目を持たせない。

プロンプトは版を持つ。
指示は system メッセージに置き、利用者のデータは user メッセージに分ける。
メモはタグで囲み、制御文字を空白に、`<` と `>` を全角の `＜` と `＞` に置き換える。
データの中の指示に従わないことを、指示側に明記する。

出力の型は、評価、次回セットの提案、メニューの最適化、目標重量への対応に分ける。
評価は、良かった点、改善点、次に取る行動の 3 つを持ち、それぞれ 1 から 3 項目とする。
各項目は本文と根拠を持ち、根拠には記録の数値を含める。
次回セットの提案は、種目、グリップとアタッチメント、重量、回数または時間、セット数、理由を 1 文で持つ。
メニューの最適化は、現在のルーティンとの差分を持つ。
目標重量への対応は、達成できるか、段階的な途中の目標、理由を持つ。

出力の検証は Serde の型で行い、文字列の長さ、配列の件数、列挙値の範囲を検査する。
形式に合わない項目は落とし、表示できる内容がない場合は生成を失敗させる。
評価の各項目の根拠に数字がない項目は落とす。
提案の理由が空の項目は落とす。

痛み、けが、体調不良の記述がある場合は、モデルの出力だけに頼らず、サーバー側で負荷を増やす提案を除く。
サーバーは、メモに固定の一覧の語が含まれるかを調べる。
一覧は、痛み、痛い、けが、怪我、故障、体調不良、調子が悪い、めまい、吐き気、しびれとする。
一覧の語が含まれる場合は、そのトレーニングまたは種目の次回セットの提案を除き、負荷を下げるか休むことと、続く場合は医師などの専門家への相談を案内する文を返す。
モデルの分類は補助にだけ使い、固定の一覧の判定を弱めない。
メニューの最適化でも、対象のルーティンに痛みやけがの記述がある種目が含まれる場合は、その種目の量を増やす変更を除く。

医療上の助言ではない旨の文言は、型付きのキーと日本語の表で持つ。
画面は 0056 以降でこのキーを表示する。

## 完了条件

- [ ] 目的を変えると、評価で重視する観点がその目的の観点に変わる。これは REQ-AI-002 の受入基準「設定した目的に応じて、上の表の観点で評価が表示される」を、プロンプトの組み立ての側から満たす。
- [ ] 評価の出力が、良かった点、改善点、次に取る行動の 3 つに分かれ、それぞれに根拠の数値が含まれる。数字のない項目は落ちる。これは REQ-AI-003 の受入基準に対応する。
- [ ] 医療上の助言ではない旨の文言のキーがあり、評価と提案の画面から参照できる。これは REQ-AI-013 の受入基準「AI の評価と提案の画面に、医療上の助言ではない旨が表示される」を、文言の定義の側から満たす。表示は 0056 以降が担う。
- [ ] メモに固定の一覧の語が含まれる場合、その種目の次回セットの提案が出力に残らず、負荷を下げるか休むことと専門家への相談を案内する文が返る。これは REQ-AI-016 の受入基準に対応する。
- [ ] 一覧の語を含まないメモでは、この除去を理由に提案を落とさない。
- [ ] 補助筋のセットを 0.5 として加えた参考値が、AI に渡すコンテキストにだけ含まれ、アプリへ返す出力の型に含まれない。これは REQ-AI-017 の受入基準「参考値は AI にだけ渡り、画面のセット数には現れない」に対応する。
- [ ] AI に渡すコンテキストに、アカウントの識別子、メールアドレス、端末の識別子、プッシュ購読の情報が含まれない。
- [ ] メモの制御文字とタグを壊す文字が無害化される。
- [ ] 出力の検証が、範囲内の値を受理し、範囲外の値を拒否する。全ての項目を落とした結果、表示できる内容がない場合は生成を失敗させる。
- [ ] PBT で、一覧の語を含むメモでは負荷を増やす提案が必ず除かれること、一覧の語を含まないメモではこの除去が起きないこと、出力の検証が範囲内を受理し範囲外を拒否することを確かめる。
- [ ] 例示テストで、全ての一覧の語、数字のない根拠、上限と下限の長さ、空の提案を確かめる。
- [ ] Fuzzing の対象を 0065 で追加する。この issue ではパーサの型検査までを置く。

## 解決方法

`backend/warrior_core/src/ai/context.rs` にコンテキストの型と組み立てを置く。
`backend/warrior_core/src/ai/prompt.rs` にプロンプトの版、system メッセージ、user メッセージ、メモの無害化を置く。
`backend/warrior_core/src/ai/output.rs` に評価、提案、メニューの差分、目標の型と Serde の検証を置く。
`backend/warrior_core/src/ai/safety.rs` に固定の一覧と負荷を増やす提案の除去を置く。
`backend/warrior_core/src/ai/mod.rs` から公開する。
`backend/pbt/tests/ai.rs` に性質テストを置く。
`backend/warrior_core/src/ai/` の `#[cfg(test)]` に例示テストを置く。
`frontend/src/text.rs` に医療上の助言ではない旨のキーを追加する。
