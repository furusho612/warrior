# ルーティンの保存、編集、複製、削除、開始を実装する

- Requirements: REQ-REC-001, REQ-RTN-001, REQ-RTN-002, REQ-RTN-003, REQ-RTN-004
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-routine

## 目的

よく行うメニューをルーティンとして保存し、種目を選び直さずに記録を始められるようにする。
完了したトレーニングをそのままルーティンとして保存できるようにする。
ルーティンの編集、複製、削除、並べ替えをできるようにする。

## 優先度根拠

ルーティンは段階 1 の入力の手間を減らす中心の機能である。
ルーティンからの開始の経路を先に固定しないと、記録の開始の 3 つの経路のうち 1 つが欠ける。

## 現状

0022 で空の状態からのトレーニングの開始と終了、0024 から 0033 で種目とセットの記録を実装する。
しかし、ルーティンの表、保存、編集、複製、削除、並べ替え、ルーティンからの開始がない。

## 設計方針

ルーティンは、名称と順序を持つ。
ルーティンの種目は、種目のスナップショット、セット数、目標重量、目標回数 (時間の種目は目標時間)、グリップとアタッチメント、レスト時間を持つ。
種目のスナップショットを持つため、種目マスターが編集されてもルーティンの表示は変わらない。
ルーティンの種目は順序を持つ。

完了したトレーニングからルーティンを作る場合は、次の値をコピーする。

- 種目と順序。
- セット数: ウォームアップを除いたセットの数。
- 目標重量: ウォームアップを除いた最初のセットの重量。
- 目標回数または目標時間: ウォームアップを除いた最初のセットの回数または時間。
- グリップとアタッチメント: ウォームアップを除いた最初のセットの選択。
- レスト時間: その種目に指定されたレスト時間。指定がない場合は全体の既定値。

ウォームアップを除いた最初のセットを目標値にする選び方は、PRD が目標値の決め方を定めていないための実装の判断である。

ルーティンの編集では、種目と目標値を変更できる。
複製すると同じ内容の別のルーティンができ、新しい ID を割り当てる。
削除すると一覧から消える。
並べ替えで一覧の順序が変わる。

ルーティンから開始すると、そのルーティンの種目とセットが入った状態で記録の画面が開く。
セットは通常の種別とし、目標重量と目標回数を初期値にする。
前回の記録も合わせて表示する。
開始の経路は、0022 の開始の API と画面を使う。
ルーティンから開始したトレーニングは、開始元のルーティン ID を持つ。
トレーニング全体の前回の比較に使う。

ルーティンの保存、編集、複製、削除、並べ替えは、端末内の保存と送信待ちの列を通る。

## 完了条件

- [ ] 種目ごとに、セット数、目標重量、目標回数または目標時間、グリップとアタッチメント、レスト時間を指定して、ルーティンとして保存できる。保存したルーティンを開くと、指定した値がそのまま表示される。これは REQ-RTN-001 の受入基準に対応する。
- [ ] 終了したトレーニングからルーティンを作ると、そのトレーニングと同じ種目、セット数、目標重量、目標回数または目標時間、グリップとアタッチメント、レスト時間を持つルーティンが保存される。これは REQ-RTN-002 の受入基準に対応する。
- [ ] ルーティンの種目と目標値を編集できる。ルーティンを複製すると同じ内容の別のルーティンができ、削除すると一覧から消える。並べ替えでルーティンの一覧の順序が変わる。これは REQ-RTN-003 の受入基準に対応する。
- [ ] ルーティンから開始すると、そのルーティンの種目とセットが入った状態で記録の画面が開く。前回の記録も合わせて表示される。これは REQ-RTN-004 と REQ-REC-001 の受入基準のうち、ルーティンの経路に対応する。
- [ ] ルーティンから開始したトレーニングが、0022 と同じ記録の画面とサマリーで扱われる。これは 0022 と同じ画面とサマリーを使う内部条件であり、REQ-RTN-004 の受入基準の外側である。
- [ ] ルーティンから開始したトレーニングが、開始元のルーティン ID を持ち、トレーニング全体の前回の比較に使われる。
- [ ] ルーティンの種目がスナップショットを持ち、種目マスターの編集の後にルーティンの表示が変わらない。
- [ ] ルーティンの複製が新しい ID を割り当て、元のルーティンと別の行になる。
- [ ] ルーティンの保存、編集、複製、削除、並べ替えが、端末内の保存と送信待ちの列を通る。
- [ ] セット数が 0 のルーティン、名称が空のルーティンを拒否する。
- [ ] PBT で、トレーニングから作ったルーティンが、元のトレーニングの種目と目標値を持ち、ウォームアップを除くことを確かめる。
- [ ] PBT で、ルーティンの複製が同じ内容で別の ID を持ち、元のルーティンの編集が複製に影響しないことを確かめる。
- [ ] 例示テストで、保存、編集、複製、削除、並べ替え、ルーティンからの開始を確かめる。
- [ ] E2E で、ルーティンを作成し、トレーニングから作り、開始し、前回の記録が表示されることを確かめる。

## 解決方法

`migrations/` に `routines`、`routine_exercises` の表を追加する。
`backend/warrior_core/src/routine.rs` に、ルーティンの型、トレーニングからのコピー、複製を置く。
`backend/warrior/src/routine.rs` に、保存、編集、複製、削除、並べ替え、開始を置く。
`backend/warrior/src/router.rs` にルーティンの経路を追加する。
`frontend/src/screens/routines.rs` にルーティンの一覧、編集、複製、削除、並べ替えを置く。
`frontend/src/screens/record.rs` の開始の経路にルーティンを追加する。
`backend/warrior/tests/e2e_routine.rs` に E2E を追加する。
`backend/pbt/tests/routine.rs` に性質テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧にルーティンの表を追加する。
