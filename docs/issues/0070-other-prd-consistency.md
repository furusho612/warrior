# PRD の要求の矛盾と未定義を解消する

- Requirements: REQ-PRF-001, REQ-PRF-005, REQ-REC-004, REQ-SET-007, REQ-SET-010, REQ-PRG-003, REQ-PRG-006, REQ-PRG-016, REQ-GOAL-002, REQ-AI-009, REQ-AI-015, REQ-AI-017, REQ-MYP-006, REQ-MYP-008, REQ-NFR-004, REQ-NFR-010, REQ-NFR-013, REQ-NFR-017
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-prd-consistency

## 目的

PRD の中で矛盾している要求、受入基準を書けない要求、issue が独自に決めている製品判断を、PRD の側で一意に決める。
これにより、後続の issue が同じ要求を別々に解釈する状態をなくす。

## 優先度根拠

`sessions` の名称、時間種目の前回比、ドロップセットの RPE、AI の重量増加の上限、アカウント削除の端末内データのように、実装の形を変える矛盾が複数ある。
これらを放置すると、schema、画面、テストの前提が issue ごとに分かれる。

## 現状

レビューで次を確認した。

- 認証の `sessions` とトレーニングの `sessions` が同じテーブル名になる。
- 時間種目は総重量の対象外だが、`REQ-REC-004` は全種目に総重量の差を要求する。
- `REQ-SET-007` はセットごとの RPE を要求するが、ドロップセットの RPE を禁じる issue がある。
- 種目マスターのサイドプランクは時間の左右別だが、時間種目の左右別を禁じる issue がある。
- `REQ-AI-009` は重量増加の固定上限を禁じるが、AI のプロンプトは 2 〜 10% を指示する。
- `REQ-AI-015` は「同じ出力は不合格」と「最小値なら合格」を並べ、優先順位がない。
- `REQ-MYP-006` と `REQ-NFR-013` はパスキーの登録、追加、削除に再認証を要求するが、issue の API はセッションだけで実行できる。
- `REQ-NFR-010` は利用者に属するすべてのデータの削除を要求するが、端末内の記録、設定、キャッシュ、認証情報が対象にない。
- レート制御の要求が PRD になく、IP ごとのカウンタをアカウント削除の対象にする issue がある。
- `REQ-MYP-008` の CSV は、表計算ソフトの数式として実行されるセルを防ぐ条件がない。
- PRD は未成年とやせている利用者の安全対応を未決とするが、レビュー時点の issue は 13 歳以上を受理していた。

## 設計方針

既存の PRD、ADR、デザイン文書から一意に決まる修正は、その根拠に従う。
製品判断が要る箇所は、個人利用の範囲で保守的な値を仮決定し、この issue に理由を残す。
利用者が別の値を選んだ場合は、この issue の修正を同じ変更で差し替える。

### 要求の意味を変える修正

- **用語**: 「トレーニング」を 1 回の記録の単位、「セッション」を認証の単位として定義する。データベースのテーブル名は「トレーニング」と「認証セッション」を区別する。テーブル名の変更は 0071 で行う。
- **年齢**: 年齢の下限を設けない。生年月日が未来の日付でないことだけを検証する。未成年とやせている利用者への安全対応は、公開する場合に定める。
- **性別**: 男性、女性、その他の 3 つとする。その他は、基礎代謝の式で男性と女性の係数の中間値 -78 を使う。
- **時間種目の前回比**: 時間種目は合計時間と最長時間の差を表示する。トレーニング全体の総重量の差から時間種目を除く。PRD の「時間で記録する種目」の定義に合わせる。
- **ドロップセットの RPE**: ドロップセットは親セットに 1 つ記録する。段ごとには記録しない。PRD の「セットごとの RPE」を保ち、デザインの D 行に欄を出さない規則と両立させる。
- **時間種目の左右別**: 時間種目も左右別を持てる。サイドプランクは左右それぞれの時間を記録する。種目マスターの「時間(左右別)」を生かす。
- **AI の重量増加**: 2 〜 10% はプログラムの進行の目安とし、AI の次回セットの提案の上限にしない。`REQ-AI-009` の「固定の上限を設けない」を優先する。
- **AI の作り直し**: 依頼前の出力が最小値に達している場合は、AI を呼ばずに「これ以上控えめにできない」旨を表示して合格とする。同じ出力の判定は、最小値に達していない場合にだけ行う。
- **パスキーの再認証**: 登録、追加、削除の前に、Google アカウントまたは既存のパスキーで再認証する。セッションだけでは実行できない。
- **アカウント削除**: サーバーのデータに加えて、端末内の記録、設定、キャッシュ、認証情報も削除する。削除後に同じアカウントでログインしても、削除前の端末内データは復元しない。端末内データの削除は 0071 の issue で実装する。
- **レート制御**: 認証、AI、プッシュ購読に利用者ごとと IP ごとの上限を設ける。IP ごとの記録は利用者に紐づけず、アカウント削除の対象にしない。上限と時間窓は非機能要件に置く。
- **CSV**: セルの先頭が `=`、`+`、`-`、`@` のいずれかである場合は、表計算ソフトで数式として実行されない形式で出力する。
- **オフライン**: 記録中の端末内保存と同期は行う。未接続での新規起動と、過去の記録の未接続での閲覧は対象外とする。再読み込みとタブの開き直しは、通信が復帰している状態で行う。
- **現在の記録**: 目標重量との比較に使う現在の記録は、直近 1 週間の終了済みトレーニングの、その種目とグリップとアタッチメントの組の最大重量の平均とする。直近 1 週間に記録がない場合は、同じ組の自己ベストの最大重量とする。
- **前回**: 空の状態から開始したトレーニングは、同じく空の状態から開始した直近の終了済みトレーニングと比べる。プログラムから開始したトレーニングは、同じプログラムの同じ日から開始した直近の終了済みトレーニングと比べる。
- **PFC の調整値**: 体重の更新で範囲外になった場合は、範囲の境界の値に直し、その旨を表示する。
- **プログラムの推奨**: 週あたりの日数が一致するプログラムを推奨する。一致しない場合は、目的と経験が合うプログラムを参考として表示し、推奨とは区別する。週あたりの日数が 0 の場合は推奨を表示しない。
