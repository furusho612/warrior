# ホームに次のメニューと今週の実施状況を表示する

- Requirements: REQ-PRG-005
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-home

## 目的

ホームに、進行中のプログラムの次に行う日のメニューを表示する。
トレーニングの開始の入口をホームに置く。
今週の実施状況と、部位ごとの回復状況の輪を表示する。

## 優先度根拠

ホームはアプリを開いたときの入口であり、次のメニューと開始の操作を置く。
進行中のプログラムの次の日を表示しないと、0045 の進行の位置が利用者に見えない。

## 現状

0007 でホームの空の画面、0044 でルーティン、0045 でプログラムの進行を実装する。
しかし、次のメニュー、開始の入口、今週の実施状況、回復状況の輪がない。

## 設計方針

ホームは、次のメニュー、開始、今週の実施状況、部位ごとの回復状況の輪を表示する。
デザインの「ホーム」の画面に従い、部位ごとの回復状況を輪で示し、中央に開始を置く。

次のメニューは、進行中のプログラムがある場合に、次に行う日のルーティンの種目とセット数の目安を表示する。
進行中のプログラムがない場合は、ルーティンの一覧と空の状態からの開始の入口を表示する。

開始の操作は、次のメニューのプログラムの日から開始する。
進行中のプログラムがない場合は、空の状態から開始する。
開始の経路は 0022 の開始の API と画面を使う。

今週の実施状況は、日本時間の週の始まりから今日までのトレーニングの日数と、部位ごとのセット数を表示する。
週の境界は 0011 の `JstWeek` を使う。
部位ごとのセット数は 0012 の計算を使い、ウォームアップを除き、ドロップセットを 1 と数える。

回復状況の輪は、0051 の回復状況の値を使う。
0051 が実装されるまでは、輪の場所だけを用意し、値がない場合は灰色で表示する。

ホームの表示は、画面を開くたびに最新の値を取得する。
未保存の記録がある場合は、その状態を表示する。
通信できない場合は、画面を開いたままなら最後に取得した値を表示し、更新できないことを示す。再読み込みの後は、ホームの値のキャッシュを持たないため、値の代わりに更新できないことを示す。

## 完了条件

- [ ] 進行中のプログラムがあるとき、ホームに次に行う日のメニューが表示される。これは REQ-PRG-005 の受入基準に対応する。
- [ ] 次のメニューの開始の操作で、プログラムの日のトレーニングが開始される。
- [ ] 進行中のプログラムがないとき、ルーティンの一覧と空の状態からの開始の入口が表示される。
- [ ] 今週の実施状況が、日本時間の週の始まりから今日までのトレーニングの日数と、部位ごとのセット数を表示する。
- [ ] 部位ごとのセット数が、ウォームアップを除き、ドロップセットを 1 と数える 0012 の計算と一致する。
- [ ] 回復状況の輪の場所が表示され、値がない場合は灰色で表示される。値の表示は 0051 が確かめる。
- [ ] 未保存の記録があるとき、その状態が表示される。
- [ ] 通信できないとき、画面を開いたままなら最後の値と更新できない旨、再読み込みの後は更新できない旨が表示される。
- [ ] 画面の幅がスマートフォンと PC の両方で、横にはみ出さない。
- [ ] 例示テストで、プログラムがある場合とない場合、週の境界、部位ごとのセット数の集計、未保存の表示を確かめる。
- [ ] PBT で、今週の実施状況の日数と部位ごとのセット数が、0011 と 0012 の計算と一致することを確かめる。
- [ ] E2E で、ホームから次のメニューを開始し、終了した後に次の日のメニューが表示されることを確かめる。

## 解決方法

`backend/warrior/src/home.rs` に、次のメニュー、今週の実施状況、回復状況の取得を置く。
`backend/warrior/src/router.rs` に `GET /api/home` を追加する。
`frontend/src/screens/home.rs` に、次のメニュー、開始、今週の実施状況、回復状況の輪を置く。
`frontend/src/text.rs` にホームの文言を追加する。
`backend/warrior/tests/e2e_home.rs` に E2E を追加する。
`backend/pbt/tests/home.rs` に性質テストを置く。
