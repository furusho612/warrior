# アカウントの管理画面を実装する

- Requirements: REQ-MYP-006, REQ-MYP-007, REQ-NFR-010
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-account-settings

## 目的

マイページに、ログイン中の Google アカウントの情報を表示し、パスキーの登録、追加、削除をできるようにする。
ログアウトと、アカウントの削除をできるようにする。
アカウントの削除の前に、記録がすべて消えることを確認する。

## 優先度根拠

アカウントの管理は段階 4 の機能であり、Google のログイン、パスキー、アカウントの削除の後に作る。
削除の確認の画面を先に作ると、サーバーの削除の処理と確認の文言が食い違う。

## 現状

0015 で Google のログインとログアウト、0016 でパスキーの登録と削除、0017 でアカウントの削除を実装する。
しかし、マイページのアカウントの画面、Google アカウントの情報の表示、パスキーの一覧と操作、削除の確認の画面がない。

## 設計方針

マイページのアカウントの区分に、次の項目を置く。

- ログイン中の Google アカウントの表示名とメールアドレス。
- パスキーの一覧と、登録、追加、削除の操作。
- ログアウトの操作。
- アカウントの削除の操作。

パスキーの登録、追加、削除には、Google アカウントまたは既存のパスキーによる認証を必要とする。
登録、追加、削除の前に、再認証の画面を出し、短命の elevation token を取得する。
再認証の結果は 5 分間だけ有効とし、1 回の操作で使い切る。
パスキーをすべて失っても Google アカウントでログインできることと、Google アカウントとすべてのパスキーを失った場合は復旧できないことを、画面に表示する。

ログアウトの操作で、セッションを削除し、ログインの画面へ移動する。
ログアウトの後は、記録の画面を開けない。

アカウントの削除の操作では、削除の前に確認の画面を出す。
確認の画面に、身体情報、記録、目標、AI の出力、パスキー、セッション、プッシュ購読を含む利用者に属するすべてのデータが消えることと、取り消せないことを表示する。
利用者が確認の操作を行った後にだけ、`DELETE /api/account` を呼ぶ。
削除の応答の成功 (204) の後に、セッション Cookie、端末トークンの Cookie、設定、Cache API のキャッシュ (アプリシェルを含む) を削除し、0021 の `clear_account` を呼んで IndexedDB と送信待ちの列を削除する。アプリシェルのキャッシュは、次回の起動で再取得して再保存する。
削除済みのアカウントの端末内データが残っている場合は、次回のログイン時に破棄する。削除の後に同じアカウントでログインしても、削除の前の IndexedDB と送信待ちの列が復元されない。
削除の処理が失敗した場合は、その旨を表示し、再試行の操作を出す。

## 完了条件

- [ ] マイページに、ログイン中の Google アカウントの情報が表示される。パスキーを登録、追加、削除でき、操作の後に登録済みのパスキーの一覧が変わる。これは REQ-MYP-006 の受入基準に対応する。
- [ ] マイページからログアウトでき、ログアウトの後は記録の画面を開けない。アカウントの削除では、削除の前に記録がすべて消える旨の確認を表示し、確認した後に削除を実行する。これは REQ-MYP-007 の受入基準に対応する。
- [ ] 確認の画面に、身体情報、記録、目標、AI の出力、パスキー、セッション、プッシュ購読を含む利用者に属するすべてのデータが消えることと、取り消せないことが表示される。
- [ ] 確認の操作の後にだけ、アカウントの削除の API を呼ぶ。
- [ ] 削除の後にセッションの Cookie が消え、ログインの画面へ移動する。
- [ ] 削除の後に、セッション Cookie、端末トークンの Cookie、設定、Cache API のキャッシュ (アプリシェルを含む) が削除され、0021 の `clear_account` が呼ばれる。削除の後に同じアカウントでログインしても、IndexedDB と送信待ちの列の記録が復元されない。IndexedDB と送信待ちの列の削除は 0021 が確かめる。これは `REQ-NFR-010` の受入基準のうち、端末内のキャッシュの削除と再ログイン後の復元の禁止に対応する。
- [ ] 削除の処理が失敗した場合、その旨を表示し、再試行の操作を出す。
- [ ] パスキーをすべて失っても Google アカウントでログインできることと、Google アカウントとすべてのパスキーを失った場合は復旧できないことが、画面に表示される。
- [ ] パスキーの登録、追加、削除の前に再認証を求め、再認証なしの操作が拒否される。
- [ ] E2E で、アカウントの表示、パスキーの追加と削除、再認証なしの操作の拒否、ログアウト、削除の確認、削除の実行、削除の後に同じアカウントでログインしても記録が復元されないこと、設定と Cache API のキャッシュが残らないこと、次回の起動でアプリシェルを再取得して再保存することを確かめる。
- [ ] E2E で、削除の確認を取り消した場合に、アカウントと記録が残ることを確かめる。
- [ ] 画面の表示の確認は E2E で行う。状態を持たない画面のため、PBT は使わない。

## 解決方法

`frontend/src/screens/mypage.rs` にアカウントの区分を追加する。
`frontend/src/screens/account.rs` に、Google アカウントの情報、パスキーの一覧と操作、ログアウト、削除の確認、再認証の画面を置く。
`frontend/src/storage/` に、セッション Cookie、端末トークンの Cookie、設定、Cache API のキャッシュ (アプリシェルを含む) の削除と、0021 の `clear_account` の呼び出しを置く。
`frontend/src/text.rs` にアカウントの文言と削除の確認の文言を追加する。
`backend/warrior/tests/e2e_account_settings.rs` に E2E を追加する。
