# セットの計算規則を実装する

- Requirements: REQ-SET-006, REQ-SET-008, REQ-SET-009
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-set-calculations

## 目的

推定 1RM、総重量、ストリクト回数、部位別のセット数、自己ベストの判定を純粋なロジックとして実装する。
記録、分析、AI、CSV のすべてが同じ計算を使えるようにする。

## 優先度根拠

推定 1RM と自己ベストは記録中の表示に直接出る。
計算を画面ごとに実装すると、同じセットの総重量と自己ベストが画面によって変わる。

## 現状

PRD の「計算ルールと用語定義」と「セット種別ごとの扱い」が計算を定めているが、実装がない。
記録、分析、AI がそれぞれ計算を持つ状態になる。

## 設計方針

`backend/warrior_core/src/set_calc.rs` に、計算に必要な最小の型と関数を置く。
DB の型と API の型は 0019 以降で定義し、この issue では計算の入力だけを定義する。

型は次のとおりとする。

- `SetKind`: `Normal`、`Warmup`、`Drop`。
- `Side`: 左右別の種目で使う `Left`、`Right`。左右別でない種目は `None`。
- `SetSegment`: 1 つの段の重量と回数、反動の回数、補助の回数、左右の値を持つ。
- `SetRecord`: セット種別、段の列、RPE、時間、記録方式を持つ。
- `RecordMode`: `WeightAndReps`、`BodyweightAndReps`、`Time`。
- `PersonalBest`: 最大重量、推定 1RM、種目別の総重量、最長時間の値と達成日を持つ。

ストリクト回数は、回数から反動の回数と補助の回数を引いた値とする。
0 を下回る場合は 0 とする。
入力の検証では、反動の回数と補助の回数の合計が回数を超えるセットを拒否する。

推定 1RM は次の式で求める。
`w` は重量、`r` はストリクト回数とする。

```text
1RM = 100 * w / (48.8 + 53.8 * exp(-0.075 * r))
```

回数が 1 のときは重量をそのまま使う。
回数が 0 のときは推定 1RM を返さない。
回数が 10 を超えるセットは参考値として扱い、記録には参考値の印を持つ。
重量が 0 以下のときは推定 1RM を返さない。

総重量は、重量と回数の積を合計した値とする。
総重量に使う回数は、回数から補助の回数を引いた値とする。
反動の回数は引かない。
ウォームアップセットを除く。
ドロップセットは全段を含める。
左右別のセットは左右を合算する。
自己ベストの種目別の総重量は、ストリクト回数だけで計算する。

部位別のセット数は、種目の部位区分ごとに数える。
ウォームアップセットは 0、通常とドロップセットは 1 と数える。
補助筋として使った部位には数えない。
AI に渡す参考値に限り、補助筋のセットを 0.5 として加える。

自己ベストの判定は、次の対象と規則に従う。

- 最大重量は、ドロップセットの最初の段だけを対象にする。
- 推定 1RM は、ドロップセットの最初の段だけを対象にする。
- 種目別の総重量は、ドロップセットの全段を対象にし、ストリクト回数で計算する。
- 時間で記録する種目は、最長時間を対象にする。
- グリップとアタッチメントが違う記録は、別の比較の対象にする。

時間で記録する種目は、総重量と推定 1RM の対象外とする。
部位別のセット数には 1 セットとして数える。

## 完了条件

- [ ] ストリクト回数が、回数から反動と補助の回数を引いた値になり、0 以上で回数以下になる。これは REQ-SET-006 の受入基準「反動と補助の回数を保存でき、総重量と推定 1RM の計算では計算ルールのとおりに扱う」に対応する。
- [ ] 推定 1RM が、回数が 1 のとき重量に一致し、重量と回数に対して単調で、正の有限の値になる。これは REQ-SET-008 の受入基準「重量と回数を入力すると、そのセットの推定 1RM が計算ルールの式の値として表示される。回数が 1 のときは重量と同じ値が表示される」に対応する。
- [ ] 推定 1RM の式が、上の式と一致する。回数が 10 を超えるセットには参考値の印が付く。
- [ ] 総重量の回数が、回数から補助の回数を引いた値になり、反動の回数を含む。
- [ ] 自己ベストの種目別の総重量が、ストリクト回数だけで計算される。
- [ ] 部位別のセット数が、ウォームアップを 0、通常とドロップセットを 1 と数え、補助筋を数えない。
- [ ] 自己ベストの判定が、最大重量と推定 1RM はドロップセットの最初の段だけ、種目別の総重量は全段、時間の種目は最長時間を対象にする。これは REQ-SET-009 の受入基準「最大重量と推定 1RM はドロップセットの最初の段だけを対象にし、種目別の総重量はドロップセットの全段を対象にする」に対応する。
- [ ] 時間で記録する種目が、総重量と推定 1RM の対象外で、部位別のセット数には 1 と数えられる。
- [ ] グリップとアタッチメントが違う記録が、別の自己ベストの比較の対象になる。
- [ ] PBT で、ストリクト回数、推定 1RM の単調性と回数 1 の一致、総重量の規則、部位別のセット数、自己ベストの対象を確かめる。
- [ ] 例示テストで、ウォームアップ、ドロップセット、左右別、時間の種目、回数 10 と 11 の境界を確かめる。
- [ ] PBT が見つけた反例を `backend/pbt/tests/` の例示テストに残す。

## 解決方法

`backend/warrior_core/src/set_calc.rs` に型と関数を置く。
`backend/warrior_core/src/lib.rs` から `pub mod set_calc;` で公開する。
`backend/pbt/tests/set_calc.rs` に性質テストを置く。
`backend/warrior_core/src/set_calc.rs` の `#[cfg(test)]` に境界の例示テストを置く。
`backend/pbt/proptest-regressions/` に反例を保存する。
記録画面、分析、AI、CSV の issue は、このモジュールの関数だけを使い、計算を再実装しない。
