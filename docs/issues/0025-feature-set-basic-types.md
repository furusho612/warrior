# セットの追加と削除、セット種別を実装する

- Requirements: REQ-SET-001, REQ-SET-002, REQ-LIB-004, REQ-PRF-005, REQ-NFR-003, REQ-NFR-004, REQ-NFR-005, REQ-NFR-007
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-set-basic-types

## 目的

種目ごとにセットを追加し、重量と回数を記録できるようにする。
セットの削除と、通常、ウォームアップ、ドロップセットのセット種別の選択を実装する。
セット種別ごとの集計の扱いを、0012 の計算に接続する。

## 優先度根拠

セットの記録がないと、総重量、自己ベスト、分析、AI の提案がすべて成立しない。
セットの表と入力の形を先に固定しないと、ドロップセットや左右別の機能が別の構造を持つ。

## 現状

0021 でセットの表と端末内の保存、0022 で記録画面の枠、0024 で種目の追加を実装する。
しかし、セットの追加、削除、重量と回数の入力、セット種別の選択がない。

## 設計方針

セットは種目に属し、順序を持つ。
セットの追加で行が増え、削除でその行が一覧から消える。
セットの行は、セット番号、重量、回数、セット種別を持つ。
重量の単位は kg とする。
自重と回数の種目は、利用者が加重を任意で入力する。セットの重量は、記録時点の体重に加重を足した値とする。体重は 0043 の身体情報から取得し、セットとともに保存する。身体情報がない場合は重量を保存せず、総重量と自己ベストの対象外とする。
セット種別は通常、ウォームアップ、ドロップセットの 3 つとする。

セットの値は、0012 の `SetRecord` に変換できる形で保存する。
通常とウォームアップは 1 つの段を持つ。
ドロップセットの段の追加と制約は 0026 で実装する。
この issue では、ドロップセットを選べるが、段は 1 つとする。

セットの完了の操作で、レストタイマーを起動する。
タイマーの実装は 0034 が担う。
この issue では、セットの完了の状態を保存し、完了のイベントを発行する。

セット種別ごとの集計は、0012 の規則に従う。

- 通常は、総重量に含め、推定 1RM と自己ベストの対象とし、部位別のセット数に 1 と数える。
- ウォームアップは、総重量から除き、推定 1RM と自己ベストの対象外とし、部位別のセット数に数えない。
- ドロップセットは、全段を総重量に含め、推定 1RM と自己ベストは最初の段だけを対象とし、部位別のセット数に 1 と数える。

セットの追加と削除は、端末内の保存と送信待ちの列を通る。
削除したセットの段も削除する。
セットの順序は、利用者が並べ替えた順を保つ。
画面のセット番号は表示時に振る。

## 完了条件

- [ ] セットごとに重量と回数を入力して保存できる。セットを追加すると行が増え、削除するとその行が一覧から消える。これは REQ-SET-001 の受入基準に対応する。
- [ ] セットごとに通常、ウォームアップ、ドロップセットの 3 つから種別を選べる。選んだ種別は保存され、集計ではセット種別ごとの扱いに従う。これは REQ-SET-002 の受入基準に対応する。
- [ ] 自重種目のセットで加重を入力でき、体重に加重を足した値が重量として保存される。加重が空の場合は体重だけを使う。身体情報がない場合は重量を保存しない。これは REQ-PRF-005 と REQ-LIB-004 の受入基準に対応する。
- [ ] 重量と回数の入力が、0012 の `SetRecord` に変換される。
- [ ] ウォームアップが総重量から除かれ、推定 1RM と自己ベストの対象外になり、部位別のセット数に数えられない。
- [ ] 通常のセットが総重量に含まれ、推定 1RM と自己ベストの対象になり、部位別のセット数に 1 と数えられる。
- [ ] セットの完了で、完了のイベントが 1 回発行される。レストタイマーの起動は 0034 が受け取る。
- [ ] セットの追加と削除が、端末内の保存と送信待ちの列を通る。
- [ ] セットを削除すると、そのセットの段も削除される。
- [ ] セットの順序が、並べ替えの後も保たれる。
- [ ] PBT で、セット種別ごとの総重量、推定 1RM、自己ベスト、部位別のセット数の扱いが 0012 と一致することを確かめる。
- [ ] 例示テストで、3 つのセット種別、セットの追加と削除、順序の変更を確かめる。
- [ ] E2E で、セットを追加し、重量と回数を入れ、種別を変え、削除する操作を確かめる。
- [ ] Safari の E2E で、セットを入力して再読み込みすると、記録画面が開き、入力済みのセットが残る。これは REQ-NFR-004 の受入基準に対応する。

## 解決方法

`backend/warrior/src/set.rs` に、セットの追加、削除、更新、並べ替えを置く。
`migrations/` の `set_segments` に加重の列を追加する。記録時の体重の列は 0043 が追加する。
`frontend/src/screens/record.rs` に、セットの表、追加と削除、重量と回数、セット種別の選択を置く。
`frontend/src/text.rs` にセット種別の文言を追加する。
`backend/warrior/tests/e2e_record_set.rs` に E2E を追加する。
`backend/pbt/tests/set.rs` に性質テストを置く。
