# トレーニングの開始と終了、サマリーを実装する

- Requirements: REQ-REC-001, REQ-REC-005, REQ-NFR-002
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-session-lifecycle

## 目的

空の状態、ルーティン、プログラムの当日メニューからトレーニングを開始できるようにする。
トレーニングを終了したときに、所要時間、総重量、種目数、セット数、更新した自己ベストをサマリーに表示する。

## 優先度根拠

トレーニングの開始と終了は、すべての記録の機能の入口と出口になる。
サマリーの値を記録から計算する経路を先に固定しないと、画面ごとに集計がばらける。

## 現状

0021 で記録の表、端末内への保存、送信待ちの列、トレーニングの作成と更新の操作を実装する。
しかし、開始の画面、終了の操作、サマリーの計算と表示がない。

## 設計方針

記録の開始は、空の状態、ルーティン、プログラムの当日メニューの 3 つの経路を持つ。
この issue では空の状態からの開始を実装する。
ルーティンからの開始は 0044、プログラムからの開始は 0045 が同じ開始の API と画面を使って実装する。
どの経路で開始したトレーニングも、同じ記録の画面とサマリーで扱う。

トレーニングは、日本時間の日付、開始時刻、終了時刻、開始元の種別、ルーティン ID、プログラムの日 ID、独自プログラムの日 ID、メモを持つ。
認証のモジュール `auth/session.rs` と区別するため、トレーニングのモジュールを `training_session.rs`、種目のモジュールを `training_session_exercise.rs` とする。
日付は 0011 の `JstDate` で決める。
後から日付を指定して追加するトレーニングは 0032 で扱う。

記録の画面は、左に幅 60px の種目レール、下にレストタイマーを固定する枠を持つ。
セットの表は、ウォームアップを含めて 5 行までスクロールなしで表示する。
セットが 6 行以上のときは、表だけがスクロールする。
セット番号を押すと、セット詳細の drawer が開く。
実際の種目、セット、タイマーの中身は 0024 以降の issue が実装する。

トレーニングの終了では、サーバーが記録から次の値を計算し、保存する。

- 所要時間: 開始時刻から終了時刻までの秒数。開始時刻がない記録は、指定された所要時間。
- 総重量: 0012 の総重量。時間で記録する種目は含めない。ウォームアップを除き、ドロップセットの全段を含め、左右別を合算し、反動の回数を含め、補助の回数を含めない。
- 種目数: 記録した種目の数。
- セット数: 記録したセットの数。ウォームアップを除き、ドロップセットを 1 と数え、時間で記録する種目を 1 と数える。PRD の「計算ルールと用語定義」のトレーニングのセット数に従う。
- 更新した自己ベスト: 0012 の判定で、今回のトレーニングで更新した最大重量、推定 1RM、種目別の総重量、時間の種目の最長時間。

サマリーの画面は、終了したトレーニングの記録から値を読み、上の 5 項目を表示する。
AI の評価の表示は 0056 以降で加える。

終了の操作は、記録の画面の「終了」から行う。
終了の後は、サマリーの画面へ移動する。

## 完了条件

- [ ] 空の状態からトレーニングを開始すると、記録の画面が開く。これは REQ-REC-001 の受入基準のうち、空の状態からの経路を満たす。ルーティンとプログラムの経路は 0044 と 0045 が満たす。
- [ ] 空の状態から開始したトレーニングが、記録の画面とサマリーで扱われる。ルーティンとプログラムの経路は、0044 と 0045 が同じ画面とサマリーを使うことを確かめる。これは 0044 と 0045 の経路が同じ画面とサマリーを使う内部条件であり、REQ-REC-001 の受入基準の外側である。
- [ ] トレーニングを終了するとサマリーが表示され、所要時間、総重量、種目数、セット数、更新した自己ベストが並ぶ。表示される値は、終了したトレーニングの記録と一致する。これは REQ-REC-005 の受入基準に対応する。
- [ ] 別のアカウントのトレーニング ID を指定した取得、終了、サマリーの要求が 404 になる。0015 の所有者検査を使う。
- [ ] サマリーの総重量とセット数が、0012 の計算と一致する。
- [ ] サマリーの自己ベストが、0012 の判定と一致し、更新したものだけが並ぶ。
- [ ] 日付を指定しないトレーニングの日付が、日本時間の開始日になる。
- [ ] 記録の画面が、左の種目レール、下のレストタイマーの枠、5 行までのセットの表、セット詳細の drawer を持つ。
- [ ] 記録の画面が、スマートフォンの幅でもレイアウトが崩れず、セットの入力と完了ができる。これは REQ-NFR-002 の受入基準のうち、記録の画面の部分を満たす。
- [ ] 単体テストで、サマリーの 5 項目の計算を固定の記録で確かめる。ウォームアップ、ドロップセット、左右別、時間の種目を含める。
- [ ] 結合テストで、開始、種目とセットの保存、終了、サマリーの取得を確かめる。
- [ ] E2E で、空の状態から開始し、種目とセットを入れて終了し、サマリーの値が記録と一致することを確かめる。
- [ ] PBT で、サマリーの総重量とセット数が 0012 の計算と一致することを確かめる。

## 解決方法

`migrations/` の `training_sessions` に開始元の種別、ルーティン ID、プログラムの日 ID、独自プログラムの日 ID の列を追加する。
`backend/warrior_core/src/training_session.rs` に、トレーニングの型とサマリーの計算を置く。
`backend/warrior/src/training_session.rs` に `POST /api/trainings`、`POST /api/trainings/:id/finish`、`GET /api/trainings/:id/summary` を置く。
`frontend/src/screens/record.rs` に記録の画面の枠と終了の操作を置く。
`frontend/src/screens/summary.rs` にサマリーの画面を置く。
`frontend/src/text.rs` にサマリーの項目の文言を追加する。
`backend/warrior/tests/e2e_training_session.rs` に E2E を追加する。
`backend/warrior_core/src/training_session.rs` の `#[cfg(test)]` にサマリーの例示テストを置く。
`backend/pbt/tests/training_session.rs` にサマリーの性質テストを置く。
