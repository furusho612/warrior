# TLA+ で編集権とオフライン同期の不変条件を検査する

- Requirements: REQ-NFR-003, REQ-NFR-004, REQ-NFR-005, REQ-NFR-015
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/other-formal-ownership-sync

## 目的

記録中のトレーニングの編集権と、端末内の送信待ちの列の状態遷移を TLA+ で書き、TLC で不変条件を検査する。
ADR-024 の形式手法のうち、編集権と引き継ぎ、オフライン同期の 2 つのモデルを担う。

## 優先度根拠

編集権と同期の誤りは、記録の消失や別の端末による上書きとして現れる。
入力の組合せのテストでは見つけにくいため、実装より先にモデルで不変条件を固める。

## 現状

`formal/` がなく、TLA+ の仕様、TLC の実行、不変条件と要求 ID の対応を記録する場所がない。
編集権と同期の状態遷移は、ADR-003 と ADR-002 の文章にだけ存在する。

## 設計方針

`formal/` に `SessionOwnership.tla` と `OfflineSync.tla` を置く。
定数は端末 2 台、セッション 1 つ、操作 2 つ、タイマー 2 つなど小さくし、TLC が短時間で終わるようにする。
状態の種類を増やしすぎず、検査したい不変条件が反例を出せる最小のモデルにする。

`SessionOwnership.tla` は、記録中のトレーニングの編集権、開始した端末、サーバーに保存済みの内容、未同期の変更、引き継ぎ、終了後の同時編集をモデル化する。
不変条件は次のとおりである。

- 記録中のトレーニングを編集できる端末が常に 1 台以下である。
- 引き継ぎは、サーバーに保存済みの内容からのみ行える。
- 編集権を持たない端末の書き込みを拒否する。
- 終了した後は、同じアカウントのどの端末も編集できる。
- 終了後の同時編集は後勝ちになる。
- 後勝ちの上書き以外では、受理済みの書き込みが失われない。

`OfflineSync.tla` は、端末内の送信待ちの列、送信、受理、再送、重複、サーバーへの適用をモデル化する。
不変条件は次のとおりである。

- 同じ操作を複数回適用しても結果が変わらない。
- セットが重複しない。
- 受理済みの操作を最終的にサーバーへ適用する。
- 未同期の変更をサーバーの内容で上書きしない。

`formal/README.md` に、各不変条件と REQ-NFR-003、REQ-NFR-004、REQ-NFR-005、REQ-NFR-015 の対応を書く。
TLC を CI で実行する。
`tla2tools.jar` は版と SHA-256 を固定して取得し、リポジトリに含めない。
不変条件が実際に違反を検出することを、ガードを 1 つ外した仕様で確かめ、結果を issue に記録する。

## 完了条件

- [ ] `formal/SessionOwnership.tla` の TLC の検査が、上の 6 つの不変条件を満たして終了する。これは REQ-NFR-015 の受入基準「記録中のトレーニングは、開始した端末でだけ編集でき、ほかの端末では閲覧だけができる」「引き継ぎの後は元の端末が編集できない」「終了後の編集は後から保存した内容が残る」に対応する。
- [ ] `formal/OfflineSync.tla` の TLC の検査が、上の 4 つの不変条件を満たして終了する。これは REQ-NFR-003、REQ-NFR-004、REQ-NFR-005 の受入基準「通信を切った状態でも入力した内容が失われない」「再読み込みの後も同じ状態から再開できる」「未保存の記録が自動で保存される」を状態遷移の側から支える。
- [ ] ガードを 1 つ外した仕様で TLC が違反を検出し、その結果を issue に記録する。
- [ ] `formal/README.md` に、各不変条件と要求 ID の対応、定数、実行のコマンドを書く。
- [ ] `mise run formal` が TLC を実行し、`mise run check` から呼ばれる。
- [ ] CI が TLC を実行する。
- [ ] `tla2tools.jar` をリポジトリに含めず、版と SHA-256 を固定して取得する。
- [ ] 仕様は実装の写しではなく、ADR-002 と ADR-003 の判断を抽象化したものである。実装の issue は、この仕様と実装の対応を保つ。

## 解決方法

`formal/SessionOwnership.tla`、`formal/OfflineSync.tla`、`formal/README.md` を追加する。
`mise.toml` に `formal` タスクを追加し、`tla2tools.jar` の取得と TLC の実行を書く。
`.github/workflows/ci.yml` に TLC のジョブを追加する。
`tools/` に TLA+ の定数と実行の補助を置く場合は、本番のビルドに含めない。
