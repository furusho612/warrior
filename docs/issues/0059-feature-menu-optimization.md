# メニューの最適化の提案と承認を実装する

- Requirements: REQ-AI-010, REQ-AI-011, REQ-AI-012
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-menu-optimization

## 目的

週と月の評価をもとに、ルーティンの変更案を提案する。
変更案を現在のルーティンとの差分として表示し、利用者が承認したものだけをルーティンに反映する。
提案する種目は、種目ライブラリにあるものに限る。

## 優先度根拠

メニューの最適化は段階 3 の機能であり、週と月の評価とルーティンの後に作る。
承認した変更だけを反映する規則を先に固定しないと、AI の提案が利用者の意図なくルーティンを変える。

## 現状

0044 でルーティン、0045 でプログラム、0057 で週と月の評価、0055 で生成の状態を実装する。
しかし、ルーティンの変更案の生成、差分の表示、変更ごとの承認、承認した変更の反映がない。

## 設計方針

メニューの最適化の提案は、週と月の評価があるときに生成する。
週と月の評価の生成が完了した後に、0055 の生成の行を作り、Queue で生成する。
入力は、週と月の評価、現在のルーティン、トレーニングの記録、部位別の分析、回復状況、目標重量、種目ライブラリとする。
提案は、種目の追加と入れ替え、セット数の増減、部位の配分の見直しを含む。

提案は、現在のルーティンとの差分として表す。
差分は、追加する種目、入れ替える種目と入れ替え先、セット数の変更、部位の配分の変更、理由を持つ。
変更の理由には、記録の数値を含める。
提案する種目は、種目ライブラリにあるものに限る。0014 の出力の検証で、種目ライブラリにない種目を落とす。

画面は、現在のルーティンと提案を並べ、変更ごとに承認と却下の操作を置く。
承認した変更だけをルーティンに反映する。
承認していない変更は反映しない。
複数の変更をまとめて承認する操作は、変更ごとの承認の結果を変えない。
反映の後に、ルーティンの内容と、取り込み済みのプログラムのルーティンとの関係を保つ。プログラムのマスターは変えない。

提案の生成に失敗した場合、または週と月の評価がない場合は、提案を表示しない。
ルーティンは変えない。

## 完了条件

- [ ] 週と月の評価があるとき、ルーティンの変更案に、種目の追加と入れ替え、セット数の増減、部位の配分の見直しが含まれる。これは REQ-AI-010 の受入基準に対応する。
- [ ] 変更案が、現在のルーティンとの差分として表示される。承認した変更案だけがルーティンに反映され、承認していない変更は反映されない。これは REQ-AI-011 の受入基準に対応する。
- [ ] 変更案に含まれる種目が、種目ライブラリに登録されている種目だけである。これは REQ-AI-012 の受入基準に対応する。
- [ ] 変更の理由に、記録の数値が含まれる。
- [ ] 種目ライブラリにない種目を含む変更が、出力の検証で落ちる。
- [ ] 承認していない変更が、ルーティンに反映されない。
- [ ] 提案の反映が、プログラムのマスターを変えない。
- [ ] 週と月の評価がない場合、提案を表示せず、ルーティンを変えない。
- [ ] 固定の AI の出力を使って、種目の追加、入れ替え、セット数の増減、部位の配分、承認、却下、種目ライブラリにない種目を確かめる。
- [ ] PBT で、承認した変更の集合だけがルーティンに反映され、却下した変更が反映されないことを確かめる。
- [ ] PBT で、提案の種目が種目ライブラリの集合の部分集合であることを確かめる。
- [ ] 例示テストで、変更なし、1 つの変更、複数の変更、全て却下、全て承認、種目ライブラリにない種目を確かめる。
- [ ] E2E で、差分を表示し、一部を承認し、ルーティンに承認した変更だけが反映されることを確かめる。AI の正常系は staging で確かめる。

## 解決方法

`backend/warrior_core/src/menu_optimization.rs` に、差分の型、承認の適用、種目ライブラリの検証を置く。
`backend/warrior/src/menu_optimization.rs` に、提案の生成、取得、承認の反映を置く。
`backend/warrior/src/scheduled.rs` に、週と月の評価の生成の後にメニューの最適化の生成の行を作る処理を追加する。
`backend/warrior/src/router.rs` に `GET /api/routines/:id/proposals`、`POST /api/routines/:id/proposals/:proposal_id/approve` を追加する。
`backend/warrior_core/src/ai/output.rs` に、メニューの差分の種目の検証を追加する。
`frontend/src/screens/routines.rs` に差分の表示と承認、却下を置く。
`backend/warrior/tests/e2e_menu_optimization.rs` に E2E を追加する。
`backend/pbt/tests/menu_optimization.rs` に性質テストを置く。
