# 記録の CSV の書き出しを実装する

- Requirements: REQ-MYP-008, REQ-NFR-019
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-csv-export

## 目的

全期間の記録を、1 つの CSV ファイルで書き出せるようにする。
1 行を 1 セットとし、日付、種目、部位区分、セット番号、セット種別、重量、回数、時間、RPE、反動と補助の回数、グリップとアタッチメント、メモの列を持つ。
取り込みの操作は持たない。

## 優先度根拠

CSV の書き出しは段階 4 の機能であり、記録の全ての項目が保存された後に作る。
列の定義と、ドロップセットと左右別の 1 行の表し方を先に固定しないと、書き出したファイルを読み直せない。

## 現状

0021 から 0033 で記録の項目、0031 でグリップ、0033 でメモを実装する。
0036 でプッシュ購読、0017 でアカウントの削除を実装する。
しかし、CSV の生成、R2 への保存、認証済みの経路からのダウンロード、列の定義がない。

## 設計方針

CSV は、利用者の全期間の記録を 1 つのファイルにまとめる。
1 行を 1 セットとする。
列は、日付、種目、部位区分、セット番号、セット種別、重量、回数、時間、RPE、反動と補助の回数、グリップとアタッチメント、メモの順とする。

値の形式は次のとおりとする。

- 日付は、日本時間の `YYYY-MM-DD`。
- 種目と部位区分は、記録時のスナップショットの値。
- セット番号は、種目の中の 1 から始まる番号。
- セット種別は、通常、ウォームアップ、ドロップセットのいずれか。
- 重量は kg、回数は回の整数。
- 時間は秒の整数。時間で記録しないセットは空。
- RPE は 6.0 から 10.0 の表記。空の場合は空。ドロップセットは親セットの RPE を書く。
- 反動と補助の回数は、`反動の回数/補助の回数` の形式。
- グリップとアタッチメントは、日本語の表記。選ばない場合は空。
- メモは、トレーニングのメモと種目のメモを、`;` で区切る。空のメモは省く。メモ内の `;` と `\` は `\;` と `\\` にエスケープし、読み直しで復号する。

ドロップセットは 1 セットとして 1 行にまとめる。
重量と回数の列に、段の値を `;` で区切って順に書く。
左右別のセットは、重量と回数の列に、左右の値を `/` で区切って書く。
ドロップセットと左右別の両方の場合は、段を `;` で区切り、各段の左右を `/` で区切る。
自重種目の重量は、記録時の体重に加重を足した値とする。
ドロップセットと左右別の 1 行の表し方は、PRD が列だけを定めているための実装の判断である。

CSV のセルは、カンマ、引用符、改行を含む場合に引用符で囲み、引用符を 2 つ重ねる。
セルの先頭が `=`、`+`、`-`、`@` のいずれかである場合は、先頭に `'` を付けるか、値を文字列として扱う形式で出力する。表計算ソフトで数式として実行されないようにするためである。
文字の符号化は UTF-8 とし、先頭に BOM を付ける。日本語の表計算のソフトで開いたときに文字化けしないためである。

CSV は Worker が生成し、R2 の `exports/<利用者 ID>/<書き出し ID>.csv` に保存する。
ADR-017 は、CSV の書き出しを R2 に保存し、D1 にはメタデータだけを置き、署名付き URL と公開 URL を使わないと決めている。
この issue はその決定に従う。
D1 には書き出しのメタデータだけを置く。
利用者は認証済みの経路からダウンロードする。
署名付き URL と公開 URL は使わない。
`exports/` の接頭辞に対する R2 のライフサイクルルールで、書き出しのファイルを 7 日で削除する。

取り込みの操作は持たない。

## 完了条件

- [ ] 全期間の記録を、1 つの CSV ファイルとして書き出せる。1 行が 1 セットで、日付、種目、部位区分、セット番号、セット種別、重量、回数、時間、RPE、反動と補助の回数、グリップとアタッチメント、メモの列を持つ。取り込む操作はない。これは REQ-MYP-008 の受入基準に対応する。
- [ ] CSV の行数が、ウォームアップとドロップセットを含む記録のセット数と一致する。
- [ ] ドロップセットが 1 行にまとまり、重量と回数の列に段の値が `;` で区切られる。
- [ ] 左右別のセットが、重量と回数の列に左右の値が `/` で区切られる。
- [ ] カンマ、引用符、改行、空のセル、日本語を含むセルが、正しく引用され、読み直せる。
- [ ] 先頭が =、+、-、@ のセルが、表計算ソフトで数式として実行されない形式で出力される。
- [ ] 先頭に UTF-8 の BOM が付く。
- [ ] CSV が R2 に保存され、D1 にはメタデータだけが保存される。
- [ ] ダウンロードの経路が認証を必須とし、署名付き URL と公開 URL を使わず、R2 のオブジェクトがない書き出しのダウンロードは 404 を返す。これは期限切れのファイルを返さない内部条件である。
- [ ] 別のアカウントの書き出し ID を指定したダウンロードが 404 になる。0015 の所有者検査を使う。
- [ ] アカウントの削除で、書き出しのファイルとメタデータも削除される。
- [ ] PBT で、任意のセルの文字列の引用と復号が往復し、カンマ、引用符、改行を含む場合も一致することを確かめる。
- [ ] PBT で、任意の記録の集合に対して、CSV の行数がセット数と一致し、列の対応が変わらないことを確かめる。
- [ ] 例示テストで、カンマ、引用符、改行、空のセル、日本語、先頭が =、+、-、@ のセル、ドロップセット、左右別、時間で記録する種目、メモ、`;` と `\` を含むメモの往復を確かめる。
- [ ] 結合テストで、R2 への保存、メタデータの保存、認証済みのダウンロード、認証なしのダウンロードの 401、R2 のオブジェクトを削除した書き出しのダウンロードの 404、アカウントの削除を確かめる。
- [ ] E2E で、書き出しを実行し、ダウンロードしたファイルの列と行数を確かめる。

## 解決方法

`backend/warrior_core/src/csv.rs` に、列の定義、セルの引用、数式として解釈される先頭文字の無害化、ドロップセットと左右別の値の整形を置く。
`backend/warrior/src/export.rs` に、全期間の記録の取得、CSV の生成、R2 への保存、メタデータの保存、ダウンロードを置く。
`backend/warrior/src/router.rs` に `POST /api/exports`、`GET /api/exports/:id` を追加する。
`frontend/src/screens/mypage.rs` に書き出しの操作を置く。
`backend/warrior/tests/csv_export.rs` に結合テストを追加する。
`backend/warrior/tests/e2e_csv_export.rs` に E2E を追加する。
`backend/pbt/tests/csv.rs` に性質テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に書き出しのメタデータの表を追加する。
0003 と 0067 が `exports/` の接頭辞のライフサイクルルールを設定する。
