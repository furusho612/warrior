# 記録中のトレーニングの編集権と引き継ぎを実装する

- Requirements: REQ-NFR-015, REQ-NFR-006
- Priority: High
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-session-ownership

## 目的

記録中のトレーニングを開始した端末だけが編集でき、ほかの端末はサーバーに保存済みの内容を閲覧できるようにする。
開始した端末が使えなくなった場合は、ほかの端末からサーバーに保存済みの内容で記録を引き継げるようにする。
終了した後の編集はどの端末からでもでき、後から保存した内容を残す。

## 優先度根拠

複数の端末で同じ記録を編集すると、未同期の変更とサーバーの内容が混ざる。
編集権の境界を先に固定しないと、同期の競合の扱いが後から決められない。

## 現状

0021 で端末内の保存と送信待ちの列、0022 でトレーニングの開始と終了を実装する。
しかし、端末を識別する仕組みと、記録中の書き込みを開始した端末に限る検査がない。

## 設計方針

トレーニングを開始した端末に、そのトレーニングの編集権を紐づける。
編集権はトレーニングごとに持つ。
編集権はアカウントではなく、端末のブラウザに保存した推測できない端末トークンに紐づける。

端末トークンは 32 バイトの乱数とし、HttpOnly、Secure、SameSite=Lax の Cookie で送る。
サーバーは端末トークンの SHA-256 のハッシュだけを D1 に保存し、書き込みのたびに照合する。
端末トークンは利用者に属し、認証中のアカウントと一致する場合だけ編集権を認める。
API の応答とログには出さない。

ログインのときに端末トークンがない場合は作る。
同じ利用者でログインし直した場合は、同じ端末トークンで記録中のトレーニングの編集権に再接続する。
別のアカウントに切り替えたときは、前の利用者の端末トークンを破棄する。

サーバーは、編集権を持たない端末からの記録中の書き込みを 403 で拒否する。
ほかの端末は、サーバーに保存済みの内容を閲覧できる。
端末は、編集権を失ったことを表示し、サーバーの内容を読み直す。

引き継ぎは、ほかの端末で利用者が明示的に操作したときにだけ行う。
操作の前に、元の端末にだけある未同期の変更が失われることを確認する。
引き継いだ端末は、サーバーに保存済みの内容を読み、編集権を得る。
元の端末は閲覧のみになる。

トレーニングの終了後は編集権を外し、同じアカウントのどの端末からでも編集できる。
同時に編集した場合は、サーバーが受理した保存時刻が遅い内容を残す。
編集の要求に含まれる端末の時刻ではなく、サーバーが受理した時刻で決める。

削除した端末トークンの行は、アカウントの削除の対象に含める。

## 完了条件

- [ ] 記録中のトレーニングは、開始した端末でだけ編集でき、ほかの端末では閲覧だけができる。これは REQ-NFR-015 の受入基準に対応する。
- [ ] 開始した端末が使えない場合、ほかの端末から、サーバーに保存済みの内容で記録を引き継げる。これは REQ-NFR-015 の受入基準に対応する。
- [ ] 引き継ぎの後に、元の端末からの書き込みが 403 になり、元の端末は閲覧のみになる。
- [ ] 引き継ぎの前に、元の端末にだけある未同期の変更が失われることを確認する。
- [ ] 終了した後の編集はどの端末からでもでき、編集が重なった場合は後から保存した内容が残る。これは REQ-NFR-015 の受入基準に対応する。
- [ ] 後から保存した内容を、端末の時計ではなくサーバーが受理した時刻で決める。
- [ ] 端末トークンが HttpOnly、Secure、SameSite=Lax の Cookie で渡され、D1 にはハッシュだけが保存される。
- [ ] ログアウトの後に同じ利用者でログインし直すと、記録中のトレーニングの編集権に再接続できる。
- [ ] 別のアカウントに切り替えると、前の利用者の端末トークンが使えなくなる。
- [ ] 同じアカウントでログインした別の端末から、サーバーに保存済みの記録を閲覧できる。これは REQ-NFR-006 の受入基準のうち、複数の端末から同じ記録を見られることを満たす。
- [ ] E2E で、2 つのブラウザのプロファイルを起動し、開始した端末だけが編集できること、ほかの端末が閲覧のみになること、引き継ぎの後に元の端末が編集できなくなることを確かめる。
- [ ] 結合テストで、編集権を持たない端末の書き込みが 403 になること、終了後の同時編集が後勝ちになることを確かめる。
- [ ] 0009 の TLA+ のモデルと実装の対応を保つ。状態を変えるときは仕様も更新する。

## 解決方法

`migrations/` に `terminal_tokens` の表を追加し、`training_sessions` に `owner_terminal_id` と `updated_at` を追加する。
`backend/warrior/src/ownership.rs` に、端末トークンの発行と照合、編集権の検査、引き継ぎを置く。
`backend/warrior/src/session.rs` の書き込みの経路に編集権の検査を加える。
`backend/warrior/src/router.rs` に `POST /api/trainings/:id/takeover` を追加する。
`frontend/src/storage/terminal.rs` に端末トークンの扱いを置く。端末トークンは HttpOnly の Cookie であるため、アプリは値を読まず、サーバーの応答だけを使う。
`frontend/src/screens/record.rs` に、閲覧のみの表示と引き継ぎの確認を置く。
`backend/warrior/tests/e2e_ownership.rs` に E2E を追加する。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に `terminal_tokens` を追加する。
