# プログラムの構成、推奨、取り込み、進行を実装する

- Requirements: REQ-REC-001, REQ-PRG-002, REQ-PRG-003, REQ-PRG-004, REQ-PRG-005, REQ-PRG-019, REQ-PRG-020
- Priority: Medium
- Created: 2026-11-12
- Model: deepseek-v4.1-flash:1017
- Branch: feature/feature-program-structure

## 目的

プログラムを、週あたりの日数と日ごとのルーティンで構成する。
設定した目的、トレーニング経験、週あたりの日数に合うプログラムを推奨し、選んだプログラムの日ごとのルーティンを取り込んで、次に行う日のメニューをホームに表示する。
プログラムに期間を設けず、順番で進める。

## 優先度根拠

プログラムは段階 3 の機能であり、ルーティンと記録の後に作る。
進行の位置を曜日ではなく順番で持つことを先に固定しないと、休んだ日でメニューがずれる。

## 現状

0044 でルーティンの保存と開始を実装する。
しかし、プログラムの表、推奨、取り込み、進行の位置、次に行う日のメニュー、やめる操作と切り替えの操作がない。
15 本のプログラムの内容は 0046 で投入する。

## 設計方針

プログラムは、目的、レベル、週あたりの日数、日ごとのルーティンを持つ。
目的は 5 つ、レベルは 3 つとする。
日ごとのルーティンは、種目、セット数、回数または時間の目安、グリップとアタッチメント、レスト時間を持つ。
プログラムと日とルーティンはマスターの表に置き、`user_id` を持たない。

推奨は、設定した目的、トレーニング経験、週あたりの日数に合うプログラムを返す。
候補が複数ある場合は、週あたりの日数が一致するものを先にし、その後にプログラムの並び順で決める。
週あたりの日数が一致する候補がない場合は、同じ目的と経験のプログラムを参考として返し、推奨とは区別する。
週あたりの日数が 0 の場合は推奨を返さない。
設定を変えた後に表示される推奨は、変更後の条件に合う。

プログラムを選ぶと、日ごとのルーティンを利用者のルーティンとして取り込む。
取り込んだルーティンは編集でき、編集してもプログラムの内容は変わらない。
取り込みの結果は、進行中のプログラム、取り込み元のプログラム、次に行う日の位置を持つ。

進行は、曜日ではなく順番で進める。
プログラムから開始したトレーニングを終了したら、次に行う日の位置を 1 つ進める。
プログラムから開始したトレーニングは、開始したプログラムの日 ID を保存し、進行と前回の比較に使う。
何日か休んだ場合も、休んだ日を飛ばさず、次に行う日のメニューを順に表示する。
1 週間分の最後の日を終えたら、最初の日に戻る。
プログラムに終了日を設けない。

進行中のプログラムをやめる操作と、別のプログラムに切り替える操作を用意する。
やめた後は、次に行う日のメニューを表示しない。
切り替えた場合は、前のプログラムの進行を消し、新しいプログラムの最初の日から始める。
過去に取り込んだルーティンは残す。

ホームの次に行う日のメニューは 0047 が表示する。
この issue では、次に行う日のメニューを取得する API を用意する。

プログラムの内容は 0046 で投入する。
この issue では、テスト用のプログラムのデータを使って、推奨と取り込みと進行を検証する。

## 完了条件

- [ ] 各プログラムが、週あたりの日数と日ごとのルーティンで構成される。各ルーティンに、種目、セット数、回数または時間の目安、グリップとアタッチメント、レスト時間が入る。これは REQ-PRG-002 の受入基準に対応する。
- [ ] 設定した目的、トレーニング経験、週あたりの日数に合うプログラムが、推奨として表示される。設定を変えた後に表示される推奨は、変更後の条件に合う。週あたりの日数が一致しない場合は、目的と経験が合うプログラムが参考として表示され、推奨とは区別される。週あたりの日数が 0 の場合は推奨が表示されない。これは REQ-PRG-003 の受入基準に対応する。
- [ ] プログラムを選ぶと、日ごとのルーティンが自分のルーティンとして追加される。追加したルーティンは編集でき、編集してもプログラムの内容は変わらない。これは REQ-PRG-004 の受入基準に対応する。
- [ ] 進行中のプログラムがあるとき、次に行う日のメニューを取得できる。表示は 0047 が担う。これは REQ-PRG-005 の受入基準のうち、取得の部分を満たす。
- [ ] プログラムの当日メニューから開始すると、記録画面が開く。これは REQ-REC-001 の受入基準のうち、プログラムの経路を満たす。
- [ ] プログラムから開始したトレーニングが、0022 と同じ記録画面とサマリーで扱われる。これは 0022 と同じ画面とサマリーを使う内部条件であり、REQ-PRG-004 の受入基準の外側である。
- [ ] プログラムに終了日がなく、1 週間分のメニューが利用者の操作まで繰り返し表示される。進行中のプログラムをやめる操作と、別のプログラムに切り替える操作ができ、やめた後は次に行う日のメニューが取得できない。これは REQ-PRG-019 の受入基準に対応する。
- [ ] 日ごとのメニューに曜日の割り当てがなく、トレーニングを行った順に次の日へ進む。何日か休んだ場合も、休んだ日を飛ばさず、次に行う日のメニューが順に表示される。これは REQ-PRG-020 の受入基準に対応する。
- [ ] 1 週間分の最後の日を終えると、最初の日に戻る。
- [ ] プログラムから開始したトレーニングが、開始したプログラムの日 ID を保存し、終了後の進行と前回の比較に使われる。
- [ ] プログラムから開始したトレーニングを終了すると、次に行う日の位置が 1 つ進む。
- [ ] プログラムの推奨の候補が複数ある場合、週あたりの日数が一致するものを先にし、その後にプログラムの並び順で決める。一致する候補がない場合は、目的と経験が合うプログラムを参考として返し、推奨とは区別する。日数が 0 の場合は推奨を返さない。
- [ ] 取り込んだルーティンの編集が、マスターのプログラムの内容を変えない。
- [ ] やめたプログラムの進行が消え、過去に取り込んだルーティンが残る。やめた後、その利用者の `user_program_progress` の行が残らない。
- [ ] PBT で、進行の位置が、トレーニングの終了の回数と 1 週間分の日の数から一意に決まり、曜日に依存しないことを確かめる。
- [ ] PBT で、推奨が条件に合うプログラムだけを返し、条件を満たすプログラムを落とさないことを確かめる。参考は推奨と区別し、日数が 0 の場合は推奨を返さない。
- [ ] 例示テストで、目的 5 つとレベル 3 つの組み合わせ、週あたりの日数の一致、0 日、取り込み、進行、休んだ日、やめる、切り替えるを確かめる。
- [ ] E2E で、プログラムを選び、取り込み、開始し、終了し、次に行う日のメニューが進むことを確かめる。

## 解決方法

`migrations/` に `programs`、`program_days`、`program_day_exercises`、`user_program_progress` の表を追加する。
プログラムから開始したトレーニングには、開始した `program_days` の ID を保存する。
`backend/warrior_core/src/program.rs` に、推奨の条件、進行の位置、取り込みのコピーの規則を置く。
`backend/warrior/src/program.rs` に、推奨、取り込み、進行、やめる、切り替えるを置く。やめるときは `user_program_progress` の行を削除する。
`backend/warrior/src/router.rs` にプログラムの経路を追加する。
`frontend/src/screens/routines.rs` にプログラムの一覧、推奨、取り込み、進行、やめる、切り替えるを置く。
`backend/warrior/tests/e2e_program.rs` に E2E を追加する。
`backend/pbt/tests/program.rs` に性質テストを置く。
`backend/warrior_core/src/account_deletion.rs` の表の一覧に `user_program_progress` を追加する。
