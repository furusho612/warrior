# トレーニング記録 Web アプリ PRD

Nov 12, 2026 · @Shoichi

## 概要

ジムでのウェイトトレーニングについて、記録、振り返り、次回メニューの決定までを 1 つの Web アプリで完結させる。

### 解決したい課題

- セットごとの記録に手間がかかり、トレーニングの流れが止まる。
- 前回の重量や回数を覚えておらず、負荷を伸ばせているかがわからない。
- 記録を残しても、次に何をどれだけ行うべきかの判断材料にならない。

### 目的

1. セットの記録を、ジムでその場で、少ない操作で残せる。
2. 前回比、カレンダー、グラフで、成長と部位の偏りがわかる。
3. 設定した目的に沿って、AI から評価と次回メニューの提案を受けられる。

### 対象利用者と利用シーン

対象の中心は、ジムでウェイトトレーニングを行う初心者から中級者とする。上級者は、ある程度は自分で進められると考え、対象の中心からは外す。

| シーン | 端末 | 主な操作 |
| --- | --- | --- |
| トレーニング前 | スマートフォン | 今日のメニューと前回の記録を確認する |
| トレーニング中 | スマートフォン | セットを記録し、レストを計る |
| トレーニング後 | スマートフォン | サマリーと AI の評価を確認する |
| 日常 | スマートフォン、PC | カレンダーと分析を見返し、ルーティンを整える |

## スコープ

提供するのは Web ブラウザ版のみとし、記録、振り返り、AI 提案までの一連の機能を含める。
当面は個人としての利用を前提とする。
広く公開する場合は、個人利用を理由に対象外や不要とした項目を改めて検討する。

### 提供する機能

| 領域 | 機能 |
| --- | --- |
| 身体情報と目的 | 身体情報の登録、目的の設定 |
| トレーニング記録 | 種目とセットの記録、セット種別、左右別セット、スーパーセット、RPE、反動と補助の回数、時間で記録する種目、グリップとアタッチメントの選択、レストタイマー(プッシュ通知を含む)、推定 1RM、前回比、自己ベストの検出、代わりの種目の提案 |
| ルーティンとプログラム | ルーティンの保存、目的別とレベル別のプログラム、目標カロリーと PFC の計算 |
| カレンダー | 月間のトレーニング日数、部位ごとの色分け |
| 種目ライブラリ | 種目マスター、解説、鍛えられる部位の人体図、お気に入り、独自種目の追加、マスターの種目の編集 |
| 分析 | 種目別の履歴とグラフ、部位別分析、回復状況 |
| AI | 日、週、月の評価、次回セットの提案、種目ごとの目標重量、メニューの最適化 |
| マイページ | 各種設定、アカウントの管理、記録の書き出し |

### 対象外

| 機能 | 理由 |
| --- | --- |
| ネイティブアプリ | 初回は Web ブラウザに絞る |
| ウェアラブル端末対応、ヘルスケアサービス連携 | Web ブラウザでは対象にしない |
| ロック画面でのタイマー常時表示 | Web ブラウザでは実現できない。代替はレストタイマーの要件で定める |
| 完全なオフライン利用と同期 | 初回は見送る。記録中データの保護は非機能要件で定める |
| 体組成の継続記録 | 身体情報は最新値のみ保持する |
| 進捗写真 | 不要と判断 |
| SNS 共有、フォロー | 不要と判断 |
| やり方の図、動作のアニメーション | 初回は掲載しない。やり方は文章で説明し、鍛えられる部位は人体図で示す |
| 利用規約、プライバシーポリシー、同意の取得 | 当面は個人としての利用に止めるため、対象外とする。公開する場合は改めて検討する |

### 開発の段階

機能のまとまりごとに、作る順番を 4 段階に分ける。各段階の終わりに、ジムで実際に使って確かめられる状態にする。

| 段階 | 目標 | 含めるもの |
| --- | --- | --- |
| 1 | 記録できる | ログイン、身体情報の登録、種目ライブラリ、トレーニング記録(自己ベストの判定を含む)、レストタイマー(音と画面表示)、ルーティン、記録中データの保護、マイページの基本 |
| 2 | 振り返れる | カレンダー、種目別の履歴とグラフ、自己ベストの一覧、部位別の分析、回復状況、人体図 |
| 3 | 提案を受ける | 目的の設定、AI の評価、次回セットの提案、種目ごとの目標重量、メニューの最適化、プログラム 15 本、目標カロリーと PFC、代わりの種目の提案 |
| 4 | 仕上げ | プッシュ通知、パスキー、CSV の書き出し、ダークモード |

- グリップの選択と時間で記録する種目は、段階 1 に含める。記録のデータの形に関わるためである。
- プッシュ通知の試作(REQ-TMR-012)は段階 1 のうちに行い、採用するかを先に決める。作り込みは段階 4 で行う。

## 身体情報と目的設定

身体情報と目的は、強度の目安、自重種目の負荷計算、AI の評価とプログラム推奨の入力として使う。

| ID | 要件 |
| --- | --- |
| REQ-PRF-001 | 初回利用時に身体情報を登録できる。項目は身長、体重、生年月日、性別、トレーニング経験(初心者、中級者、上級者)。 |
| REQ-PRF-002 | 身体情報はいつでも更新できる。保持するのは最新値のみで、推移は記録しない。 |
| REQ-PRF-003 | 目的を 1 つ設定できる。選択肢は筋肥大、ダイエット、ボディメイク、筋力向上、競技力向上。あとから変更できる。 |
| REQ-PRF-004 | 週あたりのトレーニング可能日数を設定できる。プログラムの推奨と AI のメニュー最適化に使う。 |
| REQ-PRF-005 | 身体情報を入力しなくても記録機能は使える。未入力の場合、体重を使う計算と AI の評価は行わず、入力を促す。 |

## トレーニング記録

1 回のトレーニングを開始し、種目ごとにセットを記録して終了する。記録画面はスマートフォンでの片手操作を前提にする。

### 基本の流れ

1. 空の状態、ルーティン、プログラムの当日メニューのいずれかからトレーニングを開始する。
2. 種目を追加する。前回の記録が表示される。
3. セットごとに重量と回数を入力し、完了にする。
4. レストタイマーが自動で始まる。
5. 全種目を終えたらトレーニングを終了し、サマリーを確認する。

### セッション

| ID | 要件 |
| --- | --- |
| REQ-REC-001 | 空の状態、ルーティン、プログラムの当日メニューからトレーニングを開始できる。 |
| REQ-REC-002 | 種目ライブラリから種目を追加でき、並べ替えと削除ができる。 |
| REQ-REC-003 | 種目を追加すると、その種目の前回の記録をセットごとに表示する。前回の値は 1 回の操作で入力欄にコピーできる。 |
| REQ-REC-004 | 種目ごとに、前回との総重量の差を表示する。トレーニング全体でも総重量の差を表示する。 |
| REQ-REC-005 | 終了時にサマリーを表示する。項目は所要時間、総重量、種目数、セット数、更新した自己ベスト。 |
| REQ-REC-006 | 過去のトレーニングを編集、削除できる。日付を指定して後から記録を追加できる。 |
| REQ-REC-007 | トレーニング全体と種目ごとにメモを残せる。 |

### セット

| ID | 要件 |
| --- | --- |
| REQ-SET-001 | セットごとに重量(kg)と回数を記録する。セットの追加と削除ができる。 |
| REQ-SET-002 | セット種別を選べる。種別は通常、ウォームアップ、ドロップセット。 |
| REQ-SET-003 | ドロップセットは、1 セットの中に重量と回数の組を複数段記録できる。記録画面では、種別をドロップセットにした行を、直前のセットに続く段として扱う。先頭の行と、ウォームアップセットの直後の行は、ドロップセットにできない。 |
| REQ-SET-004 | 左右別に行う種目は、左右それぞれの重量と回数を記録できる。 |
| REQ-SET-005 | 複数の種目をスーパーセットとしてまとめられる。レストタイマーは、まとめた最後の種目のセット完了時に起動する。 |
| REQ-SET-006 | 回数の内訳として、反動を使った回数と補助を受けた回数を記録できる。 |
| REQ-SET-007 | セットごとに RPE を記録できる。入力は任意とする。 |
| REQ-SET-008 | 重量と回数を入力すると、そのセットの推定 1RM を表示する。 |
| REQ-SET-009 | セットを完了した時点で自己ベストの更新を判定し、その場で表示する。対象は最大重量、推定 1RM、種目別の総重量。時間の種目は最長時間。 |
| REQ-SET-010 | 記録方式が「時間」の種目は、セットごとに時間を記録する。ストップウォッチで計った時間をそのまま記録でき、手入力もできる。重量、回数、反動と補助の回数は記録しない。RPE は記録できる。 |
| REQ-SET-011 | グリップを選べる種目では、記録時に、種目に応じて握り方、手幅、アタッチメントを選べる。選んだグリップは記録とともに保存する。前回の記録と自己ベストは、同じグリップ、同じアタッチメントの記録を対象にする。履歴とグラフは、グリップやアタッチメントで絞り込める。 |

### レストタイマー

| ID | 要件 |
| --- | --- |
| REQ-TMR-001 | レスト時間を設定できる。全体の既定値を持ち、種目ごと、セットごとに上書きできる。 |
| REQ-TMR-002 | セットを完了にすると同時にレストタイマーが起動する。 |
| REQ-TMR-003 | 残り時間を表示し、時間の延長と短縮、スキップができる。 |
| REQ-TMR-004 | 終了時に音と画面表示で知らせる。対応端末では振動も行う。 |
| REQ-TMR-005 | 記録中は画面が自動で消灯しないようにする。設定で無効にできる。 |
| REQ-TMR-006 | 別のタブやアプリから戻ったとき、経過時間を反映した正しい残り時間を表示する。 |
| REQ-TMR-007 | ブラウザ通知を許可している場合、別のタブを表示中でも終了を通知する。 |
| REQ-TMR-008 | 画面を消灯した状態やブラウザを閉じた状態でも、レストの終了をプッシュ通知で知らせる。通知は、そのトレーニングを開始した端末に送る。同じアカウントのほかの端末には送らない。通知は利用者が許可した場合のみ送る。iOS ではホーム画面に追加した場合のみ届くため、追加の手順を案内する。 |
| REQ-TMR-009 | プッシュ通知は、緊急度を最高にして送る。有効期限を短くし、遅れた通知は鳴らさずに破棄する。 |
| REQ-TMR-010 | レストを途中で切り上げた場合や延長した場合は、予約済みのプッシュ通知を取り消すか、時刻を変更する。 |
| REQ-TMR-011 | セットの完了時に通信できず、プッシュ通知を予約できない場合は、音と画面表示だけで知らせる。 |
| REQ-TMR-012 | プッシュ通知(REQ-TMR-008)は、早い段階で試作し、iPhone と Android の実機で遅れを測ってから採用する。合格の基準は、レスト終了から 5 秒以内に届く割合が 10 回中 9 回以上とする。満たさない場合、プッシュ通知は補助の位置づけに変え、主な手段を画面の消灯防止と音にする。 |

### 代わりの種目

メニューをこなす途中で、使いたい器具がふさがっている場合に、代わりに行える種目を提案する。

| ID | 要件 |
| --- | --- |
| REQ-ALT-001 | 記録中の種目について、マシンやダンベルなどの器具が使われていて行えない場合に、代わりの種目の候補を表示できる。 |
| REQ-ALT-002 | 候補は、種目ライブラリの中から、主働筋が重なる種目を選ぶ。並び順は、主働筋の重なりが多い順、使う器具が違う順、過去に記録のある順とする。 |
| REQ-ALT-003 | 候補は AI を呼ばずにアプリが選ぶ。通信できない状態でも、すぐに表示する。 |
| REQ-ALT-004 | 候補を選ぶと、その回のトレーニングに限って種目を入れ替える。セット数と回数の目安は元の種目から引き継ぎ、重量は選んだ種目の前回の記録を表示する。元のルーティンは変更しない。 |
| REQ-ALT-005 | 入れ替えのほかに、その種目を後に回すこともできる。 |

## ルーティンとプログラム

よく行うメニューをルーティンとして保存し、種目を選び直さずに記録を始められるようにする。プログラムは、目的とレベルに合わせて用意したルーティンの組である。

### ルーティン

| ID | 要件 |
| --- | --- |
| REQ-RTN-001 | 種目、セット数、目標重量、目標回数(時間の種目は目標時間)、グリップやアタッチメント、レスト時間をまとめてルーティンとして保存できる。 |
| REQ-RTN-002 | 完了したトレーニングをそのままルーティンとして保存できる。 |
| REQ-RTN-003 | ルーティンの編集、複製、削除、並べ替えができる。 |
| REQ-RTN-004 | ルーティンから開始すると、種目とセットが入った状態で記録が始まる。前回の記録も合わせて表示する。 |

### プログラム

| ID | 要件 |
| --- | --- |
| REQ-PRG-001 | 目的(筋肥大、ダイエット、ボディメイク、筋力向上、競技力向上)とレベル(初心者、中級者、上級者)別のプログラムをあらかじめ用意する。目的 5 つ × レベル 3 つの 15 本をすべて用意する。 |
| REQ-PRG-002 | プログラムは、週あたりの日数と、日ごとのルーティンで構成する。ルーティンには種目、セット数、回数または時間の目安、グリップやアタッチメント、レスト時間を含む。 |
| REQ-PRG-003 | 設定した目的、トレーニング経験、週あたりの日数に合うプログラムを推奨として表示する。 |
| REQ-PRG-004 | プログラムを選ぶと、日ごとのルーティンが自分のルーティンとして取り込まれ、編集できる。 |
| REQ-PRG-005 | 進行中のプログラムがある場合、次に行う日のメニューをホームに表示する。 |
| REQ-PRG-017 | プログラムの内容は、付録の出典にもとづいて組む。週あたりの日数は、初心者が 2 〜 3 日、中級者が 3 〜 4 日、上級者が 4 〜 5 日を目安とする。初心者の回数は 8 〜 12 回を基本とする。部位ごとの週あたりセット数、レスト時間、重量の上げ方は、付録の研究の要約に従う。 |
| REQ-PRG-019 | プログラムに期間は設けない。1 週間分のメニューを、利用者がやめるまで繰り返す。プログラムは、いつでもやめるか、別のものに切り替えられる。 |
| REQ-PRG-020 | メニューは曜日に割り当てず、順番で進める。休んだ日があっても飛ばさず、次に行う日のメニューを順に表示する。 |

### 目標カロリーと PFC

目的と身体情報から、1 日の目標カロリーと PFC(たんぱく質、脂質、炭水化物)の目安を計算して表示する。食事内容の記録は行わない。

| ID | 要件 |
| --- | --- |
| REQ-PRG-006 | 身体情報(身長、体重、生年月日、性別)、目的、週あたりのトレーニング日数、日常の活動量から、1 日の目標カロリーを計算する。 |
| REQ-PRG-007 | 日常の活動量は「低い」「普通」「高い」の 3 段階から選ぶ。 |
| REQ-PRG-008 | 目標カロリーから、たんぱく質、脂質、炭水化物の目安量をグラム数で表示する。 |
| REQ-PRG-009 | 目的に応じてカロリーを調整する。筋肥大は消費カロリーより多く、ダイエットは少なく、ボディメイク、筋力向上、競技力向上は同程度とする。 |
| REQ-PRG-010 | 身体情報または目的を更新すると、目安を計算し直す。 |
| REQ-PRG-011 | 目安はプログラムの画面に表示する。プログラムを選んでいなくても確認できる。 |
| REQ-PRG-012 | 目標カロリーには下限を設け、基礎代謝を下回る値は提示しない。 |
| REQ-PRG-013 | 身体情報(性別を含む)と目的の入力を必須とする。未入力の項目がある場合は計算せず、入力を促す。 |
| REQ-PRG-014 | 表示する値は目安であり、医療上や栄養指導上の助言ではない旨を表示する。持病がある場合や妊娠中の場合は、専門家に相談するよう案内する。 |
| REQ-PRG-015 | PFC の配分は利用者が調整できる。たんぱく質は体重 1 kg あたり 1.6 〜 2.2 g の範囲で、脂質は目標カロリーに対する割合で指定し、炭水化物は残りから自動で計算する。 |
| REQ-PRG-016 | 調整した値は保存し、身体情報や目的の更新で計算し直すときも保つ。既定値に戻す操作を用意する。たんぱく質と脂質の合計が目標カロリーを超える指定はできない。 |
| REQ-PRG-018 | 目的がダイエットの場合、カロリーの目安の近くに、減量の速さの目安(週に体重の 0.5 〜 1%)を表示する。体重の推移は記録しないため、守れているかの判断は利用者が行う。 |

計算式は「計算ルールと用語定義」で定める。

## カレンダー

いつ、どの部位をトレーニングしたかを月単位でひと目で確認できるようにする。

| ID | 要件 |
| --- | --- |
| REQ-CLD-001 | 月表示のカレンダーで、トレーニングした日がわかる。前後の月に移動できる。 |
| REQ-CLD-002 | トレーニングした日には、行った部位を部位ごとの色で表示する。複数の部位を行った日は、色を並べて表示する。 |
| REQ-CLD-003 | その月のトレーニング日数を表示する。部位ごとの日数も表示する。 |
| REQ-CLD-004 | 日付を選ぶと、その日の種目、セット内容、総重量を表示する。 |
| REQ-CLD-005 | 部位を選んで絞り込むと、その部位を行った日だけを強調して表示する。 |
| REQ-CLD-006 | 部位と色の対応を凡例として表示する。 |

色分けの部位区分は、胸、背中、肩、二頭・前腕、三頭、脚、腹筋、その他の 8 つとする。その日の部位は、記録した種目の部位区分から判定する。
月の境界は日本時間で決める。

## 種目ライブラリ

代表的な種目をマスターとして用意し、やり方の確認と記録時の種目選択の両方に使う。

| ID | 要件 |
| --- | --- |

## AI による評価と最適化

AI は記録をもとに、設定した目的に沿った評価と次回メニューの提案を行う。提案を採用するかは利用者が決め、内容は編集できる。

## 計算ルールと用語定義

集計と表示がぶれないよう、計算の定義をここで固定する。重量の単位は kg、週は月曜始まり、日付と週と月の境界は日本時間 (Asia/Tokyo) で決める。

| 用語 | 定義 |
| --- | --- |
| トレーニングの日付 | 記録した時刻とは別に持つ、日本時間の日付。後から日付を指定して追加した記録も、日本時間の日付として扱う。 |
| 総重量 | 重量 × 回数を合計した値。ウォームアップセットは除く。ドロップセットは全段、左右別セットは左右を合算する。反動の回数は含め、補助の回数は含めない。自己ベストの判定に使う種目別の総重量は、ストリクト回数だけで計算する。 |
| 前回 | 種目単位では、同じ種目を記録した直近のトレーニング。グリップやアタッチメントを選べる種目は、同じものを選んだ直近のトレーニング。トレーニング全体では、同じルーティンから開始した直近のトレーニング。 |
| ストリクト回数 | 回数から、反動の回数と補助の回数を引いた値。推定 1RM と自己ベストの判定に使う。 |
| 推定 1RM | 1 回だけ挙げられる最大重量の推定値。下の式で求める。回数が 1 のときは重量をそのまま使う。 |
| RPE | セットの主観的なきつさを表す 10 段階の指標。10 は「これ以上 1 回もできない」、9 は「あと 1 回できた」、8 は「あと 2 回できた」。入力は 6 から 10 まで 0.5 刻み。 |
| 自重種目の重量 | 記録時点の登録体重に加重を足した値。記録時点の体重をセットとともに保存し、あとで体重を更新しても過去の記録は変えない。 |
| 部位別のセット数 | 種目の部位区分ごとに数えたセット数。ウォームアップセットは除く。ドロップセットは 1 セットと数える。補助筋として使った部位には数えない。AI に渡す参考値に限り、補助筋のセットを 0.5 として加える。 |
| 時間で記録する種目 | 総重量と推定 1RM の対象外とする。部位別のセット数には 1 セットとして数える。前回比とグラフは、合計時間と最長時間で示す。自己ベストは最長時間とする。 |

推定 1RM は次の式で求める。w は重量、r はストリクト回数。

```latex
1RM = \frac{100\,w}{48.8 + 53.8\,e^{-0.075\,r}}
```

この式は、検証研究でベンチプレスとスクワットの実測値をよく予測した。回数が多いほど推定の精度は下がるため、回数が 10 を超えるセットの推定 1RM は参考値として表示する。デッドリフトでは低めに出やすい。

### セット種別ごとの扱い

| セット種別 | 総重量 | 推定 1RM と自己ベスト | 部位別のセット数 |
| --- | --- | --- | --- |
| 通常 | 含める | 対象 | 1 セット |
| ウォームアップ | 除く | 対象外 | 数えない |
| ドロップセット | 全段を含める | 最初の段のみ対象 | 1 セット |

### カロリーと PFC の計算

目標カロリーは、基礎代謝に活動係数を掛けて消費カロリーを求め、目的別に調整して決める。係数と調整幅は、付録の出典にもとづく目安とする。

基礎代謝は次の式で求める。W は体重(kg)、H は身長(cm)、A は年齢。s は男性が +5、女性が −161。

```latex
BMR = 10W + 6.25H - 5A + s
```

| 項目 | 計算 |
| --- | --- |
| 消費カロリー | 基礎代謝 × 活動係数。活動係数は日常の活動量で幅を決める。低いは 1.40 〜 1.69、普通は 1.70 〜 1.99、高いは 2.00 〜 2.39。幅の中の値は、週あたりのトレーニング日数から決める。 |
| 目標カロリー | 筋肥大は消費カロリーの +10 〜 20%(既定値は +15%)、ダイエットは −15%、ボディメイク、筋力向上、競技力向上は ±0%。基礎代謝を下回る場合は基礎代謝の値とする。 |
| たんぱく質 | 既定値は体重 1 kg あたり 2 g。利用者が 1.6 〜 2.2 g の範囲で変更できる。 |
| 脂質 | 既定値は目標カロリーの 20%。利用者が変更できる。 |
| 炭水化物 | 目標カロリーから、たんぱく質と脂質のカロリーを引いた残り。 |

カロリーへの換算は、たんぱく質と炭水化物が 1 g あたり 4 kcal、脂質が 1 g あたり 9 kcal とする。

## 成功指標

当面は個人としての利用のため、成功指標は使わない。広く公開する場合は、継続して記録されているか、記録が手間になっていないか、AI の提案が使われているかの 3 点で測る。目標値が未定の指標は、未決事項とする。

| 指標 | 定義 | 目標値 | 確認したいこと |
| --- | --- | --- | --- |
| 4 週後の継続率 | 登録から 4 週後も、週 1 回以上記録している利用者の割合 | 未定 | 記録が習慣になっているか |
| 1 セットの記録時間 | セットの入力開始から完了までの時間の中央値 | 未定 | 記録が流れを止めていないか |
| ルーティン利用率 | ルーティンまたはプログラムから開始したトレーニングの割合 | 未定 | 入力の手間を減らせているか |
| 次回セット提案の採用率 | 提案のうち、そのまま、または修正して採用された割合 | 未定 | 提案が実用に足りているか |
| 評価の閲覧率 | 用意した評価のうち、開かれた割合 | 未定 | 評価が読まれているか |
| 記録の消失件数 | 記録中のデータが失われたという報告の件数 | 0 件 | データ保護が機能しているか |

## 付録: AI に渡すコンテキスト

AI の評価と提案の質は、渡す前提知識で決まる。筋肥大とトレーニングに関する研究を要約し、それをもとにしたプロンプトをここに置く。

研究が示すのは集団の平均であり、個人差は大きい。数値は目安として扱い、内容は付録の出典を根拠とする。

### 研究の要約

| テーマ | 研究が示すこと | AI への指針 |
| --- | --- | --- |
| 週あたりのセット数 | セット数が多いほど筋肥大は大きいが、増やすほど伸びは小さくなる。部位あたり週 5 セット未満でも効果はあり、10 セット以上でより大きい。筋力は少ないセット数でも伸び、頭打ちが早い。 | 部位ごとの週セット数を評価の中心に置く。少なすぎる部位を指摘し、増やす提案は段階的に行う。 |
| 頻度 | 週のセット数が同じなら、頻度そのものが筋肥大に与える効果は小さい。 | 頻度は、週のセット数を無理なく確保する手段として扱う。 |
| 重量と回数 | 限界近くまで行う場合、筋肥大は軽い重量でも重い重量でも同程度。最大筋力は重い重量のほうが伸びる。 | 筋肥大では回数の幅を広く認める。筋力向上では高重量、低回数を重視する。 |
| 限界への近さ | 筋肥大は、セットを限界の近くまで行うほど大きい傾向がある。筋力は余力の残し方にあまり左右されない。限界まで行うと疲労は増える。 | 筋肥大では RPE 8 以上のセットの割合を見る。筋力向上では毎セット限界まで行うことを求めない。 |
| レスト | 60 秒を超えるレストに小さな利点がある。90 秒を超えると差は見られない。 | 60 秒未満のレストが続く場合に、延長を提案する。 |
| 負荷の上げ方 | 目標回数を 1 〜 2 回上回れたら、重量を 2 〜 10% 上げる。重量を上げる方法と回数を増やす方法は、どちらも有効。 | 次回セットの提案の基本とする。重量を上げにくいときは回数を増やす。 |
| たんぱく質 | 1 日に体重 1 kg あたり約 1.6 g を超えると、除脂肪量の伸びへの追加の効果は見られない。ただし推定の幅は約 1.0 〜 2.2 g と広く、論文は約 2.2 g を目安とすることも妥当としている。 | PFC の目安を説明するときの根拠とする。設定できる範囲は 1.6 〜 2.2 g とする。 |
| 減量の速さ | 週に体重の約 0.5 〜 1% の緩やかな減量と筋力トレーニングの併用で、除脂肪量を保ちやすい。 | ダイエットでは扱う重量の維持を評価する。急な減量を勧めない。 |
| 筋力の伸びの目安 | 未経験者は 12 週間で 1RM が 15 〜 30% 伸びる例が多く、経験者の伸びは年に数 % 程度。 | 目標重量が現実的かを判断する材料とする。二次情報によるため確度は低い。 |
| グリップ | ラットプルダウンでは、手幅を変えても広背筋、僧帽筋中部、上腕二頭筋の活動に差は見られない。シーテッドロウでは、狭い手幅で広背筋、広い手幅で僧帽筋の活動が大きい。 | グリップの違いを理由に、部位の過不足を判断しない。シーテッドロウの手幅だけは考慮する。 |

### プロンプト

評価、次回セットの提案、メニューの最適化に共通で渡すシステムプロンプトの初版。波かっこの部分には、アプリが記録から値を入れる。

```text
あなたはウェイトトレーニングの記録アプリに組み込まれたパーソナルトレーナーです。
専門用語は使うときに一言で説明し、短く具体的に書いてください。

# 利用者の情報
- 目的: {{目的}}  (筋肥大 / ダイエット / ボディメイク / 筋力向上 / 競技力向上)
- トレーニング経験: {{経験}}
- 身体情報: {{身長}} cm、{{体重}} kg、{{年齢}} 歳、{{性別}}
- 週あたりのトレーニング可能日数: {{日数}}
- 種目ごとの目標重量と達成したい時期: {{目標}}

# 渡される記録
- 対象期間のトレーニング記録: {{記録}}
  (種目、セットごとの重量と回数または時間、セット種別、グリップやアタッチメント、RPE、反動と補助の回数、レスト時間、メモ)
- 部位ごとの週あたりセット数と総重量: {{部位別の分析}}
- 部位ごとの回復状況: {{回復状況}}  (回復中 / ほぼ回復 / 回復済み)
- 現在のルーティン: {{ルーティン}}
- 提案に使える種目の一覧: {{種目ライブラリ}}
- 補助筋を含めた部位ごとのセット数の参考値: {{補助筋を含むセット数}}
  (補助筋として使ったセットを 0.5 として加えた値。画面には表示していない)
- 考え直しの依頼の場合は、前回の出力: {{前回の出力}}

# 記録の読み方
- ウォームアップセットは評価と計算に含めない。
- 回数から反動と補助の回数を引いたものを、自力で行えた回数として扱う。
- RPE は 10 が「これ以上 1 回もできない」、9 が「あと 1 回できた」、8 が「あと 2 回できた」。
- 推定 1RM は、100 × 重量 ÷ (48.8 + 53.8 × e^(-0.075 × 自力で行えた回数))。回数が 10 を超える場合は参考値とする。
- 時間で記録する種目は、重量と回数の代わりに時間で評価する。総重量と推定 1RM の対象にしない。
- グリップやアタッチメントが違う記録は、別の記録として比べる。
- 部位ごとのセット数は、主に使う部位だけで数えた値である。量の過不足は、補助筋を含めた参考値も見て判断する。
  画面のセット数と判断が食い違うときは、その理由を説明する。

# 判断の原則 (研究にもとづく目安。平均的な傾向であり、個人差がある)
1. 量: 部位ごとの週あたりセット数が多いほど筋肥大は大きいが、増やすほど伸びは小さくなる。
   週 5 セット未満でも効果はあり、10 セット以上でより大きい。増やす提案は少しずつ行う。
2. 頻度: 週のセット数が同じなら、頻度そのものの効果は小さい。
   頻度は、週のセット数を無理なく確保する手段として扱う。
3. 重量と回数: 限界近くまで行うなら、筋肥大は軽い重量でも重い重量でも同程度。
   最大筋力を伸ばすには重い重量が有利。
4. 限界への近さ: 筋肥大は限界に近いセットほど効果が大きい傾向がある。
   筋力は余力を残しても伸びる。限界まで行うほど疲労は増える。
5. レスト: セット間は 60 秒を超えて休むほうがやや有利。90 秒を超えると差は小さい。
6. 負荷の上げ方: 目標回数を 1 〜 2 回上回れたら、重量を 2 〜 10% 上げる。
   重量を上げにくいときは、同じ重量で回数を増やす方法も同じく有効。
7. 筋力の伸び: 未経験者でも 12 週間で 15 〜 30% 程度の伸びが目安。経験を積むほど伸びは緩やかになる。
8. グリップ: グリップの違いを理由に、部位の過不足を判断しない。
   シーテッドロウだけは、狭い手幅で広背筋、広い手幅で僧帽筋の活動が大きい。

# 目的ごとに重視する点
- 筋肥大: 部位ごとの週セット数、重量や回数の伸び、RPE 8 以上のセットの割合
- ダイエット: トレーニング頻度の継続、全身をまんべんなく行えているか、扱う重量の維持
- ボディメイク: 部位間の量のバランス、反動や補助に頼らない回数の割合、重量や回数の伸び
- 筋力向上: 推定 1RM と最大重量の伸び、高重量で行うセットの量、レスト時間が十分か
- 競技力向上: 全身の部位のバランス、重量や回数の伸び、トレーニング頻度の継続

# 依頼ごとの出力
## 評価 (日 / 週 / 月)
「良かった点」「改善点」「次に取る行動」の 3 つに分け、それぞれ 1 〜 3 項目で書く。
どの項目にも、根拠となる記録の数値を添える。

## 次回セットの提案
種目ごとに、重量、回数、セット数を提案し、理由を 1 文で添える。時間で記録する種目は、時間とセット数を提案する。
- 前回のセット数、重量と回数、RPE、反動と補助の回数、種目のメモから判断する。
- グリップやアタッチメントを選べる種目は、前回と同じものを使う前提で提案する。
- 重量を増やす幅に固定の上限はない。その種目の前回の記録とメモから、無理のない幅を決める。
- 前回、セットが進むにつれて回数が大きく落ちた場合や、反動や補助が多い場合は、重量を据え置く。
- 回復中の部位は、量を増やす提案をしない。

## メニューの最適化
ルーティンの変更案を、現在のルーティンとの差分で示す。種目の追加と入れ替え、セット数の増減、部位の配分を対象とする。
- 提案する種目は、渡された種目の一覧にあるものに限る。
- 変更の理由を、記録の数値とともに書く。

## 目標重量への対応
- 目標重量がある種目は、そこへ向けた次回セットとルーティンを提案する。
- 現在の記録、直近の伸び、経験、時期までの期間から見て達成が難しい場合は、
  一気に届かせる提案をしない。難しい理由を伝え、段階的に届く途中の目標を提案する。
  例: 現在 20 kg の種目で、来月 60 kg を目標にしている場合。

## 考え直しの依頼
前回の出力が行き過ぎていると利用者が感じたときの依頼である。前回の出力を踏まえ、より控えめな内容で作り直す。
- 前回から何を変えたかを、最初に 1 文で書く。

# 守ること
- 記録が少なく判断できないときは、その旨を伝える。推測で断定しない。
- 記録にない事実を作らない。数値は渡された記録から引用する。
- メモに痛みやけが、体調不良の記述があるときは、重量や量を増やす提案をしない。
  負荷を下げるか休むことを勧め、続く場合は医師などの専門家への相談を案内する。
- 診断や治療の助言はしない。極端な食事制限や急な減量を勧めない。
- 提案は目安である。最終的に決めるのは利用者であることを前提に書く。
```
